# Emela for Zed

A Zed extension that highlights Emela (`.emel` files) with the tree-sitter grammar in
`editors/tree-sitter-emela`. It also gives Zed the outline, bracket pairs, indentation and the
vim-mode text objects (`af`/`if`, `ac`/`ic`). It does not start the language server yet.

- `extension.toml`: the extension and where Zed fetches the grammar from
- `languages/emela/config.toml`: file type, comments, brackets, two-space indentation
- `languages/emela/highlights.scm`: generated by `sync-queries.sh` from
  `editors/tree-sitter-emela/queries/highlights.scm`; do not edit it by hand
- `languages/emela/{brackets,indents,outline,textobjects}.scm`: Zed's own queries

## Install

The extension is not in Zed's extension registry. Install it as a dev extension: run
`zed: install dev extension` from the command palette and choose this directory. Zed needs Rust
(through rustup) to install dev extensions.

Zed fetches the grammar from the repository and commit in `extension.toml` (`[grammars.emela]`),
not from your working tree. To try a grammar you changed locally, point it at your checkout while
you work, and install the dev extension again after each change:

```toml
[grammars.emela]
repository = "file:///absolute/path/to/emela"
rev = "<a commit in that checkout that has the change>"
path = "editors/tree-sitter-emela"
```

## Update

- After changing the grammar, set `rev` to the commit on `main` that contains it.
- After changing `editors/tree-sitter-emela/queries/highlights.scm`, run `./sync-queries.sh`.
  `editors/tree-sitter-emela/scripts/check.sh` (and CI) fails while the copy is out of date.

## Captures

Zed's themes know fewer captures than nvim-treesitter, so `sync-queries.sh` renames these:

| nvim-treesitter | Zed |
|---|---|
| `@comment.documentation` | `@comment.doc` |
| `@variable.member` | `@property` |
| `@variable.builtin` | `@variable.special` |
| `@module` | `@type` |
| `@spell` | (removed) |

The other captures (`@keyword.function`, `@type.definition`, `@function.method.call` and so on)
are kept: Zed falls back to their prefix (`@keyword`, `@type`, `@function`) when a theme has no
style for the full name.
