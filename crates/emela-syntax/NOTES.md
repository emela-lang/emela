# 字句解析の補足

仕様（草案 2026-10-07）に書かれていない判断を残す．

- （補）空白はスペースとタブ．`\r\n` は `\n` と同じく1つの NEWLINE にする．単独の `\r` は認識できない文字として扱う
- （補）コメントは `\r` の手前で終わる（`\r\n` の `\r` をコメントに含めない）
- （補）小文字名は 17.2 の EBNF どおり大文字を含んでもよい（`userId` を通す）．snake_case かどうかは lint に任せる
- （補）型名は EBNF どおり大文字が続いてもよい（`HTTPServer` は型名）
- （補）どのクラスにも合わない名前（`Http_client` など）は，単語まるごとを ERROR_TOKEN 1つにして診断を1件出す
- （補）名前に使える文字は ASCII だけ．`é` などは認識できない文字になる
- （補）数値の直後に英字が続くもの（`1e9` `1.0e` `3px`）は，かたまりを ERROR_TOKEN 1つにして診断を出す．EBNF にない小数点なしの指数もここに入る
- （補）`1..2` は INT DOT2 INT，`1.x` は INT DOT LOWER_NAME（小数点の後ろに数字がなければ浮動小数点にしない）
- （補）文字列は改行をまたげない．改行に着いたら「閉じていない」の診断を出し，改行はコードとして読む
- （補）文字列は STRING_QUOTE / STRING_TEXT / INTERP_START / INTERP_END に分け，パーサが組み立てる．エスケープは STRING_TEXT の中に含めたまま，不正なものは `\` と次の1文字の範囲に診断を出す
- （補）補間の中は普通のコードなので，コメントや改行を含みうる
- （補）継続判定は改行の次の「意味のあるトークン」を見る．間の空白，コメントだけの行，空行は飛ばす（`a⏎# c⏎|> f` の改行は2つとも継続）
- （補）補間 `#{ }` の中の改行は `(` の中と同じく継続にする
- （補）2.5 の穴3つは，どれも継続にする．`}⏎else`，行頭の `->`，行頭の `|` はどれも文を始めることがないので，継続にしても曖昧さは生まれない．`} else {` などへの揃えは fmt が行う

- （補）16進と2進の接頭辞の誤り（`0XFF` `0o17` `0x`），16進と2進の小数（`0x1.5`）は，かたまりを ERROR_TOKEN 1つにして E0104 を出す
- （補）`\u{...}` の形の崩れ（`{` や `}` がない，桁数が1〜6でない）も，サロゲートや 10FFFF 超えと同じ E0108 にする．範囲は `\` から読めたところまで
- （補）複数行の文字列は，開く `"""` と閉じる `"""` を TRIPLE_QUOTE にする．閉じる側は行頭の空白を含み，その空白が各行から取り除くインデントになる．本文は STRING_TEXT で，改行を含む．開く `"""` の直後の改行は最初の STRING_TEXT に，閉じる行の直前の改行は最後の STRING_TEXT に入るので，値を作る側（lowering）がこの2つとインデントを取り除く
- （補）複数行の文字列の形の誤り（開く `"""` の後ろが改行でない，閉じる `"""` が行に1つでない，閉じる行より浅い行）はまとめて E0109 にする．字句の帯（E0101〜E0109）に空きがないため．浅さはバイトの前方一致で見るので，閉じる行と違う空白（タブと空白の混在）も誤りになる．閉じる `"""` が行に1つでないときはインデントの検査をしない
- （補）複数行の文字列の中の行末の `\` は E0106 を出し，本文を読み続ける
- （補）`""""` は `"""` と `"` に切る（最長一致）

# パーサの補足

- （補）効果の集合 `use { ... }` の波括弧の中の改行は読み飛ばす．17.1 で取り除かれるのは `(` `[` の中の改行だけなので，波括弧の中の改行は字句では区切りとして残る．複数行に分けて書けるようにパーサで読み飛ばす
- （補）パターンの負の数（18.1 #17）は，`-` と数値を LITERAL_PAT に入れたうえで E0116 を出す．仕様が決まったら診断を外せば木はそのまま使える
- （補）パターンの文字列リテラルに補間があれば E0117 を出し，補間の中身は ERROR に包む．補間は定数でないので照合に使えない
- （補）要素が1つのタプル `(Int,)` `(a)` `(a,)` は E0112 を出し，タプルとして読む．型の `(Int)` は括弧の型（PAREN_TYPE）で，診断を出さない（5.5，17.4 の改訂）
- （補）式の `(a)` は括弧の式，`(a,)` は E0112 を出してタプルにする．パターンの `(a)` はタプルの誤りとして扱う
- （補）`use X` の直後に `.` か `(` が来たら E0121 を出す（17.5 の「`(use X).op(...)` と括弧で囲む」を診断にした）
- （補）閉じていない `(` の中では改行が継続になり NEWLINE が来ないので，パーサは「直前に改行があるか」をトークンごとに持ち，行頭を文の区切りとして扱う．行頭の宣言キーワード（`fn(` を除く）はエラー回復の同期点にする
- （補）`derive` は次の行に書ける（10.5 の例 `type User(...)⏎  derive Eq`）．文法どおりだと行頭の `derive` の前の改行は区切りになるので，パーサが改行を先読みして吸収する．継続の判定（2.5）と同じく，間のコメントだけの行と空行は飛ばす
- （補）宣言と `derive` の間のドキュメントコメント `##` は DERIVE_CLAUSE の中に入れる．`derive` は宣言ではないので，型や enum のドキュメント（`doc_comments`）には含めない．型の説明は宣言の前に書く
- （補）ドキュメントコメント `##` は直後の宣言，バリアント，フィールド，effect の操作，handler の項目のノードの中に入れる．`##` の後ろの改行は区切りとして字句に残るので，パーサは区切りの改行を読むときにコメントの位置から宣言を開く
- （補）宣言の本体（effect，handler，trait，impl）の中では，行頭の `fn` と `suspend` をエラー回復の同期点にしない．本体の項目がそれで始まるため
- （補）trait の本体の `derive` で始まる項目（導出規則，18.1 #3 で構文が未確定）は E0129 を出し，対応の取れた `}` まで ERROR に包む
- （補）`@external` が要る宣言（本体のない fn，トップレベルの suspend fn，フィールドのない type）の検査は，トップレベルの宣言だけに掛ける．trait の fn は本体を省ける
- （補）引数の並びの `..` は，部分更新の `..式` も束縛の左辺の式のない `..` も SPREAD_ARG にする（リストの REST_EXPR とは分ける）．`..` の後ろの引数は E0114．呼び出し先が構成子かどうかはパーサでは見ず，関数の呼び出しに書いたときの誤りは名前解決か型検査で出す．束縛の左辺に `..式` を書けば E0125
