# emela-resolve の補足

仕様にない判断を「（補）」として1行ずつ残す．

- （補）型名の字句クラスは ASCII に限る．`föö.emel` のような非 ASCII の名前は snake_case でないとして拒否する．
- （補）`_` の直後の数字はそのまま残す．`http_2` は `Http2` になり，`http2` と重複する．
- （補）`a.emel`（`A`），`x_y.emel`（`XY`）のように小文字を含まない名前は，型名の字句クラスに合わないので拒否する．
- （補）`.` で始まるファイルとディレクトリ（エディタの一時ファイル，`.git` など）は見ない．
- （補）`.emel` 以外のファイルは黙って無視する．
- （補）名前が正しくないディレクトリは，そのディレクトリに1件だけ診断を出し，中のファイルはモジュールにしない．
- （補）大文字小文字の違いだけのファイル（`Foo.emel` と `foo.emel`）は，命名の診断に加えて重複の診断も出す．大文字小文字を区別しないファイルシステムでは同じファイルになるため．
- （補）重複したときは，パスの順で先のファイルを対応表に残し，後のファイルに診断を出す．
- （補）ルート直下の `prelude.emel`（`Prelude`）は予約名として拒否する．`std/prelude.emel` のような下の階層は許す．
- （補）ディレクトリの走査は名前の順に行い，対応表と診断の順序を決定的にする．
- （補）循環の診断は強連結成分ごとに1件．成分の中で ID が最小のモジュールを起点に，そこへ戻る最短の循環を示す．成分が単純な循環でないとき，成分の全モジュールは並ばない．
- （補）循環の診断の位置は，起点のモジュールの，循環の次のモジュールへの import 文．
- （補）自己 import は長さ1の循環として扱い，専用の文面にする．
- （補）未定義の import は辺にしない．循環がなければ依存順は返す．
- （補）依存順は循環が1つでもあれば返さない（`None`）．

## 名前解決

構文木から HIR（`hir.rs`）を作る．定義は `DefId`，局所変数は `LocalId`，式・パターン・型はプログラム全体で1つのアリーナに持つ．段は宣言の収集，import，写す（`lower.rs`）の3つ．

### 名前空間と位置

- （補）モジュールの名前空間は型，構成子，値の3つと，モジュール名．型は type，enum，error，effect，handler，layer，trait．構成子は type の構成子，バリアント，error，フィールドのある handler．値は fn と const（小文字名と大文字名なので重ならない）
- （補）名前空間は位置で引き分ける．`.` の左ではモジュールと Trait だけ，型の位置では型だけ，式とパターンの型名では構成子だけを引く．4.4 のモジュール `Email` と型 `Email` は位置で区別がつくので衝突しない．`fn f(e: Email)` は `import Email.{Email}` がなければ「モジュールで，型ではない」（E0217）
- （補）`.` の左は，モジュールの水準（定義と import）で見つからなければ組み込みのモジュールと Prelude の Trait を見る．同じ水準でモジュールと Trait の両方が見つかれば曖昧として E0218
- （補）`A.B.f` の `B` はモジュール `A` の pub な Trait に限る（入れ子のモジュールはない）
- （補）effect を `.` の左に書いた（`Logger.info`）ときは E0217 を出す．操作は能力の値を通して呼ぶ（8.2）
- 型の位置に書けるのは type，enum，error（7.1：error は同じ名前の型も定義する），組み込みの型，型引数．effect は「型として使えない」の E0221（8.2：能力の値の型は書けない）．型引数の位置に書いた集合（`Handler[NotFound | Timeout, { Db }]`）は `TypeKind::ErrorSet` と `TypeKind::EffectSet` にし，要素を `fails` 節と `use` 節と同じく引く．ただし名前付き型の型引数の位置（`Handler[NotFound, Db]` の `Db`）では effect も通す（9.2 の集合の型引数に渡すため）．集合の型引数の位置かは宣言の型引数の種類で決まるので，型推論が確かめ，集合でない位置なら同じ E0221 を出す．handler，layer，trait は E0217
- 型引数は，ふつうの型・エラーの集合・効果の集合のどれかを区別せずに解決する．種は型推論の段が使われ方から推論する（9.2）．`fails` 節と `use` 節にも型引数を書ける
- （補）`fails` 節は error と型引数，`use` 節は effect と型引数，`use X` の式は effect だけ．`with` と layer の中身は handler か layer．制約，derive，impl，上位の Trait は trait
- （補）エフェクトの型引数（8.1）．`effect State[S]` の型引数は effect の定義を親にした `DefKind::TypeParam` で，`EffectItem::type_params` に持ち，操作のシグネチャの中で引ける．`use State[Int]` の型引数は `ExprKind::Use::args`，`handler H: State[Int]` は `HandlerItem::effect_args`，`use` 節の要素は `EffectRef`（エフェクトか型引数と，その型引数）に持つ．型引数の中はふつうの型の位置として引く（エフェクトの名前は E0221）．型引数の数と省略は型推論が確かめる（E0304，E0423）
- （補）大文字名の型引数を式に書いたら E0217（2.3：型の位置でだけ参照できる）

### import と可視性

- （補）`import A.B.{x}` の形でも `B` をモジュールとしてスコープに入れる
- （補）import の一覧の名前は，その名前を持つすべての名前空間（type なら型と構成子）から pub なものを取り込む．見つからなければ E0212，見つかったが pub なものがなければ E0214
- （補）import で入れた名前は再公開しない．他のモジュールから import や `M.x` で引けるのは，そのモジュールが定義した名前だけ
- （補）同じ定義を2回 import しても重複にしない．同じ名前で別の定義なら E0213
- （補）`M.x` で pub でない定義を引いたら E0214 を出し，解決先はそのまま使って先へ進む
- （補）バリアントと type の構成子は親の型の pub と opaque に従う．trait の関数は trait に従う
- （補）未定義のモジュールの import は import のグラフが E0205 を出すので，名前解決では黙って飛ばす

### 重複と隠すこと

- （補）重複は先の定義を残し，後の定義に E0213 を出す．診断は先の定義の位置を持つ（driver が label にする）
- （補）同じモジュールの2つの enum が同じ名前のバリアントを持つと E0213．バリアントは修飾せずに書くので（`Some(x)`），構成子の名前空間で重複になる．type の構成子と error も同じ名前空間なので，`type Green` とバリアント `Green` も重複
- （補）モジュールの定義と import は Prelude の同じ名前（型，構成子，Trait，関数）を隠す．エラーにはせず W0202 を出す．2.3 の型引数と同じ考え方で，Prelude に名前を足しても既存のコードが壊れないようにする
- （補）型名の型引数が，外側の型・エフェクト・エラー・Trait（モジュールの定義，import，Prelude，外側の型引数）と同じ名前なら W0201．大文字名の型引数は型名と重ならないので見ない
- （補）effect の操作，trait の関数，フィールド，型引数の並びの中の重複も E0213

### 局所のスコープ

- （補）束縛 `p = e` は右辺を先に解決し，後でパターンの名前を入れる（`count = count + 1`）．束縛し直すと新しい `LocalId` になる
- （補）match と escape の腕はそれぞれスコープを積む．パターンの名前はガードと本体から見える．腕の変数は `LocalKind::ArmBinding`
- （補）1つのパターンか引数の並びで同じ名前を2回束縛したら E0220
- （補）handler の操作と release には暗黙の `self`（`LocalKind::SelfParam`）を入れる．init には入れない（値を作る前なので）．init でハンドラの値を作れるよう，フィールドのある handler には同じ名前の構成子を作る．フィールドを書いていない（括弧のない）handler も，init があれば同じ名前の値の構成子（`ConsoleLogger`）を作る（8.4 の「フィールドのないハンドラにも init を書ける」）．構成子を init の外で使ったかは型検査が見る（E0418）
- （補）impl と trait の `self` は引数として書く．それ以外の `self` と，trait と impl の外の `Self` は E0219
- （補）名前付き引数のラベルは解決しない（呼び出し先のシグネチャが要る）．名前と位置だけを `Arg::label` に残す．`NotFound(id:)` は値の `id` を解決して `punned` を立てる．パターンの `User(name:)` は `name` を束縛する
- （補）型引数は付いている宣言（fn，type，enum，trait の fn）を親に持つ `DefId`．制約は全部の型引数を入れてから引く

### エラーと opaque

- `fail e` の `e` は普通の式（エラーの型の値）で，名前解決では検査しない．エラーの型かどうかは型推論が見る（7.2）
- （補）escape の腕の最上位の構成子パターンは error に限る（E0217）．`_` と変数は許す．error は普通の値なので，match のパターンに error の構成子を書いてよい
- （補）opaque な型の構成子を定義モジュールの外で式に書いたら E0215，パターンに書いたら E0216．型名として使うのは自由
- （補）opaque な型のフィールドアクセス（`email.value`）は値の型が要るので，型推論の段で検査する

### Prelude と組み込みのモジュール

- （補）Prelude の定義は `Program` の最初に作る（`DefModule::Prelude`）．`Bool`，`Option`，`Ordering` は enum の中身を持ち，`Option` は型引数 `A` と位置引数1つの `Some(A)` を持つ．Prelude の中の型（`Some(A)` の `A`）だけは位置がない（`TypeRef::span` が `None`）
- （補）Prelude の Trait の関数は `Eq.eq`，`Ord.compare`，`Show.show` を名前だけ定義する．Hash は持たない（2026-10-19 に仕様から外れた．10.6，15.1）．シグネチャは型推論の段が持つ
- （補）組み込みの制約 `Immediate`（9.5）とエフェクト `Async`（8.7）も Prelude と同じく import なしで見せる
- （補）組み込みのモジュール（`String`，`List` など）は `BuiltinModules` から引く．import なしで `.` の左に書ける（4.4 の `String.contains`）．項目の `DefId` は初めて引いたときに作る（`DefModule::Builtin`）
- （補）型の位置で，型引数，モジュールの定義と import，Prelude のどれにも名前がないとき，組み込みのモジュール `X` が同じ名前の型 `X` を持てばそれを使う（5.7 の `Map[String, List[User]]`）．ソースのモジュールには適用しない

### 診断

- （補）「もしかして」の候補は，同じ位置で引ける名前のうち編集距離が名前の長さの3分の1（最低1）以下で最も近いもの
- （補）診断はモジュールの順，ファイルの中は位置の順に並べる
- （補）名前のない impl の `DefId` には `impl#1` のような名前を付ける
- （補）impl の fn は impl を親にした `DefKind::ImplFn` の定義を持つ（`ImplFn::def`）．どの名前空間にも入れない（呼び出しは Trait の関数を通り，単相化が impl の fn を選ぶ，10.3）．型検査と lowering が fn と同じく定義ごとに扱うため．impl の中で同じ名前の fn を2回書いたら，trait の関数と同じく E0213

### 部分更新（5.3）

- （補）`C(f: e, ..base)` は HIR の `ExprKind::Update` にする（`Call` とは分ける）．`base` の式は普通に解決する
- （補）`C` が構成子1つのもの（type の構成子，error，フィールドのある handler の構成子）でなければ E0222．enum のバリアント，関数，局所変数，式は E0222．解決できなかった名前には重ねて出さない
- （補）変えるフィールドを位置で書いたら E0223．HIR の `fields` には名前付きの引数だけを残す
- （補）opaque な型の部分更新は構築なので，定義モジュールの外なら E0215
- （補）フィールドの名前が `C` にあるか，`base` の型が `C` の型かは型推論の段で見る

### 同梱の core のソース

- （補）core のモジュールは `ModuleMap::add_core` でソースのモジュールと同じ対応表に足し，同じように収集，import，変換する．同じ名前のソースのモジュールがあれば，名前は core の方を指し，ソースのモジュールには E0203（予約された名前）を出す
- （補）import なしで `.` の左に書けるのと，型の位置で見つからない `X` を `X` モジュールの pub な型 `X` に解決するのは，名前が1区切りの core のモジュールだけ（4.6）．ソースのモジュールは import が要る
- （補）同梱の std のモジュールも `add_core` で足す．名前は `Std.Console` のように `Std` の下の2区切りなので，上の import なしの規則は当たらず，import して使う（15.2）．ソースのルート直下の `std.emel` と `std/` は，std のモジュールと重なるかに関わらず E0203（4.1）．`std/` はディレクトリの位置に1つ出し，中は読まない．`std` 以外のディレクトリの下の `std.emel`（`App.Std`）は置ける
- （補）core に `Prelude` があれば，その pub な定義で Prelude の名前（型，構成子，値）を名前ごとに上書きする．ソースで書いていない名前は組み込みの Prelude のまま残るので，corelib の `prelude.emel` へ少しずつ移せる．上書きした定義は `Program::prelude` にも入るので，`prelude_def` で引ける（`DefModule` は `Source` になる）
- （補）core のモジュールの中では Prelude を隠す警告（W0202）を出さない
- （補）`@intrinsic` は，同梱の core のソースのトップレベルの本体のない fn にだけ付けられる．core の外で使えば E0224，本体のある fn，fn 以外，trait・impl・handler の中の fn に付ければ E0225（今のパーサは本体の中に注釈を置かせないので，最後のものは備え）．HIR の `FnItem::is_intrinsic` が立つ
- （補）`BuiltinModules`（組み込みのモジュールの表）と `DefModule::Builtin` は，同梱の core のソースで置き換わったので使われていない（driver は `NoBuiltins`）．HIR を読む型推論の側と合わせてから外す

- （補）`@external(target, "a", "b")` の引数は `FnItem::externals`（`ExternalAttr`）に書かれた順で持つ．最初の引数が名前でないもの，文字列でない残りの引数は飛ばす（形の誤りは構文の段の E0138〜E0141 が出す）．文字列はエスケープを解いた値．
- （補）無名関数の引数のパターン（`fn((k, v)) { ... }`，6.1）はここで脱糖する．パターンの引数は名前を持たない隠れた引数（`LocalKind::PatParam`，名前はパターンの字面で表示用．スコープには入れない）にし，本体のブロックの先頭に `パターン = 隠れた引数` の束縛（`Stmt::Let`）を足す．型検査の反駁可能性の検査（E0317）と lowering 以降はこの束縛を普通の束縛として扱うので変更がない．名前だけの引数は今までどおり．全部の引数のパターンで1つの Binder を使い，引数どうしの名前の重なりを E0220 にする．構文では名前だけの引数は PARAM の直下の LOWER_NAME のまま，パターンのときだけ PARAM の下にパターンのノードを置く（`ast::Param::pattern`）

### この段で見ないもの（型推論以降に残す）

- 名前付き引数とフィールドのパターンのラベルの照合，フィールドの過不足（`..` なしの省略は 6.5 でエラー）
- handler が effect の操作を全部実装しているか，layer の依存と重複（8.5），impl を書ける場所（10.2），derive と impl の重複（10.5）
- opaque な型のフィールドアクセス

### 参照の表（LSP の定義へ移動と参照の検索）

- （補）解決できた名前の字句ごとに，位置と指す先（定義，局所変数，ソースのモジュール）を `Program::refs` に残す．`Http.Client.get` のようなパスは区切りごとに別の参照．定義の名前と局所変数を束縛した位置は入れない（`DefData::span` と `LocalData::span` にある）
- （補）import のパスは区切りごとに，そこまでの名前のモジュールがあればそれを指す（`import Util.Log` の `Util` はモジュールがなければ何も指さない）．`{x, Y}` の名前は取り込んだ定義を全部指す（type なら型と構成子）
- （補）handler の操作の名前と impl の関数の名前は，実装する effect の操作と trait の関数を指す参照として残す
- （補）組み込みのモジュール（`ModRef::Builtin`）の `.` の左は残さない（指すソースがない）．effect の操作（`log.info`）とフィールドは型推論が引くので，ここにはない
- （補）`@intrinsic` は本体のない fn に加えて effect にも付けられる（組み込みのエフェクト `Scope`，8.1，11.2）．同梱のソースの外では E0224 で，`EffectItem::is_intrinsic` は偽のまま（利用者のエフェクトとして型検査する）．それ以外の宣言に付ければ今までどおり E0225（文面は fn のまま）
- （補）エフェクトの操作の型引数（`fn fork[A](...)`，17.3 の op_sig）は `OpItem::sig.type_params` に入れ，操作の引数と戻り値の型の中で見える．組み込みのエフェクトだけに許すかは型検査が見る（E0426）
- （補）`Program::modules` の `ModuleItems` にモジュール名（`name`）を持たせた．型検査が診断に `Fiber.scope` のような名前を出すため
- （補）エフェクトのラベル（issue #255）．`effect L of E [default]` は EffectItem の `label`（LabelOf）に元のエフェクトとその型引数，`default` を持つ．ラベル自身は操作を持たず，`Program::effect_ops` が元のエフェクトの操作を返す（1段だけ．ラベルのラベルは型検査の E0429）．ラベルの handler（`handler H: L`）は型検査が E0433 にするので，名前解決は操作を引かず，E0212 を重ねない
- （補）`with` の項目は WithItem（`res`，`span`，`by`）．`by` のない項目は handler，layer，エフェクトを受け（Expected::WithItem），`L by P` の左はエフェクト（Expected::Label），右は handler かエフェクト（Expected::HandlerOrEffect）．ラベルかどうか（`with Console` がラベルでない）は名前解決では見ず，型検査が E0430 にする．そのため，`with` にエフェクトを書いたときの「handler or layer が要る」の診断は出なくなった
- （補）impl の頭の型引数（`impl Map[K: Eq, V: Eq]: Eq`，10.2）は impl の定義を親にした `DefKind::TypeParam` で，`ImplItem::type_params` に持ち，impl の本体の中で引ける．`ImplItem::self_ty` は型の名前を自分の型引数に当てた型（`Map[K, V]`）にする．頭の型引数の重複（`impl Pair[A, A]: Eq`）と既存の型と同じ名前（`impl List[Int]: Show` の `Int`）は，E0213 と W0201 でなく E0328 にして頭の全体を指す．名前を見られるのは名前解決なので，E03xx だがここで出す．重複した名前にも型引数を作り，頭の型引数の数を保つ．`ImplItem::malformed_head` が立ち，型検査はその impl の頭を見ない
