# emela-lir の補足

低い IR（LIR）の前の段，Flow IR（制御を明示した段）．後の段は Heap IR（メモリを明示した段）．設計は `emela-0.20-low-ir-design.md`（作業の分け方の 1〜4）．今あるのはデータ型，組み立て（`FnBuilder`），dump，検証器，単相化した Core IR からの変換（`from_core`）と，Heap IR のパスのうちターゲットに依らない前半（`heap`．suspend の状態機械はまだ）．driver と backend にはまだつないでいない．設計にない判断を「（補）」として残す．

## モジュールと関数

- （補）LIR の `Module` は元の Core の `Module` を持つ（`Module::core`）．変数の Core の型はその型の表の `TypeId`，構成子と enum とエフェクトはその定義を指す．Core の関数は使わない（変換で LIR の関数に置き換える）．参照で持つと寿命の引数が全体に広がるので，持ち切りにした
- （補）関数ごとに変数，文，文の並び（`Seq`），ラベルのアリーナを持ち，互いを ID で指す．解析の結果は ID をキーにした表に置ける
- （補）関数は `fails` を持つ．`fail` と `on_fail fail` はこれが真の関数でだけ書け，この関数への直接呼び出しには失敗の辺が要る．変換では Core の `Function::fails` をそのまま使う．Flow IR は単相化の後に作るので，集合の型引数による広めの見積もりは残っていない
- （補）証拠の表は普通の最後の引数（`ref`，Core の型は `Evidence`）．表はエフェクトをキーにした写像のままにする（設計の未決 2）．`ev_lookup` と `ev_extend` はこの写像を引き，伸ばす

## 文と制御

- （補）文の並び（`Seq`）は文の列と終端（`Term`）1つを持つ．終端を文の途中に置くことはデータ型の上でできないので，「終端はブロックの最後」は検証器でなく型で保証する．検証器は，関数とクロージャの本体が終わりまで流れること（`yield` で終わること）を `MissingTerminator` として報告する
- （補）値を返す `if` / `switch` / `block` / `loop` / `protect` は，設計の「結果の変数を先に宣言して各腕で代入する」でなく，文に結果の変数（`dst`）を付け，各腕を `yield v` で終える形にした．変数がどれもちょうど1回だけ定義されるので，検証器は「使う前に定義されている」を有効範囲だけで確かめられ，後の生存区間と RC の解析も単純になる．WASM では `block` と `if` の結果の値に，C では宣言した変数への代入に写せる
- （補）`yield` は囲む文に値を渡して並びを抜ける．`loop` の本体の `yield` はループを抜け，`recur` は次の回に進む．値のない `yield` は dump に書かない
- （補）`recur` は同じ本体の最も内側の `loop` に向かう．`protect` とクロージャをまたげない（Core でも `with` の本体は末尾位置でない）．`break`，`return`，失敗は `protect` の本体から抜けてよく，cleanup が走る．cleanup からは終わりまで流れる以外に抜けられない
- （補）`switch` はタグ（`SwitchOn::Tag`）と，`i32` / `i64` の値（`SwitchOn::Lit`）の2通り．文字列と Float のリテラルのパターンは比較と `if` に落とす．タグの `switch` は default がなければすべての構成子を覆う．リテラルの `switch` は default を必ず持つ（照合しない場合の defect は default に書く）
- （補）失敗の辺は `OnFail::Break(l)`（ラベル `l` の `block` をエラーの値で抜ける．その `block` の結果は `ref`）か `OnFail::Propagate`（囲む関数かクロージャを失敗させる）．辺があるのは失敗しうる呼び出しのときだけ．直接呼び出しは呼び出し先の `fails`，関数値の呼び出しは型の `FnType::fails`，操作の呼び出しは `OpDef::fails`，fiber の操作は `FiberOp::fails` と照らす
- （補）操作の呼び出しは，引数と結果の表現を `OpDef` の型で確かめる．操作自身の型引数（Scope の `fork[A]`）は置き換えずに `ref`（箱）とみなす．ハンドラは汎用の操作を全部の具体化に対して1つで実装するため（Core の `OpDef` の説明のとおり）．`fork` と `deferred` の型はどれも `ref` なので，今はこれで食い違わない
- （補）`defect` は文字列の operand を取る．`assert` の比較のように実行時に組み立てる文言があるため

## 値

- （補）演算の引数は operand（変数か定数）．フィールドの元，呼び出す関数値，クロージャの捕獲のように変数でなければならないところは `VarId` で持つ．ANF もデータ型の上で保証する
- （補）基本の演算（`PrimOp`）は `i32` / `i64` / `f64` に対するもの．文字列の比較（Core の `OpTy::String` の `==` や `<`）は `PrimTy::String` で表し，結果は `i32`．構造の等しさ（`OpTy::Structural`）は基本の演算に入れない（show と同じく型ごとに生成した関数の呼び出しにする）
- （補）表現のない値（`()` と Never）の変数，引数，戻り値は作らない．関数とクロージャの引数，呼び出しの引数は表現のあるものだけを並べる（式は評価する）
- （補）入れ物の中の `()` は，ダミーの定数 `Const::Unit` で1枠を占める（2026-10-15 に仮に決めたもの．後で見直しうる）．入れ物は構成子のフィールド，タプルとリストの要素，セル（`$Cell.new` / `set` の中身），fiber の操作の引数（`Deferred.complete(d, ())`）．`List[()]` が長さを保ち，`field` と `tuple_get` の添字が Core の添字のままになる．`Const::Unit` の表現は `void` なので，検証器はこれを表現が `void` の枠にだけ通す．表現のない枠を読む `field` / `tuple_get` / `list_head` は値がないので結果の変数を持たない（変換は読まずに済ませる）．backend はその枠に何か1語（0 など）を入れる
- （補）クロージャは関数のアリーナを共有し，本体は外側の変数をそのまま指す．指してよいのは `captures` に並べたものだけで，検証器が確かめる．入れ子のクロージャが外の外の変数を使うときは，間のクロージャも捕獲する（間のクロージャの `captures` の要素も「使う」に数える）．クロージャの Core の型は結果の変数の型で，引数の数と表現，`suspends`，`fails` をそこから決める
- （補）組み込み関数は単相化の後なので型引数を持たない．型引数の型の引数は，型引数が `()` なら落ちうるので，その分だけ少ない引数も許す（変換はセルの中身に `Const::Unit` を渡すので，全部の形になる）
- （補）`escape` の受け口には別々の error の enum が届くので，捕まえた値の変数は Core の型を `Any`（`ref`）にする．腕では `is_error e E`（`i32`）でどの error かを調べ，`as_error e E` で E の型の変数にしてからフィールドを読む
- （補）Core に組み込み関数のない実行時の操作は `runtime` で書く（`RuntimeOp`）．`show_string`（入れ物の中と `dbg` の String の表示．引用符とエスケープは JS の `$showString` と同じ），`debug_print`（`dbg` の標準エラーへの出力），`retire`（release の後にハンドラの値を使えなくする．8.6）の3つ．Core の組み込み関数に足すと，`@intrinsic` の宣言と JS の実装も要るので，Flow IR の側に置いた
- （補）`coerce v` は，変数の値を Core の型の違う変数として見る．`let` の局所変数の型と値の型が，集合の型引数（`Exit[Int, ()]` と `Exit[Int, {}]`）以外で違うときに作る．起きるのは，E や R の小さい関数の値を大きい型の局所変数に入れるとき（9.2）．関数値の呼び出しの失敗の辺と `suspends` は呼び出す変数の型で決まるので，局所変数の型に揃えておかないと検証器と食い違う．表現は同じでなければならない（片方が `Any` なら箱に入れる・出すとみなして許す）．Heap IR で呼び出し規約が `fails` と `suspends` で変わるなら，ここで包み直す

## 表現の型（`repr_of`）

- （補）設計の表どおり．引数のない構成子だけの enum は `i32`（タグ，設計の未決 1 をこちらに決めた）
- （補）error の enum は構成子に引数がなくても `ref`．失敗の値は別々の error の enum が混ざって届き，実行時に見分けるため（Core の `EnumDef::error` の要求）
- （補）`@external type`（`EnumDef::external`，ホストのハンドル）と構成子のない enum は `ref`
- （補）`Type::Param` は単相化の後には来ない．`repr_of` は `ref`（箱）を返すが，検証器は型引数を含む型の変数を `Polymorphic` として報告する
- （補）型引数を置き換えた型の表現（`repr_of_subst`）は，置き換えた型を表に登録せずに求める．表現を決めるのは一番外の型だけなので，`Param(i)` なら型引数 `i` の表現，それ以外はその型の表現になる

## dump と検証器

- （補）dump は関数だけを出す（enum とエフェクトは Core の dump で見る）．Core の型の書き方は Core の dump と同じにしたが，Core の dump の関数は非公開なので `core_ty` として写した
- （補）検証器はすべての違反を集めて返す（`verify` はモジュールの全関数，`verify_function` は1関数）．エラーは種類（`ErrorKind`）と文言を持ち，テストは種類で比べる
- （補）組み立て（`FnBuilder`）は自分の構造だけを守る（表現のない型の変数，終端の後の文，終端の2回目で panic する）．中身の正しさは検証器が見る．検証器のテストで壊れた IR を作るときは，`Function` のアリーナに直に足す

## Core IR からの変換（`from_core`）

- （補）入力は `emela_core::verify_monomorphic` を通る Core のモジュール．持ち切りで受け，型の表に変換で要る型（タプルの型，表示の関数の型など）を足して `Module::core` に入れる．変換の間は関数の本体を外へ出しておき，終わったら戻す（本体を読みながら型の表を伸ばすため）
- （補）Core の関数は同じ順と名前の Flow IR の関数になる．表示と等しさの関数は後ろに足す．名前は `show$List[Int]`，`eq$Point` のように型の dump の書き方を付ける（`$` は Emela の名前に出てこない）
- （補）評価の順は JS の backend と同じ（14.1）．左から右，関数値と操作の呼び出しは呼ぶ先を引数より先，リストの `..tail` は要素の後，`assert` の比較は左辺，右辺の順で各1回．`&&` と `||` は `if` にする
- （補）一時変数の名前は `t`．`let` は値の行き着いた一時変数にその局所変数の名前を付け，新しい文を作らない．値が定数なら局所変数を定数そのものに写す
- （補）値を返す `if`，`match`，`escape`，`loop`，`with` の結果の変数は，腕を作った後に作る（最初に値を返した腕の型を使うため）．そのため dump では結果の変数の番号が腕の中の変数より大きい．どの腕も値を返さない（`Never`）ときは結果の変数を作らず，文の後を `unreachable` にする．`Never` の値の呼び出し（`panic` 以外で戻らない関数）の後も `unreachable`
- （補）`panic(msg)` と `todo()` は `defect` にする．`match` でどの腕にも合わないときの defect の文言は JS と同じ `unreachable: no match arm matched`
- （補）パターンは backtracking automaton（Le Fessant と Maranget）の形の決定木にする．腕を行にして，先頭の行の最初の検査と同じ値を検査する行の最大の並びを1つの塊にし，`block 'next` の中で検査する．合わなければ `break 'next` で後ろの行へ進む．塊の中ではどの行もその値を検査するので，各行はちょうど1つの分岐に入り，腕の本体を2回作ることがない（そのかわり後ろの塊で同じ検査をやり直すことがある）．分岐は enum ならタグの `switch`（構成子1つなら検査なし），Int と Int64 はリテラルの `switch`，Bool は `if`，String と Float は `==` と `if` の並び，リストは空かどうかの `if`．ガードの付いた行は，束縛してガードを評価し，偽なら後ろの行へ進む
- （補）フィールド，タプルの要素，リストの先頭と残りは，その経路で最初に要る検査の直前に1回だけ読む（同じ経路の行で使い回す）．束縛は読んだ変数に局所変数を写すだけで，新しい文を作らない
- （補）`escape` は2重の `block` にする．外の `block 'escape` が値の受け口，内の `block 'caught` が失敗の受け口で，対象の式の中の失敗の辺はすべて `'caught` に向かう（`dst` はエラーの値）．腕は上から1つずつ `is_error` で調べ，どの腕にも合わないエラーは外の失敗の行き先へ渡す．ただし失敗しない本体で外に `escape` もないところでは，型検査がすべてのエラーを腕で受けると保証するので `unreachable` にする．ガードもフィールドの検査もない腕より後ろの，同じ error の腕は試さない（JS と同じ）
- （補）`with` の release のある束縛から後ろ（後の束縛と本体）を `protect` で囲む．cleanup は `protect { release } cleanup { runtime retire(h, "名前") }` で，release が defect になってもハンドラの値を使えなくする（JS の `finally` と同じ）．release の値は捨てる．release は失敗しないので，cleanup の中には失敗の行き先を置かない
- （補）クロージャの捕獲は，関数を作り終えてから求める（`captures.rs`）．内側のクロージャを先に求め，その捕獲を外側の本体での「使う」に数える．クロージャの `suspends` は Core のラムダの印でなく型の `suspends` にする．fn の操作の実装のように，型は中断しうるがラムダは中断しないことがあり，関数値の呼び出しは型に従うため
- （補）表示（10.6）は，基本型はその場で書き，リスト，タプル，enum は型ごとに生成した関数を呼ぶ．Int と Int64 は `to_string`，Float は `Float.to_string`（`1.0` の `.0` と `-0.0` の `0.0` は組み込み関数の側），Bool は `True` / `False`，`()` は `()`，中の String は `runtime show_string`．文字列の補間で引用符を付けないのは最上位の String だけ．構成子は JS と同じくソースの形（`Circle(radius: 1.0)`，`Rect(1.0, 2.0)`，`Empty`）．リストの表示は `loop` で `, ` を挟みながら連結する．連結は `String.append` を左から重ね，隣り合う文字列の定数はまとめる
- （補）構造の等しさは，Int，Bool，Int64，Float，String，引数のない構成子だけの enum はその場で `==`，リスト，タプル，enum は型ごとに生成した関数．`()` はいつも等しい．enum はタグを比べてから，構成子ごとにフィールドを順に比べ，違えばその場で `false` を返す．リストは `loop` で両方を1つずつ進める
- （補）関数の中で構成子を使う error の enum（型引数なし）のうち表示できるものには，呼ばれていなくても表示の関数を作り，`Module::error_shows` に並べる．エントリに届いた失敗を backend が `error: NotFound(id: 1)` と出すため（14.3）．どの error が届くかは実行時に値の enum で決まる
- （補）構成子のない enum の表示と等しさの関数は，`@external type`（値がある）なら defect（`cannot show a value of …`），そうでなければ `unreachable`．JS は `undefined` を返す
- （補）変換で意味の取れないもの（表示できない型の表示，束縛されていない局所変数）はエラーとして集め，その場所にはダミーを置いて変換を続ける．`from_core` はエラーがあれば `Err` を返す

## Heap IR（`heap`）

- （補）Heap IR は Flow IR と同じデータ型の後の段で，パスごとに使える構成が変わる．モジュールがどのパスまでかかったかを `Module::stage`（`Stage`）に持ち，検証器は段に合わせて確かめる（前の段で禁じたものは後の段でも禁じる）．`to_heap` が全部のパスを順にかける
- （補）suspend する関数（`Function::suspends`）はクロージャ変換だけかけて残す．状態機械のパスが入るまで，後のパスはこれらを飛ばし，検証器も `Stage::ClosuresConverted` までの段で確かめる．suspend しない関数が suspend する関数を直接呼ぶことはない（呼び出しの `suspends` が呼び先と合う）ので，混ざっても食い違わない
- （補）各パスは関数を作り直す（`copy::compact`）．たどれる変数，文，並び，ラベルだけを出会った順に番号を振り直すので，dump の番号はパスの前と変わる

### クロージャ変換（`heap/closures.rs`）

- （補）クロージャのレコードは `{関数, 捕獲…}` の平らな形にし，レコードそのものを環境にする（`make_closure f[captures]`）．持ち上げた関数は環境（レコード）を最初の引数に受け，本体の頭で捕獲を `env_get env#i` で読む．調査の結論 5 の `{関数の添字, 環境へのポインタ}` から環境の割り当てを1回減らした形で，呼び方（`call_indirect` も `call_op` も，レコードを最初の引数にして関数を呼ぶ）は同じ．lambda set はやらない
- （補）環境の引数の Core の型は，そのクロージャの関数型にする（環境はそのクロージャの値なので）．捕獲の Core の型は `Function::env` に並べ，検証器は `make_closure` の捕獲の型と `env_get` の結果の型をこれと照らす
- （補）トップレベルの関数を値として使う所（`fn_ref g`）は，`g` を呼ぶだけの包み `g$fn(env, …)` のレコードにする．関数の値の呼び方を1通りにするため．捕獲がないので，backend はこのレコードを静的なデータに置ける
- （補）持ち上げた関数の名前は `親$closureN`（N は親の中での出現順で 0 から），包みは `g$fn`．入れ子のクロージャは持ち上げた関数からさらに持ち上げるので `f$closure0$closure0` のようになる

### defect の経路（`heap/defects.rs`）

- （補）defect は例外にも巻き戻しの表にもせず，戻り値の側で明示的に伝える（調査の結論 1）．保留中の defect はランタイムが fiber ごとに1つの枠で持つ．defect を起こす関数と，defect を持ち帰った呼び出しの後の関数は `unwind`（`Term::Unwind`）で呼び出し元へ戻る．値は返さない（backend は何か返す）
- （補）defect を持ち帰りうる呼び出しには，その場の着地点（`on_defect { … }`）を付ける．`Stmt::Let` の欄で，`dst` は見えず，`yield` で抜けられない．C と WASM は呼び出しの後に保留の枠を調べる分岐1つで出せる（`if (pending) { … }`）．失敗の値とは別の経路にしたのは，失敗の型を持たない関数（ほとんど全部）の戻り値の形を変えずに済ませるため
- （補）失敗の辺も呼び出しごとの着地点（`OnFail::Handle { error, body }`）にする．`break 'l(e)` や `fail e` へ直に飛ばず着地点を通すのは，後の RC が呼び出しごとに違う変数を捨てる場所が要るのと，`protect` の cleanup をそこに写すため．Flow IR の `OnFail::Break` と `OnFail::Propagate` は Heap IR では使わない
- （補）着地点が要るのは，`Function::defects` の立った関数の直接呼び出し，関数値と操作の呼び出し（呼び先が分からない），`builtin_may_defect` と `fiber_may_defect` の組み込み関数と並行の操作．`defects` は呼び出しのグラフの不動点で求める．外部関数（ホストの例外は defect，12.5）と suspend する関数はいつも立てる．検証器は着地点が「defect を持ち帰りうる値にちょうど付いている」ことを確かめる
- （補）`defect(msg)` は `runtime defect(msg)` と `unwind` にする．整数の `/` と `%` は，割る数が 0 でない定数でなければ，前に 0 の検査（`division by zero`）を置く．backend は検査なしで割ってよい（`-2147483648 / -1` の巻き戻りは backend の側で 16.1 に合わせる）
- （補）`protect { body } cleanup { c }` は `body` の block にし，`body` を抜けるすべての所（最後の `yield`，外の block への `break`，`return`，`fail`，失敗の着地点，`unwind`）の直前に `c` の写しを置く．抜け方を表す変数で1か所に集める形より，写すほうが単純で，RC の後の形も素直になる．cleanup は release の呼び出しと `retire` だけなので，大きさの増え方は小さい
- （補）defect で抜けるときは，写しの前で保留の defect を取り出し（`runtime defect_take()`），後で戻す（`runtime defect_resume(d)`）．cleanup の中の呼び出しが自分の defect を見分けられるようにするため．cleanup の中で起きた defect は `defect_resume` が最初の defect の注記にし，そのまま外へ巻き戻る（14.4 の「最初の defect が結果」「残りの release はすべて実行」）．値や失敗で抜ける途中で cleanup が defect になったときは，その defect が抜け方を置き換える（14.4 の前半）．注記の文面と順はランタイムが決める
- （補）`Function::defects` は dump の署名の後ろに ` defects` と出す（`Stage::DefectsExplicit` から）

### RC（`heap/rc.rs`，`heap/rc_check.rs`）

- （補）RC は最後のパスで，クロージャ変換と defect の経路の後の制御にかける（調査の結論 2）．`dup x` と `drop x`（`Stmt::Dup`，`Stmt::Drop`）は `ref` の変数にだけ入れる．文字列の定数は静的なデータで，ランタイムが数えない印を付ける（調査の結論 8）ので，IR では何もしない
- （補）引数は既定で所有（調査の結論 9）．持ち上げた関数の環境の引数だけは借用（呼ぶ側がレコードを呼び出しの間生かす）で，捨てず，消費する所では `dup` する
- （補）消費するのは，関数，クロージャのレコード，操作の呼び出しの引数，`make` のフィールド，`tuple` と `list` の要素，`make_closure` の捕獲，`ev_extend` の表とハンドラ，`handler` の操作，`runtime defect_resume` の引数，ループの初期値，`yield`，`break`，`return`，`fail`，`recur` の値．呼び出しは値，失敗，defect のどれで戻っても引数を消費したものとする
- （補）借用するのは，`call_indirect` の呼び先と `call_op` のハンドラ，外部関数，組み込み関数，`runtime`，並行の操作の引数（ランタイムは持ち続けるものを自分で `dup` する），基本の演算，`tag`，`list_is_empty`，`is_error`，`switch` の対象．組み込み関数を借用にしたのは，C で書くランタイムが所有を気にせずに済むようにするため
- （補）`field`，`tuple_get`，`list_head`，`list_tail`，`env_get`，`ev_lookup`，`as_error`，`ref` の `coerce` は「覗き見」（view）で，元の値を借用して中の参照を読む．結果の変数は定義の時点では参照を持たず，後で使うときだけ直後に `dup` を置く（Perceus の射影の扱い）．使われるのが借用だけで元が生きている間なら `dup` と `drop` の組は要らないが，その省略は後の最適化にする
- （補）置き方は生存区間（構造化された制御の上の後ろ向きの解析．ループは不動点）から決める．消費する所の前に，その後もどこかの経路（失敗と defect の着地点を含む）で生きているか，同じ文で借用される変数の分だけ `dup`．文の後に，もう生きていない所有の変数を `drop`（最後に使った直後，使われなければ定義の直後）．分岐，着地点，ループの本体の頭で，そこで使わない所有の変数を `drop`．終端の前で，行き先で要らない所有の変数を `drop`（`yield` と `break` は行き先の文の後で生きているもの，`recur` はループの頭で生きているもの，`return`，`fail`，`unwind` は何も残さない）．合流点へはどの辺も同じ所有の変数を持ち込む
- （補）drop の特殊化と reuse はまだ入れない（設計のとおり reuse は backend が無視しても意味が変わらない形で後から足す）．再帰しない解放（調査の結論 6）はランタイムの側で決める
- （補）検証器の釣り合いの検査（`rc_check`）は，同じ所有の規則で全経路をたどって参照の数を数える．持っていない参照の消費と `drop`，参照のない借用（同じ文で消費した後の借用も含む），スコープや関数を抜けるときに残った参照，合流点へ違う数を持ち込む辺を報告する．規則そのものは pass と共有なので，規則の誤りは捕まえられない（ランタイムで割り当てを記録して参照の数を確かめるテストは backend の段で入れる．調査の結論 10）

## 未決

- `Any` をまたぐ値の箱詰めを Flow IR で明示していない．Scope のハンドラの中で，子の関数（`fn(evidence) -> Int`）を `fn(evidence) -> any` の引数として受け，結果の `any` を `Fiber.join` が `Int` として返す．表現が `i32` と `ref` で食い違うので，Heap IR か backend で包み直すか，変換で操作の呼び出しの引数に `coerce` と包み直しのクロージャを入れる
- 関数値の `fails` / `suspends` の違いは，`let` で局所変数に入れるときだけ `coerce` にしている．呼び出しの引数，戻り値，構成子のフィールドに流れ込むときは暗黙のまま（呼ぶ側と受ける側の型を比べれば分かる）．Heap IR で呼び出し規約がこれらで変わるなら，どこで包み直すかを決める
- 生成した等しさと表示の関数は enum の入れ子を再帰でたどる（リストは `loop`）．JS の `$eq` は明示のスタックで回すので，深い木でスタックがあふれない．WASM ではスタックが小さいので，Heap IR か backend で再帰しない形にするかを決める
