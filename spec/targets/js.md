# 16.6 The JS target `[target.js]`

This section defines what the host and users can observe about the JS target. The meaning of numbers and strings (`[target.number]`, `[target.string]`), the declaration of external functions and the boundary types (`[ext]`), suspension and resumption (`[dyn.suspend]`), and fibers (`[fiber]`) follow their own sections. This section describes the interface between the JS output and the host.

## 16.6.1 Hosts `[target.js.host]`

- The supported hosts are as in the introduction of `[target]`.
- The JS output uses the host's event loop. It learns that the event loop has become empty from the host's `beforeExit` notification. It assumes that if more host work is added after `beforeExit`, the notification comes again the next time the loop becomes empty.
- Informative: suspension and resumption, yielding, AbortSignal, and the order of virtual time (`[target.js.event-loop]`, `[target.js.abort]`) have been checked to give the same results on Node 22.14, Deno 2.7.13 and Bun 1.3.8 (2026-10-13).

## 16.6.2 Emitted modules `[target.js.module]`

- The output is ES modules. `emela build` and `emela run` write the following files to the output directory (`[cmd.build]`).

| Path | Contents |
|---|---|
| `main.mjs` | The entry module |
| `emela_runtime.mjs` | The runtime. `main.mjs` imports only the names it uses from `./emela_runtime.mjs` |
| `emela_core/` | Files that the sources of the bundled core refer to with `@external` |
| `emela_project/` | Files under the project's source root (except `.emel`) |
| `emela_tests/` | Files under the test root (except `.emel`) |
| `emela_pomes/<name>@<version>/` | Files under the source root of a dependency Pome (except `.emel`) |

- When a single file is built, only the files that `@external` refers to are copied to `emela_project/`.
- The first line of the output is `// Generated by Emela.`.
- The `pub` fns of the entry module and `main` are exported. The export name is the Emela name of the fn. Even if the name of the fn is a JS reserved word, it is exported under that name.
- A `pub` fn with type parameters is exported under its original name as a single function in which every type parameter is any type. It MAY be called with values of any type. A fn with a type parameter that has a bound cannot be exported (E0327, `[cmd.build]`).
- A module that exports at least one suspending fn also exports `$start` (`[target.js.start]`). If it exports no suspending fn, it does not export `$start`.
- How to call an exported fn whose R has effects other than Async is unspecified.

## 16.6.3 Boundary values `[target.js.value]`

The parameters and return values of external functions (`[ext.boundary]`) and of exported fns are represented by the following JS values.

| Emela | JS |
|---|---|
| Int | number (an integer from -2^31 to 2^31 - 1) |
| Int64 | bigint (-2^63 to 2^63 - 1) |
| Float | number |
| Bool | boolean |
| String | string |
| `()` | `undefined` |
| `@external type` | The host object itself |
| Function type | A JS function. Its parameters and return value are converted by this table |

- A String received from the host is normalized as in `[ext.exception]`. The same applies to a String received as an argument of a callback.
- The JS representation of values of other types is unspecified (`[target.unspecified]`).

## 16.6.4 How outcomes appear `[target.js.outcome]`

When the host calls an exported fn, the way it ends appears as follows.

- If it ends with a value, it returns that value.
- If it ends with an error, it returns a failure value without throwing. The failure value has a method keyed by `Symbol.for("emela.fail")`. This method returns the error value as shown (`[dyn.error]`). When other fibers have also failed, the notes (`[fiber.scope]`) follow, one per line.
- If it becomes a defect, it throws an `Error` whose `name` is `"Defect"` and whose `message` is the defect message (`[error.defect]`).
- If it unwinds as interrupted, it throws an `Error` whose `name` is `"Interrupted"`.

## 16.6.5 Launching a suspending fn `[target.js.start]`

- When the host calls an exported suspending fn, it returns a generator. The generator is advanced by passing it to `$start(gen, done)`.
- `$start` calls `done(true, return value)` if the launch ends with a value or an error, and `done(false, exception)` if it ends with a defect or an interruption, exactly once. The forms of the return value and the exception are as in `[target.js.outcome]`.
- If the fn stays suspended and is never resumed, `done` is not called. Telling this apart is the caller's job: when the event loop becomes empty, the caller calls the function that `$start` returned. If the launch has not ended, this function unwinds the waiting continuations, running the releases from the inside out (`[dyn.suspend]`), and calls `done(false, Interrupted)`. If a release waits on a Promise, the event loop continues. If a release remains suspended, the caller calls the function again the next time the event loop becomes empty.
- When a fiber is waiting on virtual time, this function does not interrupt the launch, and instead wakes one waiter (`[target.js.event-loop]`).

## 16.6.6 Calling external functions `[target.js.external]`

- `@external(js, "name")` is a reference followed from the global object. Each part separated by `.` is looked up as a property in turn (`"console.log"` is `globalThis.console.log`).
- `@external(js, "module", "name")` reads an export of a module. If the module is a file starting with `./` or `../` and is under a source root (of the project, the tests or a dependency Pome), the file copied to the output directory (`[target.js.module]`) is imported by relative path. A file under none of the roots is imported by an absolute `file:` URL. A specifier that is not a file (`"node:fs"`, for example) is imported as it is. The same module and name are imported only once.
- An exception thrown by a host function is a defect, as in `[ext.exception]`.
- An external function that returns `()` discards the host's return value (`[ext.boundary]`).
- When an external function with no annotation for the target is called, the defect message is ``external function `f` is not available on this target``. The name is the Emela name of the fn, without type arguments.

## 16.6.7 External suspend fns and AbortSignal `[target.js.abort]`

- An `@external` suspend fn calls the host function and waits for the returned value to resolve. A value that is not a Promise is treated as resolved with that value. The resolved value is converted by the same rule as return values (`[target.js.value]`). An exception from the call and a rejected Promise are both defects (`[ext.exception]`). A rejection happens at the position where the fiber was waiting.
- The host function receives one extra `AbortSignal` after the declared arguments (`[ext.call]`).
- When the waiting continuation is discarded (an interruption of the fiber, an interruption of the launch), the runtime aborts that `AbortSignal`. When execution continues normally through resume, it does not abort.
- When an implementation of a suspend fn operation is waiting on an external function and the caller is interrupted before resume, the continuation of the implementation is also unwound, and that wait is aborted. After the implementation has resumed, the continuation of the implementation is not stopped (`[dyn.suspend]`).
- When the launch ends, all remaining waits are aborted.

## 16.6.8 Event loop and yielding `[target.js.event-loop]`

- Yielding for fairness (`[fiber.basic]`) happens only before a suspending call inside a suspending fn. No yield is inserted before fiber operations (join, await and so on), because they are suspension points themselves.
- A fiber that yields goes to the end of the queue of fibers waiting to run. Every certain number of yields, the runtime returns control to the host's event loop. At that point, timer and I/O callbacks run. Control is returned to the host with `setImmediate`, or with `setTimeout` with a delay of 0 if the host has no `setImmediate`.
- Informative: the current implementation yields once every 1000 suspending calls per fiber, and returns to the host's event loop once in 16 yields, counted per launch. The numbers are not specified (`[fiber.basic]`).
- An empty event loop is what virtual time (TestClock of `[effect.state]`) treats as "no fiber can proceed and no host work is pending". At that point, if there are waiters on virtual time, the one with the earliest wake-up time (for the same time, the one that started waiting first) is woken, and only that one. It is woken through `setImmediate`, and the next waiter is woken the next time the event loop becomes empty. If there are no waiters, the launch is interrupted (`[target.js.start]`). When a waiting fiber is interrupted, its wait is canceled.

## 16.6.9 Output of dbg `[target.js.dbg]`

- `dbg` (`[lib.prelude]`) prints its output as one line with `console.error`. It does not print the source location (`[open.list]` #26).

## 16.6.10 Graphemes in strings `[target.js.string]`

- Informative: `String.length` and the functions that split by grapheme cluster determine grapheme cluster boundaries with the host's `Intl.Segmenter` (default locale). Until the fixed Unicode version (`[target.string]`) is decided, the boundaries follow the version of the host's Unicode data.
