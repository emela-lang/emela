# Emela 言語仕様 草案（0.20 系）

最終更新 2026年10月13日（改訂の経緯は末尾の「改訂履歴」を参照）

> 0.20 系の言語仕様の草案である。実装中に仕様にない判断をした場合は、各クレートの `NOTES.md` に（補）として残し、仕様に関わるものは 18.2 と改訂履歴に反映する。

Emela は、データの定義、それを操作する関数、副作用の明示の3つを単純に保つことを基準にした関数型言語で、JavaScript と WebAssembly にコンパイルする。この文書は、再設計後の言語（0.20 系）について合意した決定を体系的にまとめた草案である。

## 1. 位置づけと設計原則

Emela は、Effect-TS の開発パターンと、厳格なエフェクト型を、1つの言語として提供する。対象は JavaScript と WebAssembly で、同じプログラムが両方で同じ結果を返すことを仕様の要件とする。

### 1.1 3本の柱

言語の機能は、次の3つのどれかに属する。どれにも属さない機能は入れない。

- データの定義: `type`、`enum`、`error`
- データを操作する関数: `fn`、`match`、`|>`
- 副作用の明示: `effect`、`use`、`with`

### 1.2 2つの層

| 層 | 書く人 | 含まれるもの |
|---|---|---|
| 日常の層 | アプリケーションを書く人 | `type` `enum` `error` `fn` `match` `use` `with` `fail` `escape` |
| 基盤の層 | ライブラリやランタイム境界を書く人 | `effect` `handler` `layer` `suspend` `trait` `impl`、`fails` 節と `use` 節、制約、`@external` |

日常の層のコードを書くのに基盤の層の知識が必要になる場合、それは設計の不具合として扱う。

### 1.3 固定した前提

- 継続は one-shot に限る。中断した計算を再開できるのは高々1回である。これは恒久的な前提で、将来も変えない。
- エラーはエフェクトではなく、独立したチャネルで扱う。
- 期待されるエラー（型に現れる）と defect（型に現れない）を区別する。
- 変数は不変である。ループ構文は持たない。
- 高カインド型、部分型、null、暗黙の型変換、演算子の多重定義は持たない。

### 1.4 この文書の読み方

- 「エラーになる」は、コンパイル時に拒否されることを指す。実行時の異常終了は「defect になる」と書く。
- コード例の拡張子は `.emel` とする。
- 合意が済んでいない箇所と、この草案を書く際に補った箇所は、18章にまとめてある。本文中では「（補）」と記す。

## 2. 字句

名前の種類は大文字と小文字で決まり、文の終わりは改行で決まる。どちらも字句解析の段階で確定し、名前解決の結果に依存しない。

### 2.1 ソースファイル

- 拡張子は `.emel`、符号化は UTF-8 とする。
- セミコロンは使わない。文は改行で終わる（2.5）。
- 空白はスペースとタブである。改行は `\n` か `\r\n` で、どちらも1つの改行として扱う。単独の `\r` と、Unicode の空白（全角空白など）は認識できない文字になる。

### 2.2 コメント

- `#` から行末までがコメントである。
- `##` はドキュメントコメントで、直後の宣言、バリアント、フィールド、エフェクトの操作、handler の項目に付く。宣言と `derive` の間に書いたものは宣言に付かない。
- ブロックコメントは持たない。

### 2.3 名前の字句クラス

| クラス | 形 | 使うもの | 例 |
|---|---|---|---|
| 小文字名 | 小文字で始まる snake_case | 変数、関数、フィールド、ラベル、エフェクトの操作 | `user_id` `find` |
| 型名 | 大文字で始まり、小文字を1つ以上含む PascalCase | 型、構成子、エラー、エフェクト、ハンドラ、layer、Trait、モジュール、型引数 | `User` `Http` `Db` `Item` |
| 大文字名 | 大文字、数字、アンダースコアだけ | const、型引数 | `MAX_SIZE` `A` |

- クラスに合わない名前は構文エラーになる。`HTTP` や `DB` は型名として使えず、`Http`、`Db` と書く。
- 型名と大文字名は、既存の定義を指す名前である。式やパターンの中で新しく束縛されることはない。そのため、パターン中の打ち間違いは必ず「未定義の名前」としてエラーになる。
- `_` は、値を束縛しないパターンである。
- 型引数は、大文字名（`A`、`T`）と型名（`Item`、`Key`）のどちらでも書ける。型引数を宣言できるのは `[...]` の中だけで、型の位置でだけ参照できる。型名で書いた型引数が型か型引数かは、名前解決で決まる。
- 型引数は、同じ名前の外側の型・エフェクト・エラー・Trait を隠す。型名の型引数が隠したときは警告する（W0201）。後から型を足したとき（Prelude への追加を含む）に、既存のコードが壊れないようにするためである。
- 名前に使える文字は ASCII だけである。
- 字句解析は 17.2 の EBNF に従う。小文字名が途中に大文字を含むこと（`userId`）と、型名で大文字が続くこと（`HTTPServer`）は字句としては許し、snake_case と PascalCase の慣習は linter が検査する。

この規則から、`.` の左側を見れば意味が分かる。

- 左が型名: 静的な参照（モジュールの関数、Trait のメソッド）。例: `List.map`
- 左が小文字名か大文字名: 値へのアクセス（フィールド、`use` で得た能力の操作）。例: `user.name`、`log.info`、`DEFAULT_CONFIG.port`

### 2.4 リテラル

| 種類 | 形 | 備考 |
|---|---|---|
| 整数 | `42` `1_000_000` `0xFF` `0b1010` | 文脈が Int64 を要求すれば Int64、それ以外は Int。Float にはならない。`0x` は16進、`0b` は2進 |
| 浮動小数点 | `3.14` `1.0e9` | Float |
| 文字列 | `"hello"` `"""..."""` | `#{式}` で補間する。式の型は Show を満たすこと。`#{ }` の中は普通のコードとして字句解析し、コメントと改行を書ける（改行は 2.5 により継続になる）。`"""` で囲むと複数行を書ける |
| リスト | `[1, 2, 3]` `[x, ..rest]` | `List[Int]`。末尾の `..式` は、その前に要素を付けたリストを作る（17.5） |
| タプル | `(a, b)` | 要素は2つ以上 |
| Unit | `()` | 要素0個のタプル |

真偽値はリテラルではなく、Bool の構成子 `True` と `False` である。

- 浮動小数点の指数は、小数点のある形にだけ付けられる（17.2）。`1e9` は書けず、`1.0e9` と書く。数値の直後に英字が続くもの（`1e9` `3px`）は字句のエラーになる（E0104）。
- 文字列は改行をまたげない（E0101）。複数行は `"""` の文字列で書く。
- 16進と2進の接頭辞は小文字だけ（`0x`、`0b`）。16進の数字は大文字と小文字のどちらでもよい。8進は持たない。値が文脈の型（Int か Int64）の範囲を超えればエラーになる（E0311）。負の数は単項マイナスの式なので、リテラル自体は正の数として範囲を見る。そのため Int の最小値 `-2147483648` はリテラルでは書けない（`Int.MIN` のような定数を core に置く）（補）。2の補数として読み替えない（`0xFFFF_FFFF` は Int では書けず、Int64 なら書ける）。
- 文字列のエスケープは次の7つである。それ以外の `\` はエラーになる。

| エスケープ | 意味 |
|---|---|
| `\"` | `"` |
| `\\` | `\` |
| `\n` | 改行（U+000A） |
| `\t` | タブ（U+0009） |
| `\r` | 復帰（U+000D） |
| `\#` | `#`。`#{` を補間でなく文字として書くときに使う |
| `\u{...}` | 1〜6桁の16進で書いた Unicode のコードポイント。サロゲート（D800〜DFFF）と 10FFFF を超える値はエラー |

- 複数行の文字列は `"""` で囲む。開く `"""` の直後は改行でなければならず、閉じる `"""` はそれだけで1行に置く。閉じる `"""` の行のインデントを、各行の先頭から取り除く。開く `"""` の直後と、閉じる `"""` の直前の改行は含めない。閉じる `"""` より浅くインデントした行（空行を除く）はエラーになる（E0109）。インデントは文字の並びとして比べ、空行を除く各行は、閉じる `"""` の行のインデントと同じ並びで始まらなければならない。タブと空白が違う行も浅いとみなす。補間とエスケープは普通の文字列と同じく使える。

```emel
query = """
  SELECT *
  FROM users
  WHERE id = #{id}
  """
# "SELECT *\nFROM users\nWHERE id = 1" と同じ
```

- 文字の型（Char）は持たない。1文字は長さ1の String で表す（16.2）。
- エスケープを解釈しない生の文字列は持たない。
- 負の数はリテラルではなく、単項マイナスを付けた式である。パターンでは、数のリテラルの前に `-` を書ける（6.5、17.6）。

### 2.5 行の継続規則

改行は文を終わらせる。ただし次の場合は、前の行が続く。

1. 次の行が二項演算子、`.`、`escape`、`match` のいずれかで始まる。`match` は、次の意味のあるトークンが `{` のときだけ続ける（後置の match は必ず `match {` なので、正しいプログラムの読み方は変わらない。そうでない行は前置の match として新しい文に読み、E0142 を出す）。
2. 開いた `(` または `[` がまだ閉じていない。
3. 次の行が `else`、`->`、`|` のいずれかで始まる。どれも文を始めることがないので、継続にしても曖昧さは生まれない。`} else {` への揃えは formatter が行う。
4. シグネチャの中で、次の行が `fails` か `use` で始まる。シグネチャの中とは、fn の宣言の本体の `{` より前と、effect の操作の宣言である。そこでは文が始まらないので曖昧さは生まれない。本体の中では、`fails` はふつうの識別子に使え、`use` は式を始めるので、今までどおり新しい文になる。本体の `{` は、シグネチャの最後の行に書く。

```emel
pub fn get(url: String) -> Response
  fails InvalidUrl | ConnectionFailed | ResponseNotText
  use Http {
  ...
}
```

次のトークンで始まる行は、常に新しい文になる。

- `(` と `[`: 関数呼び出しや型引数の開き括弧は、名前と同じ行に書く。
- `-`: 行頭では単項マイナスとして読む。行頭の `-` は前の行を継続せず、新しい文になる。

括弧の外では、行末に二項演算子を置いても次の行へ継続しない。二項演算子で前の行を継続するときは、`-` 以外の演算子を次の行の先頭に置く。引き算の右辺を次の行に書くときは、式を括弧で囲む。括弧内の改行は規則2により継続する。

補足:

- 継続の判定は、改行の次の「意味のあるトークン」を見る。間の空白、コメントだけの行、空行は飛ばす。
- 規則2の「開いた括弧」は、括弧の入れ子の最も内側で判定する。`(` の中でも、その内側に開いた `{` があれば改行は文を区切る（`f(fn(x) {⏎a⏎b⏎})`）。
- 文字列の補間 `#{ }` の中の改行は、`(` の中と同じく継続になる。

```emel
user = users.find(id)
  |> Option.or_fail(NotFound(id:))   # 前の行の続き

foo
(bar)                                # foo とは別の文
```

## 3. 予約語と注釈

予約語は25個で、どの位置でも識別子に使えない。それ以外に、決まった位置でだけ意味を持つ語と、将来のために確保した語がある。

### 3.1 予約語

| 分類 | 語 |
|---|---|
| 宣言 | `fn` `type` `enum` `error` `const` `trait` `impl` `effect` `handler` `layer` `import` |
| 修飾 | `pub` `opaque` `suspend` |
| 式 | `if` `else` `match` `fail` `escape` `use` `with` `assert` |
| 特別な名前 | `self` `Self` |
| 初版では未使用 | `as` |

`as` は import の別名のための予約語である。初版の範囲では構文を持たない。

### 3.2 文脈依存の語

次の語は、示した位置でだけキーワードとして働く。それ以外の位置では普通の識別子である。

| 語 | 位置 |
|---|---|
| `implements` | handler の宣言 |
| `for` | `impl A for B` |
| `fails` | 関数のシグネチャと関数型 |
| `derive` | type と enum の宣言の末尾、trait の本体 |
| `init` `release` | handler の本体 |

### 3.3 将来のための予約

次の語は構文を持たないが、識別子にも使えない。

`var` `return` `while` `loop` `let` `mut` `in` `where` `do` `try` `catch` `throw` `async` `yield` `defer` `macro` `mod`

### 3.4 キーワードではないもの

- `True`、`False`、`Some`、`None` は、Prelude の enum の構成子である。
- `panic`、`todo`、`dbg` は、Prelude の関数である。
- `resume` は、ハンドラの引数に付ける慣習的な名前である。
- `Immediate`、`Async`、`Eq` などは、組み込みの Trait やエフェクトの名前である。

### 3.5 注釈

注釈は `@名前(引数)` の形で、宣言の直前に置く。使えるのはコンパイラ組み込みの注釈だけで、利用者が新しい注釈を定義することはできない。

| 注釈 | 対象 | 意味 |
|---|---|---|
| `@external(...)` | 本体のない fn | ホスト側の実装を指す。フィールドのない type にも付けられる（12章） |
| `@test` | fn | テスト関数である（13章） |
| `@deprecated(...)` | 任意の宣言 | 使用箇所で警告する |
| `@intrinsic` | 本体のない fn（同梱の core のソースのトップレベルだけ） | コンパイラが実装を持つ組み込み関数である。シグネチャは Emela の文法で書き、実装は名前でコンパイラの組み込み関数の表から引く。core のソースの外では使えない（E0224）。付いた fn は 17.3 の `@external` の制約を満たす |
| `@internal` | トップレベルの fn（同梱の core のソースだけ） | core のモジュールの外から参照できない（E0228）。core の外や、トップレベルの fn 以外には付けられない（E0229） |
| フィールド注釈 | type と enum のフィールド | 導出の細部を指定する。名前と引数は未定（18章） |

## 4. モジュールと可視性

1つのファイルが1つのモジュールであり、モジュール名はファイルのパスから決まる。ファイルの中でモジュールを宣言する構文はない。

### 4.1 モジュール名

- ソースのルートからのパスを、区切りごとに PascalCase へ変換し、`.` でつなぐ。`src/http/client.emel` は `Http.Client` になる。
- ファイル名とディレクトリ名は、小文字の snake_case とする。`json_codec.emel` は `JsonCodec` になる。
- モジュール間の循環参照はエラーになる。

変換の細部:

- 変換後の名前は型名の字句クラス（2.3）に合わなければならない。`a.emel`（`A`）や `x_y.emel`（`XY`）のように小文字を含まない名前、ASCII 以外を含む名前はエラーになる。
- `_` の直後の数字はそのまま残す。`http_2.emel` は `Http2` になり、`http2.emel` と重複する。
- 同じモジュール名になるファイルが2つあればエラーになる。大文字小文字の違いだけのファイル（`Foo.emel` と `foo.emel`）も重複として扱う。
- 名前が正しくないディレクトリは、中のファイルをモジュールにしない。
- `.` で始まるファイルとディレクトリ、`.emel` 以外のファイルは無視する。
- ソースのルート直下の `prelude.emel` と、core のモジュールと同じ名前のファイル（`string.emel`、`list.emel` など）と、`std.emel` と `std/` は予約名で、置けない（E0203）。std の層のモジュールは `Std` の下に置くので、std にモジュールを足しても予約名は増えない（15.2）。
プロジェクトとソースのルート:

- `Pome.toml` を置いたディレクトリがプロジェクトである。ソースのルートは `<プロジェクト>/src` になる。`Pome.toml` の中身の形式は未決（18.1 #14）で、0.20 では有無だけを見る。
- `emela` コマンドに渡したパスを、シンボリックリンクを解いた絶対パスに直し、祖先を上にたどって最初に見つかった `Pome.toml` のディレクトリをプロジェクトにする。
- ディレクトリを渡して `Pome.toml` が見つからなければエラーになる。プロジェクトのエントリは `<プロジェクト>/src/main.emel` である。
- ファイルを渡して `Pome.toml` が見つからなければ、単独ファイルとして扱う。そのファイルがエントリで、モジュールはファイルと同じディレクトリの直下にある `.emel` だけになる（サブディレクトリと祖先は見ない）。読んで検査するのは、エントリから import でたどれるファイルだけである。たどれない兄弟ファイルの誤りは診断に出ない。
- ファイルを渡して `Pome.toml` が見つかったが、ファイルがソースのルートの外にあるときはエラーになる（E0208）。
- 出力先はプロジェクトなら `<プロジェクト>/target/emela/js`、単独ファイルならファイルのあるディレクトリの `target/emela/js` である。
- 診断に出すパスは、プロジェクト（単独ファイルならファイルのあるディレクトリ）からの相対パスである。

### 4.2 import

```emel
import Http.Client                  # Client.get(...) と呼ぶ
import Data.Json.{Json, decode}     # Json と decode を修飾なしで使う
```

- `import A.B` は、最後の名前 B をスコープに入れる。
- 波括弧で列挙した名前だけが、修飾なしで使える。すべてを取り込む記法はない。
- import はファイルの先頭に置く。コメントは数えない。宣言より後ろの import はエラーになる（E0127）。
- 別名（`as`）は初版の範囲に含めない。

### 4.3 pub

- 宣言は既定で非公開であり、`pub` を付けたものだけが他のモジュールから見える。
- `pub` を付けられるのはトップレベルの宣言だけである。対象は `fn` `type` `enum` `error` `effect` `handler` `layer` `const` `trait`。
- フィールドやバリアントを個別に公開、非公開にする指定はない。

### 4.4 opaque

`opaque` は、型名だけを公開し、中身を隠す。

| 宣言 | 型名 | 構築 | パターンマッチ | フィールドアクセス |
|---|---|---|---|---|
| `pub type` / `pub enum` | 公開 | 公開 | 公開 | 公開 |
| `pub opaque type` / `pub opaque enum` | 公開 | 定義モジュール内のみ | 定義モジュール内のみ | 定義モジュール内のみ |

```emel
# src/email.emel
pub opaque type Email(value: String)

pub error InvalidEmail(input: String)

pub fn parse(input: String) -> Email fails InvalidEmail {
  if String.contains(input, "@") {
    Email(value: input)
  } else {
    fail InvalidEmail(input:)
  }
}

pub fn to_string(email: Email) -> String {
  email.value
}
```

他のモジュールからは `Email.parse(...)` でしか値を作れない。Email 型の値があれば、検証を通っていると型で保証される。

### 4.5 公開関数の型注釈

公開関数の戻り値の型、fails、use の注釈は任意である（引数の型は 6.1 により必須）。省略した場合、linter が警告し、LSP のコードアクションで推論結果を挿入できる。

### 4.6 名前の解決

モジュールの名前は、型・構成子・値の3つの名前空間と、モジュール名に分かれる。

| 名前空間 | 含まれるもの |
|---|---|
| 型 | type、enum、error、effect、handler、layer、trait |
| 構成子 | type の構成子、enum のバリアント、error、フィールドのある handler |
| 値 | fn、const |

- どの名前空間を引くかは、名前を書いた位置で決まる。`.` の左ではモジュールと Trait だけ、型の位置では型だけ、式とパターンの型名では構成子だけを引く。4.4 のモジュール `Email` と型 `Email` はこれで衝突しない。
- `import Email` だけでは型 `Email` は修飾なしで使えない。`Email.Email` と書くか、`import Email.{Email}` で取り込む。
- `.` の左の名前は、モジュールの定義と import から探し、なければ組み込みのモジュールと Prelude の Trait を探す。同じ水準でモジュールと Trait の両方が見つかればエラーになる（E0218）。
- `A.B.f` の B は、モジュール A の pub な Trait に限る。入れ子のモジュールはない。エフェクトを `.` の左に書くことはできない（`Logger.info` はエラー。8.2）。
- `import A.B.{x}` の形でも、B はモジュールとしてスコープに入る。列挙した名前は、その名前を持つすべての名前空間から pub なものを取り込む（type なら型と構成子）。
- import した名前は再公開しない。他のモジュールから引けるのは、そのモジュールが定義した名前だけである。同じ定義を2回 import しても重複にならない。
- バリアントと type の構成子は、親の型の pub と opaque に従う。バリアントは名前で個別に import できる。
- 同じ名前空間での重複はエラーになる（E0213）。エフェクトの操作、trait の関数、フィールド、型引数の並びの中で同じ名前を2回宣言しても同じエラーになる。同じモジュールの2つの enum が同じ名前のバリアントを持つ場合や、`type Green` とバリアント `Green` も重複である。
- モジュールの定義と import は、Prelude の同じ名前を隠してよい。警告する（W0202）。Prelude に名前を足しても、既存のコードが壊れないようにするためである（2.3 の型引数と同じ考え方）。
- 組み込みのモジュール（String、List など）は、import なしで `.` の左に書ける。型の位置の名前 X がどこにも見つからず、組み込みのモジュール X が同じ名前の型 X を持つときは、その型に解決する（`Option[List[User]]` を import なしで書ける）。ソースのモジュールにはこの規則を適用しない。
- Immediate（9.5）と Async（8.7）は、import なしで見える。
- 同梱の core のモジュールは、ソースのモジュールと同じ対応表に入り、単独ファイルでも必ず読む。import なしで `.` の左に書けることと、型の位置の名前を core の型に解決することは、名前が1区切りの core のモジュールにだけ当てはまる。
- 1つのパターンか引数の並びで、同じ名前を2回束縛するとエラーになる（E0220）。束縛では右辺を先に解決し、その後でパターンの名前を入れる。
- handler の操作と release の中では `self` が見える。init の中では見えない（init はハンドラの値を作る側のため）。フィールドのある handler は同じ名前の構成子を持ち、init で `PostgresUsers(conn: ...)` と書ける。
- escape の腕の最上位の構成子パターンは、error に限る（E0217）。`_` と変数は名前解決では通すが、型検査でエラーになる（E0320、7.3）。

## 5. データ

データは type（直積）、enum（直和）、タプルの3つで定義する。宣言、構築、パターンはすべて同じ `()` の形をとる。

### 5.1 括弧の役割

| 括弧 | 役割 |
|---|---|
| `( )` | 値の世界: 関数呼び出し、構築、パターン、フィールドの宣言、タプル |
| `[ ]` | 型引数とリストリテラル |
| `{ }` | ブロックと宣言の本体 |

添字アクセスの構文（`xs[0]`）は持たない。要素の取得は `List.get(xs, 0)` のような関数で行い、Option を返す。

### 5.2 基本型

| 型 | 内容 |
|---|---|
| `Int` | 32ビット符号付き整数 |
| `Int64` | 64ビット符号付き整数 |
| `Float` | 64ビット浮動小数点数（IEEE 754 binary64） |
| `Bool` | `True` または `False` |
| `String` | Unicode 文字の列（16章） |
| `()` | Unit。値は `()` の1つだけ |
| `Never` | 値を持たない型。`fail` や `panic` の型 |

### 5.3 type

```emel
type User(id: Int, name: String)

type Pair[A, B](first: A, second: B)

type Todo(
  id:        Int,
  title:     String,
  completed: Bool,
)
```

- type は、型と、同じ名前の構成子を1つ定義する。バリアントが1つの enum と同じものである。
- 構築は `User(id: 1, name: "a")`、フィールドの参照は `user.name` と書く。
- フィールドを参照できるのは、type、error、フィールドのある handler の値だけである。enum の値は、バリアントが1つでもフィールドを参照できない。中身は match で取り出す（E0313）。
- 型は名前で区別する（nominal）。フィールドが同じでも、名前が違えば別の型である。
- 無名のレコード型は持たない。

一部のフィールドだけを変えた値は、構成子の呼び出しの末尾に `..式` を書いて作る。書いたフィールド以外は、`..` の後の値から引き継ぐ。

```emel
renamed = User(name: "b", ..user)
fixed   = Todo(title: "Buy milk", completed: True, ..todo)
```

- 使えるのは構成子が1つのもの（type、error、フィールドのある handler）だけである。enum のバリアントには使えない（`..` の値がそのバリアントだと型で保証できないため）。
- 変えるフィールドは名前付きで書く。位置では書けない。
- `..` の後の式の型は、その構成子の型でなければならない。型引数は変わってよい。`p: Pair[Int, Bool]` から `Pair(first: "s", ..p)` を作ると `Pair[String, Bool]` になる。引き継ぐフィールドの型が矛盾しなければよい。
- opaque な型は、定義モジュールの外では更新もできない（構築と同じ。E0215）。
- フィールドを全部書いたうえで `..` も書いたとき、またはフィールドを1つも書かずに `..` だけを書いたときは、linter が警告する。

### 5.4 enum

```emel
enum Shape {
  Circle(radius: Float)     # 名前付き
  Rect(Float, Float)        # 位置引数
  Empty                     # 中身なし
}

enum Option[A] {
  Some(A)
  None
}
```

- enum は閉じた直和型である。バリアントは型ではなく、親の型の値を作る構成子である。`fn f(c: Circle)` とは書けない。
- バリアントの中身は、なし、位置引数、名前付きの3形式から選ぶ。1つの enum に形式の違うバリアントを並べてよい。
- 1つのバリアントの宣言で、名前のないフィールドと名前付きのフィールドを混ぜることはできない。1つでも名前を付けたら、すべてのフィールドに名前を付ける（E0128）。呼び出し側の規則（6.2）は変わらない。
- バリアントの区切りは、改行かカンマである。
- 一般の union 型は持たない。union はエラーの集合にだけ現れる（7章）。

### 5.5 タプル

- 型は `(Int, String)`、値は `(1, "a")`、パターンは `(n, s)` と書く。
- 要素0個のタプル `()` が Unit である。要素1個のタプルはなく、式の `(x)` と型の `(T)` はただの括弧である。パターンの `(a)` は書けない（E0112）。
- 型の括弧は、関数を返す関数型で fails と use がどの `fn` に付くかを書き分けるのに使う。`fn make() -> (fn(Int) -> String) fails ParseError` の fails は make のもので、括弧がなければ内側の `fn` のものになる。

### 5.6 const

```emel
const MAX_RETRY = 3
const DEFAULT_CONFIG = Config(port: 8080)
```

- 名前は大文字名で書く。
- 右辺は純粋な式（E と R が空）に限る。`use` や `fail` は書けない。関数の呼び出しは書ける（`const DEFAULT_TIMEOUT = Duration.seconds(5)`）。opaque な型の値は関数でしか作れない（4.4）ので、コンパイル時に評価できる式に絞ると、そういう const が書けなくなるためである。
- 右辺は、最初に参照したときに1回だけ評価し、その値を覚えておく。純粋なので値は変わらない。起動時にすべてを評価しないのは、使っていない const の defect でプログラムやほかのテストが動かなくなるのを避けるためである。
- 評価の途中の defect は、最初に参照したところで起きる。文面に const の名前を入れる（`while evaluating const X: division by zero`）。評価の途中で自分自身を参照すると defect になる（`const A refers to itself while being evaluated`）。名前だけで循環している const（`const A = B` と `const B = A`）はコンパイル時にエラーになる（E0231）。
- 評価の途中の defect も覚え、次の参照でも同じ defect を起こす（評価し直さない）。テストの間でも共有される。入れ子の const の defect は、通った const ごとに名前を前に足す（`while evaluating const A: while evaluating const B: division by zero`）。自己参照の defect には名前を足さず、どの const にも覚えさせない（最初にどこから参照したかで文面が変わらないように）。
- E0231 は、値を評価すると必ず評価する参照だけで循環を見る。if と match の腕、`&&` と `||` の右辺、ラムダの本体、呼んだ関数の中の参照は数えず、実行時の自己参照の defect に任せる。構造を通る循環（`const P = (Q, 1)` と `const Q = [P]`）は E0231 になる。
- 型を書いていない const の型は汎化する。`const EMPTY = []` の型は `∀ A. List[A]` である。
- パターンに書くと、その値との照合になる（`==`）。右辺がリテラル、単項マイナスを付けた数値のリテラル、構成子、タプル、リスト、ほかのそういう const だけでできていれば、網羅と冗長の判定ではその値として扱う。そうでなければ、ガードの付いた腕と同じく、網羅の判定に数えず、下の腕を覆わない（6.5）。展開できない const がパターンの入れ子の位置にあるとき（`Some(LIMIT)`）も、腕全体をガード付きの腕として扱う。束縛のパターンには書けない（E0317）。
- 汎化した const（`const EMPTY = []`）も、0.20 では型が実行時に消えるので、覚える値は1つである。Trait の制約の付いた const を許すかは 0.21 で決める。

### 5.7 型引数

- 型引数は `[A, B]` や `[Key, Value]` で宣言し、`List[Int]`、`Map[String, List[User]]` のように適用する。
- 制約は `[A: Ord]` と書く（10章）。
- 型引数に型構成子そのものを渡すことはできない（高カインド型なし）。

## 6. 関数と式

呼び出しの形は `名前(引数)` の1種類で、関数も構成子も同じ規則に従う。すべての構文要素は式であり、文は束縛だけである。

### 6.1 関数の宣言

```emel
fn add(x: Int, y: Int) -> Int {
  x + y
}

fn map[A, B](xs: List[A], f: fn(A) -> B) -> List[B] { ... }

pub fn find(id: Int) -> User fails NotFound use Users { ... }
```

- トップレベルの fn では、引数の型を書く。無名関数では省略できる。戻り値の型、`fails`、`use` は省略できる。省略時の意味は 7.4 と 9.3 に定める。
- 本体はブロックで、最後の式の値が戻り値になる。`return` はない。
- 無名関数は `fn(x) { x + 1 }` の1形式だけで、短縮記法はない。引数の型は省略できる。

- トップレベルの fn と、フィールドのある構成子は、呼ばずに名前を書くと関数の値になる（`List.map(xs, Some)`）。

### 6.2 引数とラベル

仮引数の名前が、そのままラベルになる。

```emel
fn connect(host: String, port: Int) { ... }

connect("localhost", 5432)
connect("localhost", port: 5432)
connect(host: "localhost", port: 5432)
```

- 位置引数を先に、名前付き引数を後に書く。
- 変数名とラベルが同じときは、`NotFound(id:)` と省略できる。パターンでも同じで、`User(name:)` は `name` を束縛する。
- 名前付きフィールドを持つ構成子も同じ規則で、`Circle(1.0)` と `Circle(radius: 1.0)` のどちらでも書ける。
- 仮引数名は公開 API の一部であり、改名は破壊的変更になる。
- 名前付き引数で呼べるのは、fn と構成子を名前で指して呼ぶとき、および能力の値の操作を呼ぶとき（`log.info(msg: "hi")`。ラベルはエフェクトの操作の宣言の仮引数名）だけである。局所変数やラムダなどの関数値は仮引数の名前を持たない（関数型 `fn(A) -> B` に名前がない）ので、位置引数でだけ呼べる（E0306）。

### 6.3 ブロックと束縛

```emel
count = 0
count = count + 1            # 同名での束縛し直し
(evens, odds) = List.partition(xs, is_even)
pairs: List[(String, Int)] = List.zip(names, scores)
```

- 束縛は `パターン = 式` と書く。宣言のキーワードはない。
- 変数は不変で、再代入はない。同じ名前で束縛し直すと、以降は新しい束縛が見える。
- 束縛のパターンは、必ず照合に成功するものに限る。失敗しうる照合は match で書く。検査は網羅性の判定（6.5）と同じで、エラーには足りないパターンの例を示す。
- ブロック `{ ... }` の値は、最後の式の値である。
- ブロックの中の束縛は汎化しない。多相になるのはトップレベルの関数と const だけである。

### 6.4 if

```emel
label = if count > 0 { "あり" } else { "なし" }

if !valid { fail Invalid(input:) }
```

- if は式である。条件の型は Bool に限り、条件を囲む括弧は要らない。
- 値として使うときは `else` が必須である。`else` のない if の型は `()` で、本体の型も `()` か `Never` でなければならない。
- 三項演算子はない。

### 6.5 match とパターン

```emel
shape match {
  Circle(radius:) if radius > 0.0 -> 3.14 * radius * radius
  Circle(_)                       -> 0.0
  Rect(w, h)                      -> w * h
  Empty                           -> 0.0
}
```

- match は後置で、`式 match { 腕 }` と書く。escape（7.3）と同じ形で、優先順位も同じ一番弱いところに置く（6.6）。パイプの結果で分けるときも、読む向きが左から右のまま変わらない。match は式なので、束縛の右辺にも書ける。

```emel
name = users |> List.find(fn(u) { u.id == id }) match {
  Some(u) -> u.name
  None -> "guest"
}

load(id) match {
  Some(user) -> user.name
  None -> "guest"
} escape {
  DbError(_) -> "unavailable"
}
```

- 前置（`match 式 { 腕 }`）は書けない。書くと、後置で書くよう助言を付けたエラーになる（E0142）。処理系は前置のまま読んで回復し、型の検査を続ける。
- パターンでは、数のリテラルの前に `-` を書ける（`-1`、`-0x10`、`-1.5`）。式の `-1` は単項マイナスとリテラルなので、これはパターンだけの規則である。`-` と数の間に空白を置いてもよい（fmt は詰める）。束縛の左辺にも書けるが、反駁可能なので E0317 になる。範囲の検査は `-` と数を1つの値として行う（Int の最小値 `-2147483648` を書ける）。`-0.0` は `==` で照合するので `0.0` と同じ値に合う。範囲のパターン（`1..10`）は持たない（網羅の判定が数の区間を扱う必要が出るため。ガードで書く）。
- 腕は上から順に試す。すべての場合を網羅していない match はエラーになる。
- ガード（`if 条件`）の付いた腕は、網羅性の判定では数えない。ガード付きの腕は、それより下の腕が冗長かどうかの判定でも、下の腕を覆わない。
- それより上の腕で全部覆われている腕は、冗長として警告する（W0301）。
- 網羅していないときは、足りないパターンの例を示す（`Rect(_, _)`、`[_, ..]`、`Some(None)`）。

| パターン | 形 | 意味 |
|---|---|---|
| ワイルドカード | `_` | 何にでも合い、束縛しない |
| 変数 | `x` | 何にでも合い、`x` に束縛する |
| リテラル | `0` `-1` `"a"` | その値と等しいとき合う。Float は `==`（10.6）で照合するので、`0.0` は `-0.0` にも合い、NaN の値のパターンはどの値にも合わない（冗長な腕の判定では NaN どうしを同じ値とみなす） |
| 定数 | `MAX_SIZE` | const の値と等しいとき合う |
| 構成子 | `Empty` `Rect(w, h)` `Circle(radius: r)` | その構成子で作られた値に合う |
| 残りを無視 | `User(name:, ..)` | 列挙していないフィールドを無視する |
| タプル | `(a, b)` | 要素ごとに照合する |
| リスト | `[]` `[x, ..rest]` `[x, ..]` | 空リスト、先頭と残り、先頭と（束縛しない）残り |

- 名前付きフィールドを持つ構成子のパターンでは、`..` を書かずにフィールドを省くとエラーになる。
- リストのパターンで、残りだけを書く形（`[..]`、`[..rest]`）は書けない。それぞれ `_`、`rest` と同じ意味なので不要である。
- escape（7.3）の腕は一部のエラーだけを受けてよいので、網羅は要求しない。冗長な腕の警告だけを行う。

### 6.6 演算子

優先順位は次のとおりとする。上ほど強く結合する。

| 順位 | 種類 | 演算子 | 結合 |
|---|---|---|---|
| 1 | 後置 | `f(x)` `x.name` | |
| 2 | 単項 | `!x` `-x` | |
| 3 | 乗除 | `*` `/` `%` | 左結合 |
| 4 | 加減 | `+` `-` | 左結合 |
| 5 | 比較 | `==` `!=` `<` `<=` `>` `>=` | 結合しない |
| 6 | 論理積 | `&&` | 左結合、短絡評価 |
| 7 | 論理和 | `\|\|` | 左結合、短絡評価 |
| 8 | パイプ | `\|>` | 左結合 |
| 9 | escape と match | `式 escape { ... }` `式 match { ... }` | 左結合 |

- 算術演算子は Int、Int64、Float にだけ使える。両辺は同じ型でなければならず、暗黙の変換はない。
- 算術演算子と単項マイナスのオペランドの型が、定義を推論し終えても決まらなければ Int とする。数値の型を抽象する型引数は持たない。
- ビット演算の演算子は持たない。core の関数（`Int.bit_and`、`Int.bit_or`、`Int.bit_xor`、`Int.bit_not`、`Int.shift_left`、`Int.shift_right`（符号を保つ）、`Int.shift_right_unsigned`。Int64 にも同じもの）で書く。`flags |> Int.bit_and(MASK)` のようにパイプで書ける。
- シフトの関数のシフト量は、Int64 の版でも Int である。シフト量が負なら defect になる。型の幅（32 か 64）以上なら全部のビットを押し出した値になり、`shift_left` と `shift_right_unsigned` は 0、`shift_right` は符号に応じて 0 か -1 になる（幅で剰余を取らない）。`shift_right_unsigned` の結果は符号付きの値として読む（`Int.shift_right_unsigned(-1, 0)` は -1）。
- `==` と `!=` は Eq、大小比較は Ord を満たす型に使える。
- 利用者が定義した型に演算子を定義することはできない。`Money.add(a, b)` のように関数で書く。
- 文字列の連結に `+` は使えない。補間（`"#{a}#{b}"`）か `String.concat` を使う。

### 6.7 パイプ

`x |> f(a)` は `f(x, a)` と同じである。左辺の値が、右辺の呼び出しの第1位置引数に入る。右辺が呼び出しでない場合、`x |> f` は `f(x)` である。

```emel
scores
  |> List.filter(is_valid)
  |> List.fold(from: 0, f: add)
```

### 6.8 繰り返し

- for や while はない。繰り返しは、再帰か、`List.map` や `List.fold` などの関数で書く。
- 自分自身への末尾呼び出しは、スタックを消費しないことを保証する。suspend な操作を含む関数でも同じである。
- 相互再帰の末尾呼び出しは保証しない。コンパイラは検出して警告する。

末尾位置は次のとおりとする。

- 関数の本体のブロックの最後の式
- 末尾位置にある if の両方の分岐、match の各腕の本体、ブロックの最後の式
- 末尾位置にある `&&` と `||` の右辺（`a && b` は `if a { b } else { False }`、`a || b` は `if a { True } else { b }` と同じ）

次の中は末尾位置ではない。

- 無名関数の本体（自分自身への呼び出しにならない）
- `escape` の対象の式（escape の腕が後に走りうる）
- `with` の本体（ハンドラの release が後に走る）

escape の対象と with の本体の中にある、末尾呼び出しに見える自分自身への呼び出しは、linter が「保証されない」と警告する。

## 7. エラー

エラー処理の道具は `fail` と `escape` の2つだけである。失敗は何も書かなければ呼び出し元へ伝わり、escape で受けると通常の値に戻る。

### 7.1 error の宣言

```emel
error NotFound(id: Int)
error Unauthorized
```

- エラーはタグ名で識別する。フィールドは値であり、識別には関わらない。`NotFound(id: 1)` と `NotFound(id: 2)` は同じエラーである。
- 関数が起こしうるエラーは、タグの集合 E として型に現れる。集合なので、順序と重複は意味を持たない。
- エラーの集合は、言語の中で union が現れる唯一の場所である。
- error 宣言は、type と同じく、同じ名前の型と構成子を定義する。`NotFound(id: 1)` は型 `NotFound` の普通の値で、変数に入れても、関数に渡しても、データ構造に入れてもよい。
- 値として扱えるのは1つのエラーの型だけである。「NotFound か DbError のどちらか」という値の型は作れない。

### 7.2 fail

```emel
fail NotFound(id:)
```

`fail e` は、現在の計算をエラー `e` で終わらせる。`e` の型はエラーの型でなければならない。式の型は Never で、`e` の型のタグが E に加わる。

型引数が値の型（`err: E`）とエラーの集合（`fails E`）の両方に使われたとき、その型引数は1つのエラーの型として推論する。`e` の型がまだ決まらない型変数のときも同じで、`fn raise(err) { fail err }` の型は `∀ E, A. fn(E) -> A fails E` になる。エラーでない型を `fail` に渡したとき、また1つのエラーの型の型引数をエラーでない型に具体化したときはエラーになる。

```emel
fn or_fail[A, E](opt: Option[A], err: E) -> A fails E {
  opt match {
    Some(a) -> a
    None    -> fail err
  }
}

user = users.find(id) |> Option.or_fail(NotFound(id:))   # E = NotFound
```

### 7.3 escape

```emel
# 復帰: 通常の値に戻す
user = find_user(id) escape {
  NotFound(_) -> guest_user()
}

# 一部だけ受ける: DbError は呼び出し元へ伝わる
data = load(id) escape {
  NotFound(_) -> default_data()
}

# 別のエラーに変える
data = load(id) escape {
  DbError(message:) -> fail Unavailable(reason: message)
}

# 値として扱う
found = Some(find_user(id)) escape {
  NotFound(_) -> None
}
```

- `式 escape { 腕 }` は、式の評価中に起きたエラーを受ける。腕のパターンはエラーの構成子でなければならない（`_` や変数は書けない）。腕の網羅は求めない。
- 元の式から起きないエラーを受ける腕は警告になる。元の式の E に中身の分からない集合変数がないときだけ確かめる。
- 腕の結果は、元の式と同じ型か、Never（`fail` や `panic`）でなければならない。元の式の型が Never のときは、腕の共通の型が全体の型になる。
- 腕で受けたタグは E から消える。受けていないタグは、そのまま伝わる。
- タグが消えるのは、そのエラーのガードのない腕を合わせて、そのエラーの値をすべて受けるとき（`NotFound(_)`。`Flag(on: True)` と `Flag(on: False)` の2本でもよい）だけである。一部の値しか受けない腕（`NotFound(id: 1)`、ガード付きの腕）だけなら、タグは E に残り、腕に合わなかった値はエラーのまま呼び出し元へ伝わる。
- 腕の中で起きたエラーは E に加わる。
- 式の E に、中身の分からない集合変数（集合の型引数 `E`、引数の関数型の見えない集合変数、1つのエラーの型の型引数、汎化する定義の集合変数）が含まれるとき、escape はその変数から何も消さない。同じ関数の中で推論中の集合（局所の関数の E など）からは、正確に消える。腕は実行時にはそのタグを受けるが、型の上では変数が残る。
- 型の上でも正確に消したいときは、受けたいタグを関数型に書き出す（`fails Timeout | E`、7.4）。書き出したタグは集合変数の外にあるので、escape で消える。

```emel
# f の E は見えない集合変数 ε。escape しても型は ε のまま（Timeout が残りうる）
fn retry[A](f: fn() -> A) -> A {
  f() escape { Timeout(_) -> f() }
}

# Timeout を書き出すと、1回目の呼び出しの Timeout は型からも消える
fn retry[A, E](f: fn() -> A fails Timeout | E) -> A fails Timeout | E {
  f() escape { Timeout(_) -> f() }    # escape の E は E、2回目の f() で Timeout | E
}
```

- 呼ぶ側では集合が決まるので、日常のコードの escape はいつも正確である。差が出るのは、関数を受け取る汎用の関数の中だけである。

### 7.4 fails の注釈規則

関数の宣言では、戻り値の書き方がエラーの扱いを決める。

| 書き方 | 意味 |
|---|---|
| 戻り値の型を省略 | E を推論する。エラーはそのまま伝わる |
| `-> T` | エラーなしを強制する。本体に未処理のエラーがあればエラーになる |
| `-> T fails NotFound` | エラーがちょうどこの集合であることを強制する |

複数のエラーは、縦棒で区切って並べる。エラーのタグと、エラーの集合を表す型引数を混ぜてよい。

```emel
fn load(id: Int) -> User fails NotFound | DbError { ... }
fn retry[A, E](f: fn() -> A fails Timeout | E) -> A fails Timeout | E { ... }
```

`Timeout | E` は、タグ Timeout と集合変数 E の和である。引数の関数型にこう書くと、渡された関数のエラーのうち Timeout 以外が E になる。Timeout を起こさない関数を渡してもよい。

引数の位置に書く関数型では、省略の意味が異なる。`fn(A) -> B` は「何を失敗してもよく、そのエラーは呼び出し元に伝わる」であり、失敗しない関数に限るときは `fails {}` と書く（9.2）。

戻り値の型を書いた関数の E は、書いた fails 節に、引数の関数を呼んだときのエラー（引数の関数型の見えない集合変数）を足したものである。見えない集合変数は書けないので、`-> T` でも引数の関数のエラーは伝わる。

```emel
fn twice(f: fn() -> Int) -> Int { f() + f() }   # E は f のエラー。-> Int でもエラーにならない
```

引数の関数が受け取る関数（`f: fn(fn() -> A) -> B` の内側）の見えない集合変数は、本体から見ると中身が分からないので、そこへ失敗する関数を渡すとエラーになる。

### 7.5 defect

defect は、プログラムの誤りや回復できない異常を表す。型には現れず、escape では受けられない。

| 発生源 | 例 | メッセージの例 |
|---|---|---|
| `panic(message)` | 到達しないはずの分岐 | message そのもの。`todo()` は `not yet implemented` |
| `assert` の失敗 | テストでの検証 | `assertion failed: ...`（13.2） |
| 整数のゼロ除算 | `1 / 0` | `division by zero` |
| 外部関数が投げた例外 | JS の throw | `TypeError: bad`（12.5） |
| Float から Int への変換の失敗 | `Float.floor(NaN)` | `cannot convert NaN to Int` |
| 負のシフト量 | `Int.shift_left(1, -1)` | `negative shift amount: -1` |
| match の腕に合わない値 | 網羅の検査をすり抜けたとき | `unreachable: no match arm matched` |

メッセージの文面は、付録 A の診断と同じく仕様の一部ではなく、改善のために変えてよい。

- defect が起きたときも、ハンドラの release は実行される（14章）。
- defect を観測できるのは境界だけである。境界とは、プログラムの最上位、テストランナー、`Fiber.attempt`（11.5）を指す。
- 期待されるエラーを defect に変えるには、escape の腕で panic を呼ぶ。逆方向の変換は境界でしかできない。
- `emela run` は、プログラムの最上位に達した defect を標準エラーに `defect: <message>` と1行出し、終了コード 101 で終わる。

### 7.6 持たないもの

Result 型、`?` 演算子、try / catch、mapError は持たない。Option から失敗への変換は、`Option.or_fail(opt, NotFound(id:))` のような普通の関数で書く。

## 8. エフェクト

副作用は、effect で宣言した操作を、use で取り出した値を通して呼ぶことでしか起こせない。実装は handler が持ち、with で供給する。

### 8.1 effect

```emel
effect Logger {
  fn info(msg: String) -> ()
}

effect Clock {
  suspend fn sleep(ms: Int) -> ()
  fn now() -> Instant
}
```

| 操作の種類 | 意味 |
|---|---|
| `fn` | ハンドラが値を返すと、呼び出し元はすぐ続きを実行する |
| `suspend fn` | 呼び出し元が中断しうる。続きがいつ実行されるかはハンドラが決める |

- 操作には、引数と戻り値の型を書く。
- 操作が失敗しうる場合は、宣言に `fails` を書く。書かなければ、その操作は失敗しない。ハンドラは宣言された範囲を超えて失敗できない。これにより、ハンドラを差し替えても、呼び出し側の E は変わらない。
- エフェクトは型引数を持てる（`effect State[S]`）。型引数はふつうの型に限る。型引数の違うエフェクトは別のエフェクトとして扱い、R の中で `State[Int]` と `State[String]` は区別される。`use State[Int]` のように、型引数は省略できない。 型引数を書かなければエラー（E0423）、数が違えばエラー（E0304）になる。操作の引数と戻り値の関数型の fails か use にだけ書いた型引数は集合になるのでエラー（E0424）だが、操作自身の `fails S` は fn と同じく1つのエラーの型（7.2）として通す。エフェクトの型引数の中の関数型で fails と use を省略すれば空である（9.2 の宣言の中と同じ）。ただし組み込みのエフェクト（同梱のソースで `@intrinsic` を付けた effect。Scope、11.2）は、集合の型引数と、操作自身の型引数（`fn fork[A](...)`）を持てる。利用者のエフェクトの操作に型引数を書くとエラーになる（E0426）。組み込みのエフェクトは利用者がハンドラを書けないので、多相な操作を実装するハンドラの検査は要らない。`use State[S]` の型引数には、囲む fn の型引数を書ける。Immediate はエフェクトの定義で決まり、型引数には左右されない。
- R の中で同じエフェクトかどうかは、型引数まで比べる。型引数がまだ決まっていなければ単一化して比べるので、`State.run([], fn() { with TestConsole { greet(1) } })` の状態の型は、body の R の `State[List[String]]` から決まる。with の「同じエフェクトは後ろが優先」と layer の重複（E0421）も、型引数まで同じものだけを数える。R に残った型変数は汎化する（`fn peek() { modify(fn(x) { x }) }` は `∀ A. fn() -> A use State[A]`）。
- 型引数のあるエフェクトを実装するハンドラは、具体的な型を書く（`handler Fixed implements State[Int]`）。どの型でも実装する汎用のハンドラは持たない。
- 操作には `use` 節を書けない（17.3 の op_sig）。操作の実装が別のエフェクトを使うときは、ハンドラの依存（9.4 の依存(H)）として with の場所で満たす。これにより、ハンドラを差し替えても、呼び出し側の R は変わらない。呼ぶたびに別の能力を使わせたいときは、その能力を使うクロージャを操作の引数で渡す（エフェクトに効果の型引数が要る。9.2）。
- fn の操作（suspend fn でないもの）の実装の本体は、次のどちらかを満たさなければならない（E0417）。どちらもそれだけで本体が中断しないことを保証する。
  - 本体の R が Immediate である。その場で resume するハンドラの with の中で suspend fn の操作を呼ぶ本体（`fn now() { with InstantClock { (use Clock).sleep(1) } ... }`）はこちらで通る。
  - 本体が中断しうる呼び出しを含まない。
- 呼び出しが中断しうるかは次で決める。
  - 操作の呼び出し（`clock.now()`、`(use Clock).now()`）は、その操作の宣言で決める。`suspend fn` なら中断しうる。
  - 関数と関数の値の呼び出しは、呼ばれる側の型の R で決める。R が Immediate でなければ中断しうる。能力を捕まえたクロージャ（`f = fn() { clock.now() }`）や、値として取り出した操作（`g = clock.now`）を呼ぶのも関数の値の呼び出しである。
  - `@external suspend fn` の呼び出しは中断しうる。
- 中断しうる呼び出しを含まなければ、本体の R は制限しない。`fn now() { (use Clock).now() }` の R には Clock が載り、ハンドラの依存になる。外側の Clock の `now` と、内側の `with InstantClock` の中の `sleep` を同じ本体に混ぜると、どちらも満たさず E0417 になる。これを通すには、呼び出しごとに最も内側でそのエフェクトを供給する with まで見る必要があり、規則が重くなるので見送る。関数を挟むと、その関数が fn の操作しか呼ばなくても中断しうるとみなす（`fn stamp() -> Instant use { Clock }` を呼ぶ `fn now() { stamp() }` は E0417）。関数の本体から中断しないことは推論しない。どのハンドラの fn の操作の実装も同じ規則で縛られるので、fn の操作の呼び出しはどのハンドラに当たっても中断しない。
- 待つ処理（`@external suspend fn` を待つ、suspend な操作を呼ぶ）を含む操作は、エフェクトの側で suspend fn と宣言する。呼ぶ側はエフェクトの宣言からしか中断するかを知れないためである。中断するかどうかの印が付くのはエフェクトの操作の宣言だけで、関数のシグネチャ（`use Http`）と呼び出しには付かない。

### 8.2 use

```emel
fn greet(id: Int) {
  log   = use Logger
  users = use Users

  user = users.find(id) |> Option.or_fail(NotFound(id:))
  log.info("hello #{user.name}")

  (use Clock).sleep(1000)
  user
}
```

- `use X` は式で、エフェクト X の能力を表す値を返す。関数の中のどこにでも書ける。
- 操作は、能力の値を通して `log.info(...)` の形でしか呼べない。エフェクト名で直接呼ぶ形（`Logger.info(...)`）はない。
- 能力の値の操作は、呼ばずに `log.info` と書くと関数の値になる。能力の値はその位置で評価され、関数の値の型には能力のエフェクトが載る（能力を捕まえたクロージャと同じ）。
- 能力の値の操作を呼ぶと、R にそのエフェクトが載り、E に操作の `fails` が載る。能力の値を捕まえたクロージャの型にもそのエフェクトが載る（下の `copy` の例）。
- 能力の値を引数に渡す、データ構造（構成子、リスト、タプル）に入れる、関数から返す、はどれもエラーになる。値の最上位の型だけを見る。
- `use X` を含む関数の効果の集合 R には、X が載る。分岐の中に書いても、関数全体の R に載る。
- 呼び出し側に、副作用や中断を示す印（await や `!`）は付けない。suspend な操作も、普通の呼び出しと同じ形で書く。
- 能力の値の型は、ソースに書けない。能力の値は、関数の引数として渡すことも、データ構造に入れることも、返すこともできない。
- 特定のハンドラの能力を関数に使わせたいときは、その能力を捕まえたクロージャを渡す。クロージャを with の中で下の関数へ渡すのはよい（8.6）。

```emel
fn copy(read: fn() -> Rows use { Db }, write: fn(Rows) -> () use { Db }) {
  write(read())
}

with PrimaryDb {
  primary = use Db
  with ReplicaDb {
    replica = use Db
    copy(fn() { replica.query("...") }, fn(rows) { primary.execute(rows) })
  }
}
```

能力の値を引数として直接渡す構文（`from: use Db` のような能力の型）は、必要になれば後から足せる。足す方向の変更なので、既存のコードは壊れない。

### 8.3 with

```emel
with ConsoleLogger { greet(1) }

with AppTest, FixedClock { greet(1) }
```

- `with H { 本体 }` は、本体の中で H が実装するエフェクトを供給する。値は本体の値である。
- 供給したエフェクトは、本体の R から消える。ただし escape と同じく、中身の分からない効果の集合（引数の関数型の見えない集合など）からは消さない。`fn run(f: fn() -> ()) { with ConsoleLogger { f() } }` の R は f の効果の集合のまま残る（7.3）。
- 型の上でも正確に消したいときは、供給するエフェクトを関数型に書き出す（`use { Logger, R }`。エラーの `fails Timeout | E` と同じ）。書き出したエフェクトは集合変数の外にあるので、with で消える。

```emel
fn run[R](f: fn() -> () use { Logger, R }) -> () use R {
  with ConsoleLogger { f() }      # R は R だけ。Logger は消える
}
```
- 同じ with に並べたハンドラの依存は、同じ with の別のエフェクトを供給するハンドラが満たしてよい。自分と同じエフェクトへの依存は外側が満たす。同じ with のハンドラの依存が循環すればエラーになる。
- H にはハンドラか layer を書く。カンマで並べた場合、同じエフェクトについては後ろが優先される。layer は中のハンドラに展開してから並べる。後ろのハンドラに上書きされた前のハンドラは、初期化もしない（init の E も with の E に入らない）。
- `use X` は、書いた位置から見て最も内側の with が供給するハンドラを指す。同じ関数に該当する with がなければ、呼び出し元から渡されたものを指す。
- 無名関数の中の `use X` は、無名関数を囲む with（同じトップレベルの関数の中のもの）を先に見る。なければ、無名関数を呼んだ側から渡されたものを指す。無名関数の R は無名関数の型に閉じ込められ（9.4）、囲む関数の R には載らないためである。
- 外側で取り出した能力の値は、内側の with で同じエフェクトが上書きされても、外側のハンドラを指し続ける。
- main の R は、Async を除いて空でなければならない。main はエントリのモジュールの `main` という名前の fn である。エントリに main がなければ、`emela run` はエラーになる（E0230）。`main` という名前でも fn でないもの（const など）は main と数えない。`emela build` は main がなくても出力してよい。use 節を書いていても空を求める。const の値の R も空である。

```emel
with PrimaryDb {
  primary = use Db
  with ReplicaDb {
    replica = use Db
    replica.query("...")      # ReplicaDb
    primary.execute("...")    # PrimaryDb
  }
}
```

### 8.4 handler

```emel
handler ConsoleLogger implements Logger {
  fn info(msg) { console_log(msg) }
}

handler PostgresUsers(conn: Connection) implements Users {
  init {
    config = use Config
    PostgresUsers(conn: pg_connect(config.db_url()))
  }

  release {
    pg_close(self.conn)
  }

  fn find(id) { ... self.conn ... }
}

handler SystemClock implements Clock {
  suspend fn sleep(ms, resume) {
    set_timeout(ms, fn() { resume(()) })
  }
  fn now() { date_now() }
}
```

- ハンドラは宣言であり、1つのエフェクトのすべての操作を、それぞれちょうど1回実装する。操作の引数と戻り値の型は、エフェクトの宣言から決まるので書かない。引数の数は宣言と同じでなければならない。
- 操作の本体の E は、操作の宣言の `fails` に含まれなければならない。依存(H)（9.4）は、操作の本体の R の和である。
- 状態を持つハンドラは、名前の後ろにフィールドを宣言する。フィールドは `self.conn` のように `self` を通して参照する。
- `init` は with に入るときに1回実行され、ハンドラの値を返す。フィールドがあるハンドラでは必須である（E0419）。フィールドのないハンドラにも init と release を書ける。フィールドのないハンドラの init は、括弧のないハンドラなら値 `ConsoleLogger` を、`handler H()` なら `H()` を返す。init の中では self は使えない（値を作る前なので）。状態を持たないハンドラの操作の中の self は値を持たず、型は `()` である。
- ハンドラの値（`PostgresUsers(conn: ...)`）を作れるのは、そのハンドラの init の中だけである。外で作れると init と release を飛ばせてしまうためである。 外で作るとエラーになる（E0418）。init の中の無名関数の中は init の中とみなす。部分更新（`H(n: 1, ..self)`）も値を作るので、操作の本体の中では書けない。構成子のパターンは値を作らないので、どこに書いてもよい。
- `init` の中の `use` が、そのハンドラの依存である。設定を外から渡すときは、Config のようなエフェクトを init で use する。ハンドラ自体は引数を取らない。
- `release` は with を抜けるときに1回実行される。正常終了、エラー、defect、中断のどの場合でも実行される。
- release の E は空でなければならない（E0420）。失敗しうる後始末は、release の中で escape するか panic で defect にする。release の値は捨てるので、型は問わない。release の中で suspend な操作を呼んでよい（中断はされない。11.4）。
- suspend fn の実装は、最後の引数として `resume` を受け取る。`resume(v)` を呼ぶと、中断していた呼び出し元が再開し、操作の戻り値が `v` になる。
- suspend fn の実装の引数は、操作の引数に resume を1つ足した数である。最後の引数が resume で、名前は問わない。resume の型は `fn(T) -> () fails {} use {}`（T は操作の戻り値の型）である。実装の本体の値は捨てるので、本体の型は `()` でなければならない。
- `resume` を呼べるのは高々1回である。その場で呼んでも、コールバックの中で後から呼んでもよい。

### 8.5 layer

```emel
layer AppLive {
  EnvConfig
  ConsoleLogger
  SystemClock
  PostgresUsers      # init で Config を use している
}

fn main() {
  with AppLive { run_server() }
}
```

- layer はハンドラの束に名前を付ける宣言である。中にはハンドラか、別の layer を並べる。
- 並び順は意味を持たない。コンパイラが依存(H)（init、release、操作の本体の R。9.4）から初期化の順序を決め、release はその逆順で実行する。操作の本体や release が使うエフェクトも、先に初期化されたハンドラが供給する（14.2）ためである。依存から順が決まらないところは、書いた順を保つ。
- 同じエフェクトを2つのハンドラが供給する layer はエラー（E0421）、互いを含む layer もエラー（E0422）になる。誤りは layer の宣言で1回だけ報告する。
- 依存が循環する、同じエフェクトを2つのハンドラが供給する、のどちらもエラーになる。
- layer の中で満たされない依存はエラーにせず、with の R に残る（8.3 の依存(H) と同じ）。main とテストでは R が空でなければならないので、そこでエラーになる。一部の依存を外から与える layer を書ける。
- 一部だけ差し替えるときは、`with AppTest, FixedClock { ... }` と後ろに並べる。

### 8.6 能力の持ち出しの禁止

能力の値と、それを捕まえたクロージャは、供給元の with の外へ出せない。

```emel
fn make_greeter() {
  with ConsoleLogger {
    log = use Logger
    fn() { log.info("hi") }    # エラー: log を抱えたまま with の外に出る
  }
}
```

- コンパイラは、値がどの能力を抱えているかを型とともに追跡する（capture set）。クロージャが別のクロージャやデータ構造に入ると、その情報も引き継がれる。
- with の本体の値が、その with が供給した能力を抱えていればエラーになる。
- capture set の検査が入るまで（0.22）は、実行時に検査する。release 済みのハンドラの操作を呼ぶと defect になる（`handler PostgresUsers was used after release`）。この検査は、フィールド、init、release のどれかを持つハンドラにだけ掛かる。状態を持たないハンドラは、with の外へ持ち出しても今までどおり動く。
- capture set は推論され、ソースには書かない。利用者が目にするのはエラーメッセージだけである。
- with の中で使い終わるクロージャ（`List.map(names, fn(n) { log.info(n) })`）は問題ない。
- Scope の能力、fiber のハンドル、Deferred の持ち出しも同じ考え方で防ぐ。0.20 と 0.22 で検査できる範囲は 11.8 の表にまとめる。

### 8.7 Async

- Async は組み込みのエフェクトで、「後から再開される」ことを表す。供給できるのはランタイムだけで、利用者はハンドラを書けない。
- `resume` を後から呼ぶ手段（外部関数のコールバック、`@external suspend fn`、fork）は Async を要求する。したがって SystemClock は Async に依存し、`with SystemClock { ... }` の R には Async が残る。
- コンパイラは、suspend fn の実装の本体で `resume` を直接呼ぶ（`resume(v)`）以外の使い方をしたとき、resume を後から呼びうるとみなして、ハンドラの依存に Async を足す。直接呼ぶ以外の使い方とは、変数に入れる、クロージャで捕まえる、引数に渡す、などである。`@external suspend fn` を呼んだときも Async を足す。この判定は構文だけで行い、安全側に倒す。
- その場で resume するハンドラ（テスト用の InstantClock など）は Async を要求しない。`with InstantClock { ... }` は実際に中断せず、型の上でも Async が現れない。
- 「中断しない」ことを要求する制約 Immediate は 9.5 に定める。

### 8.8 State

可変な状態は、同梱の core のエフェクト State で表す。状態の置き場所は `State.run` の枠であり、値そのものは不変のままである。

```emel
pub effect State[S] {
  fn get() -> S
  fn set(value: S) -> ()
  fn update(f: fn(S) -> S) -> ()
}

pub fn run[S, A, E, R](
  initial: S,
  body: fn() -> A fails E use { State[S], R },
) -> (A, S) fails E use R
```

- `State.run(initial, body)` は、初期値 initial の状態を供給して body を実行し、body の値と最後の状態の組を返す。body の R から State[S] が消えるので、外からは純粋に見える。
- body が失敗したときは、状態を捨ててエラーだけが伝わる。失敗の時点の状態も欲しいときは、body の中で escape して値に変える。
- body が中断しても、状態は再開の後に引き継がれる。
- 同梱の TestConsole の `print_line` は、行を書いた順に状態の末尾へ足し、`print_error_line` は捨てる。TestClock は仮の時刻で動く。`sleep` は本当に待ち、どの fiber も進めず、ホストの処理も待っていないときに、一番早く起きる予定の時刻まで状態の時刻を進めてその fiber を起こす。起きる順は予定の時刻の早い順で、同じ時刻なら sleep を呼んだ順である。fiber が1本なら、sleep で時刻が進んでそのまま続くのと同じ結果になる。TestClock は Async に依存するので、Immediate を求める場所では使えない。負の `ms` は 0 とみなす（SystemClock も同じ）。
- update に渡す関数は、操作の宣言の中の関数型なので純粋である（9.2）。そのため update は一息に実行され、fiber の間で共有しても途中の状態は見えない（11.1）。
- 同じ型の状態を2つ持つときは、別の型で包んで区別する（`State[Hits]` と `State[Misses]`）。
- 状態を使うハンドラは、State に依存するハンドラとして書く。テスト用のハンドラはこの形になる。

```emel
handler TestConsole implements Console {
  fn print_line(text) {
    st = use State[List[String]]
    st.set(List.append(st.get(), [text]))
  }
  fn print_error_line(text) { () }
}

@test
fn greets() {
  (_, lines) = State.run([], fn() { with TestConsole { greet(1) } })
  assert lines == ["Hello, alice!"]
}
```

## 9. 型と効果の体系

すべての式は、値の型 T、エラーの集合 E、効果の集合 R の3つ組を持つ。T は Hindley-Milner 方式で推論し、E と R は集合の和と差で求める。

### 9.1 判定の形

```
Γ ⊢ e : T ! E ; R
```

- T: 値の型。
- E: エラーのタグの集合。空なら失敗しない。
- R: エフェクトの集合。空なら環境に依存しない。
- E と R がともに空の関数を、純粋な関数と呼ぶ。

### 9.2 関数型

```
fn(A, B) -> C fails E use R
```

引数の位置に書く関数型では、節の省略は「何でもよく、呼び出し元に伝わる」を意味する。

| 書き方 | 受け取れる関数 |
|---|---|
| `fn(A) -> B` | どんなエラーと効果を持っていてもよい。それらは、受け取った関数を呼ぶ側の E と R に加わる |
| `fn(A) -> B fails {}` | 失敗しない関数だけ |
| `fn(A) -> B use {}` | 効果を持たない関数だけ |
| `fn(A) -> B fails {} use {}` | 純粋な関数だけ |
| `fn(A) -> B use R`（R は型引数） | 効果に名前を付け、制約を掛けられる（9.5） |

この規則により、`List.map(xs, f)` は f のエラーと効果をそのまま引き継ぐ。純粋版と効果版を2つ用意する必要はない。

関数型の節を省略したときの意味は、書いた位置で決まる。

| 位置 | 省略したときの意味 |
|---|---|
| 引数の型の中（どの深さでも。`f: fn(A) -> B`、`fs: List[fn(A) -> B]`） | 何でもよい。省略した節ごとに、見えない集合変数を置く。そのエラーと効果は、関数を呼んだ側に加わる |
| 戻り値の型、束縛の型注釈、無名関数の引数の型注釈 | 本体から推論する。引数の見えない集合変数を参照してよい（無名関数は汎化しないので、見えない集合変数を置けない） |
| 宣言の中（type・enum・error・handler のフィールド、エフェクトの操作、Trait の関数、const） | 空。失敗せず、効果を持たない関数だけ |

宣言の中で効果のある関数を持つときは、型引数で明示する。

```emel
type Handler[E, R](run: fn(Request) -> Response fails E use R)

fn compose[A, B, C](f: fn(A) -> B, g: fn(B) -> C) -> fn(A) -> C {
  fn(x) { g(f(x)) }      # 戻り値の関数は f と g のエラーと効果を持つと推論される
}
```

- 宣言の中を空にするのは、型の名前に現れない集合変数を作らないためである。`Handler` が効果を持ちうることは、`Handler[E, R]` と型引数に現れる。
- 型引数がふつうの型か、エラーの集合か、効果の集合かは、使われた位置（`fails E`、`use R`）から推論する。種を書く構文は持たない。
- 名前付き型の集合の型引数には、集合を渡せる。書き方は fails 節（`A | B`）と use 節（`{ A, B }`）にそろえる。`Handler[NotFound | Timeout, { Db, Log }]`、`Handler[{}, {}]`、`Handler[E | Timeout, { R, Log }]`。
- 要素が1つなら囲まずに書ける（`Handler[NotFound, Db]`）。構文の上では型として読む。空の `{}` はエラーの集合の位置にも書ける（`fails {}` と同じ）。
- どの型引数が集合を受けるかは文法では決めず、型検査で確かめる。違う種類の集合や集合でない要素は E0323、集合でない型引数の位置の集合（`List[{}]`）は E0324 になる。

### 9.3 宣言での注釈と推論

| 部分 | 省略したとき | 書いたとき |
|---|---|---|
| 戻り値の型 | T と E を推論する | T を検査し、E は fails 節のとおりであることを強制する（7.4） |
| fails 節 | 戻り値の型があれば「エラーなし」 | ちょうどその集合であることを強制する |
| use 節 | 常に R を推論する（戻り値の型を書いていても） | ちょうどその集合であることを強制する。引数の関数を呼んだときの効果（見えない集合変数）は足される（7.4 の E と同じ） |

E と R は普段ソースに現れず、LSP が表示する。

型を推論する定義（戻り値の型を書いていない fn、戻り値の型の中に節を省いた関数型がある fn、use 節のない fn、型を書いていない const）は、互いに参照し合うまとまりごとに、参照される側から推論する。

- まとまりの中では単相の型で参照し、まとまりを推論し終えてから汎化する。まとまりの中で同じ定義を別の型に使うと型が合わない（多相再帰は持たない）。use 節のない fn は T と E が宣言のとおりで、R についてだけこの規則に従う。
- 汎化するとき、引数の関数型の E と R にあって下界も上界もない集合変数は、集合の型引数として量化する（`fn caller() { fn(g) { g() } }` は `∀ A, E. fn() -> fn(fn() -> A fails E) -> A fails E`）。それ以外の集合変数は、制約を満たす最小の集合に決める。

型の表示は次のとおりとする。

- 汎化した型引数は現れた順に `A`、`B`、…、`Z`、その後は `T26`、`T27`、… と名付け、制約は `∀ A: Ord + Show, B. T` の形で量化子に書く。
- 汎化した集合の型引数は `E`、`E1`、…（エラー）、`R`、`R1`、…（効果）と名付け、ふつうの型引数の後ろに並べる。引数の型の中の見えない集合は、引数の名前から `E(f)`、`R(f)` と表示し、同じ引数の2つ目以降は `E(f, 2)` とする。
- 空の E と R は省く。ただし関数型の引数の型の中では、省くと「何でもよい」と読めるので `fails {}`、`use {}` と書く。
- 効果の集合は、要素が1つならそのまま、2つ以上なら `{ A, B }`、空なら `{}` と書き、エフェクトを先、集合の型引数を後に並べる。`fails` 節の後に `use` 節を書く。
- 外側に節のある関数型の戻り値が関数型なら、戻り値を括弧で囲む（5.5）。能力の値の型は `use Logger` と表示する。
- 型の食い違いの診断には、まだ決まっていない集合変数を出さない。

### 9.4 型付け規則

各式の T、E、R は次のとおり決まる。部分式の E と R は、特記がないかぎり親の式に合流する。

| 式 | T | E | R |
|---|---|---|---|
| リテラル、変数、const | その型 | {} | {} |
| `[e1, ..., en]` / `[e1, ..., en, ..r]` | `List[T]`（各 ei が T、r が `List[T]`） | E1 ∪ … ∪ En ∪ Er | R1 ∪ … ∪ Rn ∪ Rr |
| `f(a)` | f の戻り値の型 | Ef ∪ Ea | Rf ∪ Ra |
| `C(fi: ei, ..r)` | C の型（型引数は ei と r の引き継ぐフィールドから決まる） | Ei ∪ Er | Ri ∪ Rr |
| `fail e` | Never | { e のタグ } | {} |
| `e escape { Ti -> ei }` | e の型と各腕の型の共通の型（Never は合流で消える） | (Ee ∖ {Ti}) ∪ Eei（Ti は腕が値をすべて受けるタグ。集合変数からは消さない。7.3） | Re ∪ Rei |
| `use X` | X の能力 | {} | { X } |
| `with H { e }` | e の型 | Ee ∪ (init の E) | (Re ∖ 供給(H)) ∪ 依存(H) |
| `fn(x) { e }` | `fn(..) -> T fails Ee use Re` | {} | {} |
| `if c { a } else { b }` | a と b の共通の型 | Ec ∪ Ea ∪ Eb | Rc ∪ Ra ∪ Rb |
| `e match { pi -> ei }` | 腕の共通の型 | Ee ∪ Eei | Re ∪ Rei |

- 無名関数は、本体の E と R を関数型の中に閉じ込める。それらが表に出るのは、関数を呼んだときである。
- Never は、どの型とも共通の型を作れる。if や match の一方の分岐が fail でも、全体の型はもう一方の型になる。
- フィールドの参照 `x.name` は、検査がそこに達した時点で x の型が名前付きの型に決まっていなければならない。決まっていなければエラーになる（E0314）。フィールドの名前から型を逆算することはしない（行多相は持たない）。
- 呼び出しの引数は仮引数の順に検査する。期待する型がある位置（引数、戻り値の型、束縛の型注釈）では、その型をブロックの最後の式、if と match の各分岐、リストの要素、無名関数の引数と本体へ先に渡す。`List.map(users, fn(u) { u.name })` では、u の型は先に検査した users から決まる。
- Never が他の型として扱われるのは、分岐の合流と、期待される型の位置に置かれたときの最上位だけである。`List[Never]` と `List[Int]` は一致しない。
- 供給(H) は H が実装するエフェクト、依存(H) は H の init と操作が要求するエフェクトである。
- 関数の値の E は、期待される関数型の E に含まれればよい。E の小さい関数を E の大きい関数として使える。分岐の合流やリストの要素で E の違う関数を並べると、E はそれらの和になる。包含の向きは、関数型の引数の中で逆になり、名前付きの型の型引数の中では両方向（一致）になる。
- E はタグと集合変数の和で表す。`∖ {Ti}` はタグの部分だけに作用し、集合変数はそのまま残す。集合変数が後で具体的な集合に決まっても、遡って消すことはしない（安全側に倒した近似）。

### 9.5 効果への制約

効果の集合は型引数として書けて、Trait と同じ構文で制約を掛けられる。

```emel
@external(js, "./dom.mjs", "onClick")
fn on_click[R: Immediate](id: String, handler: fn() -> () use R) -> ()
```

Immediate は、「中断せず、呼んだその場で完了する」ことを表す組み込みの制約である。コンパイラが宣言から自動で判定し、利用者が実装を書くことはない。

- エフェクトが Immediate であるのは、suspend fn を1つも持たず、Async でもないときである。
- 効果の集合が Immediate であるのは、要素がすべて Immediate のときである。空集合は Immediate である。

中断されると困る場所（外部関数に渡すコールバックなど）だけがこの制約を要求する。呼び出し側に印を付ける代わりに、型検査で禁止する。

- `R: Immediate` の制約は、その定義（fn か構成子）を参照したところで、具体化した集合について確かめる（E0416）。型の注釈（`Ticker[Clock]`）では確かめない。値は構成子からしか作れないためである。
- 引数の型の中の見えない効果の集合は Immediate の制約を持たないので、`R: Immediate` の引数には渡せない。制約が要るときは、名前を付けた型引数に `: Immediate` を書く。
- 外部関数の引数の型の中の見えない効果の集合は、Immediate の制約を持つ。外部関数の宣言の引数の関数型に書いた use 節は、Immediate でなければエラーになる。
- 型を推論する定義で、Immediate を要求する位置に渡した集合変数を汎化するときは、その型引数に Immediate の制約を付ける。
- エフェクトが Immediate かどうかは宣言だけで決まり、ハンドラには左右されない。fn の操作の実装は、本体の R が Immediate か、中断しうる呼び出しを含まない（8.1、E0417）ので、fn の操作の呼び出しはどのハンドラに当たっても中断せず、Immediate なエフェクトの操作が中断することはない。

### 9.6 持たないもの

部分型（9.4 の E の包含を除く）、一般の union 型と intersection 型、高カインド型、null、暗黙の型変換、動的型は持たない。

## 10. Trait と導出

Trait は型への制約であり、その型にどの関数が用意されているかを検査するための仕組みである。環境によって差し替わる振る舞いは Trait ではなく、エフェクトで書く。

### 10.1 trait

```emel
trait Show {
  fn show(self) -> String
}

trait Ord: Eq {                          # Eq を前提とする
  fn compare(self, other: Self) -> Ordering

  fn max(self, other: Self) -> Self {    # 既定の実装
    Ord.compare(self, other) match {
      Less -> other
      _    -> self
    }
  }
}

trait Decode {
  fn decode(json: Json) -> Self fails DecodeError
}
```

- `self` は第1引数で、型は `Self`（実装する型）である。
- `self` を取らない関数も書ける。どの型の実装を使うかは、期待される戻り値の型から決まる。
- 本体を持つ関数は既定の実装で、impl で省略できる。
- `trait A: B` は、A を実装する型が B も実装していることを要求する。

### 10.2 impl

```emel
impl Show for User {
  fn show(self) { "User(#{self.name})" }
}
```

- 引数と戻り値の型は Trait の宣言から決まるので、書かない。
- 1つの型と1つの Trait の組に対して、実装はプログラム全体で1つだけである。
- impl を書けるのは、その型を定義したモジュールか、その Trait を定義したモジュールだけである。
- どちらの持ち主でもない場合は、自分の型で包む。フィールドが1つの型は、実行時のコストを持たない。

```emel
type MyDate(inner: ThirdParty.Date)

impl Encode for MyDate { ... }
```

### 10.3 呼び出しと制約

```emel
Show.show(user)
user |> Show.show

fn largest[A: Ord](xs: List[A]) -> Option[A] { ... }
```

- Trait の関数は、`Trait名.関数名(値)` の形で呼ぶ。`user.show()` のようなメソッド呼び出しの構文はない。
- 制約は `[A: Ord]` と書く。複数の制約は `[A: Ord + Show]` と書く。上位の Trait も `trait A: B + C` と書く。
- `==` と `!=` は Eq、大小比較は Ord、文字列補間は Show の実装を使う。

### 10.4 Trait の関数のエラーと効果

- Trait の関数は、既定では純粋である。
- 宣言に `fails E` や `use R` を書けば、実装はその範囲でエラーと効果を持てる。実装は宣言された範囲を超えられない。
- したがって、`[A: Decode]` を使う関数の E と R は、Trait の宣言だけから決まる。

### 10.5 derive

```emel
type User(id: Int, name: String, email: Email)
  derive Eq, Show, Encode
```

- derive に並べた Trait の実装を、コンパイラが型の構造から生成する。生成されるのは普通の impl である。
- 各フィールドは、そのフィールドの型自身の実装を通る。Email に手書きの Encode があれば、それが使われる。
- 同じ型と Trait の組に、derive と手書きの impl の両方があればエラーになる。
- 導出した Ord は、バリアントを宣言の順に小さいとし、同じバリアントならフィールドを前から順に比べる。
- 導出できるのは、導出規則を持つ Trait だけである。

導出規則は、Trait の作者が次の3種類の型のどれかで書く。

| 導出の型 | 形 | 例 |
|---|---|---|
| 畳み込み | 値を1つ受け取り、フィールドごとの結果をまとめる | Show Encode Hash |
| 突き合わせ | 値を2つ受け取り、フィールドごとに比べる | Eq Ord |
| 組み立て | フィールドごとの生成結果から、値を作る | Decode Default |

導出規則の構文は次の形を想定しているが、確定していない（18章）。

```emel
trait Encode {
  fn encode(self) -> Json

  derive fold {
    record(name, fields) { Json.object(fields) }
    variant(name, tag, payload) {
      Json.object([("tag", Json.string(tag)), ("value", payload)])
    }
  }
}
```

### 10.6 組み込みの Trait

| Trait | 用途 | 利用者の impl |
|---|---|---|
| Eq | `==` `!=` | 書ける |
| Ord | `<` `<=` `>` `>=` | 書ける |
| Show | 文字列補間、dbg | 書ける |
| Hash | Map と Set のキー | 書ける |
| Immediate | 効果が中断しないこと（9.5） | 書けない（自動判定） |

関数型は Eq、Ord、Show、Hash を満たさない。

基本型の Show と Ord は次のとおりとする。

- Bool の Show は `True` / `False`（構成子の名前）。
- Float の Show は、最短で往復できる桁数で表す（JS の `Number.prototype.toString` と同じ規則）。整数値で有限のものには `.0` を付ける（`1.0`）。それ以外は `1e+21`、`-2.5e-8`、`Infinity`、`NaN` の形になる。WASM でも同じ文字列を出す。
- Int64 の Show に接尾辞は付けない。
- String の Ord は、Unicode のコードポイントの辞書順である（符号化の順を使わない。16.2）。
- Float の Eq は IEEE 754 の比較に従う。`NaN` は自分自身とも等しくなく、`0.0 == -0.0` である。
- Float の `-0.0` は `0.0` と表示する。

導出した Show は、値をソースの構築の形で表す（`Circle(radius: 1.0)`、`Rect(1.0, 2.0)`、`Empty`、`(1, "a")`、`[1, 2, 3]`、`()`）。

- 文字列補間で引用符を付けずに埋め込むのは、最上位の String だけである。リストや構成子の中の String と、dbg の String は `"` で囲む。
- 囲むときは `\"`、`\\`、`\n`、`\t`、`\r` と、`#{` の前の `\#` でエスケープする。それ以外の制御文字（U+0000〜U+001F、U+007F）は `\u{...}` と出す。

### 10.7 持たないもの

関連型、高カインド型への Trait、実行時の動的ディスパッチ、演算子に対応する Trait、利用者が定義する自動判定の Trait は持たない。

## 11. 並行性

並行処理の単位は fiber であり、fiber はスコープの中でしか起動できない。非同期や並行のための専用構文（async、await）はなく、すべて標準ライブラリの関数とエフェクトで表す。並行の道具は `Std.Fiber`（Scope、Fiber、Exit）、`Std.Cause`、`Std.Deferred` に置く。

土台（Fiber.scope、Scope の操作、join、await、interrupt、attempt、Deferred、Cause）は `@intrinsic` で、ランタイムが実装する。Emela の中からは書けない操作を要るためである。

- ほかの fiber を外から中断し、途中の with の release を巻き戻す（11.4）。Emela の継続は `resume(v)` で1回再開することしかできず、待っている継続を捨てて巻き戻す手段がない。
- 子の defect を受けて兄弟を止め、attempt で値に変える（11.5）。defect は境界でしか観測できない（7.5）。
- 子に Fiber.scope を呼んだ時点のハンドラを引き継ぐ（11.2）。ハンドラの表は Emela から見えない。
- 公平性の譲渡（11.1）と、外部の処理を止める AbortSignal（12.2）。

継続を捨てる手段や defect を受ける手段を言語に足せば土台も Emela で書けるが、継続は高々1回、defect は境界でしか見えない、という約束が崩れるので足さない。土台の上の組み合わせ関数（11.3）は純粋な Emela で書く。intrinsic は構文ではないので、専用の構文を持たないという上の方針とは矛盾しない。

### 11.1 fiber

- fiber は、1つのスレッドの上で協調的に切り替わる軽量な実行単位である。並列ではないので、速くなるのは待ちを重ねられるときだけである。待たない計算は、fiber に分けても合計の時間は変わらない（並列は 11.6）。
- 切り替えが起きるのは中断点だけである。中断点とは、Async を要求する suspend な操作の呼び出しと、ランタイムが公平性のために挟む譲渡である。
- 譲渡は、中断しうる呼び出し（8.1）の位置にだけ挟む。ランタイムは中断しうる呼び出しの回数を数え、一定の回数ごとに他の fiber とホストのコールバックに譲る。時間でなく回数で数えるので、切り替えの順序は実行のたびに同じになる。回数は規定しない。
- したがって、プログラムは、中断しうる呼び出しのどこででも他の fiber に切り替わりうるものとして書く。中断しうる呼び出しを挟まない区間は一息に実行される。`st.set(st.get() + 1)` は一息だが、`x = st.get(); helper(); st.set(x + 1)` は `helper` の R が Immediate でなければ割り込まれうる。
- Immediate な関数は、他の fiber から見て一息に実行される。譲渡も挟まない。

### 11.2 Fiber.scope

```emel
import Std.Fiber.{Fiber, Scope}

profile = Fiber.scope(fn() {
  s = use Scope
  a = s.fork(fn() { fetch_user(1) })
  b = s.fork(fn() { fetch_orders(1) })
  Profile(user: Fiber.join(a), orders: Fiber.join(b))
})
```

```emel
## スコープの中で fiber を起動する能力。E と R は子の fails と use
pub effect Scope[E, R] {
  fn fork[A](f: fn() -> A fails E use { Scope[E, R], R }) -> Fiber[A]   # 子の中の Scope はこのスコープ自身
  fn deferred[A]() -> Deferred[A]
}

@intrinsic
pub fn scope[A, E, R](
  body: fn() -> A fails E use { Scope[E, R], Async, R },
) -> A fails E use { Async, R }
```

- Scope は組み込みのエフェクトで、供給できるのは `Fiber.scope` だけである。利用者は Scope のハンドラを書けない（E0413）。`use Scope` は書ける。
- Scope の操作は、操作自身の型引数（`fork[A]`）と、集合の型引数（E、R）を持つ。どちらも組み込みのエフェクトにだけ許す（8.1）。
- `Fiber.fork(f)` と `Fiber.deferred()` は、`(use Scope).fork(f)` と `(use Scope).deferred()` を包んだ関数である。ふつうはこちらを使い、`s = use Scope` は外側のスコープを指すときにだけ書く。

```emel
pub fn fork[A, E, R](f: fn() -> A fails E use { Scope[E, R], R }) -> Fiber[A] use Scope[E, R] { (use Scope).fork(f) }
pub fn deferred[A, E, R]() -> Deferred[A] use Scope[E, R] { (use Scope).deferred() }
```

- fork できるのは、Scope が供給されているところ、つまり Fiber.scope に渡した関数の中と、そこから呼ばれた関数の中だけである。補助の関数はスコープを引数で受けず、`use Scope` で受ける（能力の値は引数に渡せない。8.2）。どのスコープへ fork するかは R の Scope に表れる。入れ子のスコープでは、`use Scope` は最も内側のスコープを指す。外側へ fork するときは、外側で取り出した能力の値を使う（8.3）。
- 子の fiber は、スコープを抜けるまでに必ず終わる。スコープの本体が値を返した時点で残っている子は中断され、すべての子の巻き戻り（release を含む）が終わってから、スコープが本体の値を返す。
- 子がエラーか defect で終わると、兄弟の fiber（スコープの本体を含む）は中断され、原因はスコープの外へ伝わる。子の fails は `Scope[E, R]` の E を通してスコープの fails に合流する。2つ以上の子が失敗したときは、先に失敗したものをスコープの結果にし、後の失敗は表示の注記（`note: another fiber also failed: <原因>`）に足す（14.4 の release の defect と同じ）。
- 子の中で、呼び出し元から渡されるハンドラ（8.3）は、Fiber.scope を呼んだ時点のものである。ただし Scope だけは、その子が属すスコープ自身を指す（子が兄弟を fork できるように）。
- 子の E と R は `Scope[E, R]` の E と R に含まれなければならない（包含。R の中の `Scope[E1, R1]` の要求は、E1 ⊆ E2、R1 ⊆ R2 の `Scope[E2, R2]` で満たされる）。等式にすると、fork する補助の関数の型が具体的な集合に決まり、別の子が別のエラーを足すと食い違うためである。したがって子が使うエフェクトは Fiber.scope の外で供給しなければならない。ただし子の R の中の Scope の要求は、そのスコープ自身の `Scope[E, R]` で満たす。型の上では、fork に渡す関数の型に `Scope[E, R]` を書き出しておき（`use { Scope[E, R], R }`）、R には入れない。書き出さないと、子の中の Scope が R に入ってスコープの外へ漏れる（子が兄弟を fork できるように。要求の E と R がスコープの E と R に含まれることだけを課す）。入れ子のスコープでも、子の Scope は外側でなく、その子が属すスコープで満たされる。スコープの本体の中に書いた with は、子には配られない。

```emel
Fiber.scope(fn() {
  s = use Scope
  with PostgresUsers {
    s.fork(fn() { (use Users).find(1) })    # error[E0402]: effect `Users` is not provided
  }
  ()
})
# 直し方: with PostgresUsers { Fiber.scope(fn() { ... }) }
```

- この規則により、子より先に終わる with のハンドラを子が使うことは、型で起きなくなる。例外は、同じエフェクトをスコープの外でも供給していて、スコープの本体の中の with の中で作ったクロージャ（または取り出した能力の値）を子に渡した場合である。このとき子は内側のハンドラを使い、その with が先に終われば、8.6 の実行時の検査で defect になる（0.22 の capture set で静的に止める）。
- fork は中断点ではない（Scope の操作は fn）。子は待ち行列に入り、親が次に中断したときに走り始める。走り始める前に中断された子は、f を呼ばずに Interrupt で終わる。
- スコープの結果は、本体と子のうち最初の Fail か Die、なければ本体の終わり方である。本体が外からの中断で巻き戻る途中に子が defect で終われば、その defect が結果になる（14.4 の release の defect と同じ向き）。
- 子が失敗した時点で、スコープは閉じる（11.8）。兄弟の失敗で巻き戻る途中の fork と deferred は defect になり、注記に回る。
- fork は Async を要求する。fork の操作の型には Async を載せず、Fiber.scope の R に残る Async で表す（`Fiber.fork` の use 節に Async がないため）。
- 親より長生きする、切り離された fiber は持たない。常駐する処理は、main 直下のスコープで fork する。

### 11.3 組み合わせ関数

組み合わせ関数は、Fiber.scope の上に標準ライブラリ（`Std.Fiber`）として純粋な Emela で書く。言語機能ではない。

| 関数 | 型 | 意味 |
|---|---|---|
| `all` | `all[A, E, R](fs: List[fn() -> A fails E use R]) -> List[A] fails E use { Async, R }` | すべてを並行に実行して、結果を元の順に集める。1つが失敗すれば残りを中断して失敗する |
| `race` | `race[A, E, R](fs: List[fn() -> A fails E use R]) -> A fails E use { Async, R }` | 最初に終わったものを採り、残りを中断する。最初に終わったものがエラーなら、そのエラーで失敗する |
| `both` | `both[A, B, E, R](f: fn() -> A fails E use R, g: fn() -> B fails E use R) -> (A, B) fails E use { Async, R }` | 型の違う2つを並行に実行して組で返す。1つが失敗すればもう1つを中断して失敗する |
| `map` | `map[A, B, E, R](xs: List[A], f: fn(A) -> B fails E use R) -> List[B] fails E use { Async, R }` | 各要素に f を並行に適用し、結果を元の順に集める |
| `timeout` | `timeout[A, E, R](ms: Int, f: fn() -> A fails E use R) -> Option[A] fails E use { Clock, Async, R }` | f を ms ミリ秒まで待つ。間に合えば Some、間に合わなければ f を中断して None。失敗にしたいときは `Option.or_fail` を挟む |

```emel
pub fn race[A, E, R](fs: List[fn() -> A fails E use R]) -> A fails E use { Async, R } {
  scope(fn() {
    s = use Scope
    d = s.deferred()
    List.map(fs, fn(f) { s.fork(fn() { Deferred.complete(d, f()) }) })
    Deferred.await(d)
  })
}
```

- 日常の書き方は組み合わせ関数で済み、scope と fork は途中で join する、Deferred を使う、のような込み入った形にだけ現れる。

```emel
(user, orders) = Fiber.both(fn() { fetch_user(1) }, fn() { fetch_orders(1) })
users = Fiber.map(ids, fn(id) { fetch(id) })
```

- 「後で実行するもの」は `fn() { ... }` で包んで渡す。計算そのものを値にしない直接の書き方なので、包むのは避けられない。引数なしの関数の短い書き方は設けない。
- 最初の成功を採る版（失敗した子を無視し、全部が失敗したら最後の原因で失敗する）は、`attempt`（11.5）と Deferred の上に書ける。
- 同時に走る数の上限（「1000件を最大10並行で」）は、Queue か Semaphore と一緒に足す（15.2）。

### 11.4 中断

- 中断は、対象の fiber が次の中断点に達したときに効果を持つ。
- 中断された fiber は、その地点から巻き戻る。途中の with について、ハンドラの release が内側から順に実行される。
- release の実行中は中断されない。中断は、実行中の release が終わった後に効く。
- 子が中断されるのは、スコープの本体が値を返したとき、兄弟が失敗したとき、`Fiber.interrupt` を呼ばれたときの3通りである。

```emel
## 子を中断し、巻き戻り（release を含む）が終わるまで待つ。終わっている子には何もしない
@intrinsic
pub fn interrupt[A](fiber: Fiber[A]) -> () use Async
```

### 11.5 失敗の原因

fiber が正常に終わらなかったときの原因は、次の3種類である。監視する側は、この区別を観測できる。

| 原因 | 発生源 | 型に現れるか |
|---|---|---|
| Fail | fail | 現れる（E） |
| Die | defect | 現れない |
| Interrupt | 中断 | 現れない |

原因は `Std.Cause` の `Cause[E]` で表す。7.1 のとおり「E のどれか」という値の型は作れないので、Cause は中身のエラーの値を取り出せない opaque な型とし、種類を見ることと、起こし直すことだけができる。起こし直した後は、呼ぶ側で escape を書けば具体的なエラーとして受けられる。

```emel
pub enum Exit[A, E] { Success(A), Failure(Cause[E]) }      # Std.Fiber

pub opaque type Cause[E]                                     # Std.Cause
pub enum CauseKind { Fail, Die, Interrupt }
pub fn kind[E](c: Cause[E]) -> CauseKind
pub fn to_string[E](c: Cause[E]) -> String      # error: ... / defect: ... / interrupted
pub fn raise[A, E](c: Cause[E]) -> A fails E    # Fail は fail、Die は defect、Interrupt は中断の巻き戻し
```

結果の受け取り方は4つある。

| 関数 | 型 | 意味 |
|---|---|---|
| `join` | `join[A](fiber: Fiber[A]) -> A use Async` | 子が終わるのを待ち、値を返す |
| `await` | `await[A](fiber: Fiber[A]) -> Exit[A, {}] use Async` | 子が終わるのを待ち、終わり方を返す |
| `attempt` | `attempt[A, E, R](f: fn() -> A fails E use R) -> Exit[A, E] use R` | f をその場で実行し、Fail と Die を値に変える |
| `Cause.raise` | 上のとおり | 受けた原因を起こし直す |

- 待つのは、join か await を呼んだ fiber だけである。ほかの fiber はその間も進む。呼び出し側に印は付かない（8.2）。
- 子の Fail と Die はスコープに伝わる（11.2）ので、join と await に届くのは成功か Interrupt だけである。終わった子の値は覚えておき、2回目からはすぐ返す。
- 中断された子を join すると、中断の起こり方（`Fiber.interrupt`、スコープの終わり、resume されずに捨てられた継続）によらず defect になる（`fiber was interrupted`）。
- release の実行中は中断を待たせる（11.4）ので、その間だけ join と await が失敗した子を見ることがある。そのとき join は呼んだ fiber を中断として巻き戻し（join の型に E がないため）、await は `Failure(原因)` をそのまま返す。
- 自分自身への `Fiber.interrupt` は、その場で巻き戻る（release の中なら release の後）。
- 届いた中断は、受け止める枠（スコープかプログラムの最上位）に達するまで巻き戻りとして続く。途中で内側のスコープの結果を escape が受けるなどして普通の処理に戻っても、次の中断点でもう一度中断する。巻き戻りの途中の attempt は Die も受けない（release の defect を fiber の結果に残すため）。
- 中断されうる子の結果を見たいときは await を使う。
- 子のエラーをスコープに伝えたくないときは、子の中で attempt で包む。fork の種類は増やさない。

```emel
s.fork(fn() {
  Fiber.attempt(fn() { handle(conn) }) match {
    Success(_) -> ()
    Failure(cause) -> (use Console).print_error_line(Cause.to_string(cause))
  }
})
```

- attempt は、defect を値に変えられる境界である（7.5）。attempt の外では、defect はこれまでどおり escape を素通りする。
- attempt は、自分の fiber への中断（Interrupt）を受けない。受けると中断を握りつぶして走り続ける fiber が書けるためである。Interrupt を観測できるのは、await で子を見るときだけである。

| 原因 | attempt | await | スコープ |
|---|---|---|---|
| Fail | Failure として受ける | 届かない | 兄弟を中断して伝える |
| Die | Failure として受ける | 届かない | 兄弟を中断して伝える |
| Interrupt | 受けずに巻き戻る | Failure として受ける | その子だけが終わる |

### 11.6 並列

複数スレッドでの並列実行は、初版の範囲に含めない。将来は、純粋な関数に限った並列プリミティブと、ヒープを分離したワーカー間のメッセージングを検討する。スレッドやロックを言語に出すことはしない。

### 11.7 Deferred

Deferred は、一度だけ値を入れられる入れ物で、fiber の間で値を受け渡す。スコープに属す。

```emel
d = (use Scope).deferred()       # Deferred[A]。スコープに属す
```

| 関数（`Std.Deferred`） | 型 | 意味 |
|---|---|---|
| `complete` | `complete[A](d: Deferred[A], value: A) -> Bool` | 最初の1回だけ値を入れて True。2回目からは何もせず False。中断しない |
| `await` | `await[A](d: Deferred[A]) -> A use Async` | 値が入るまで待つ |
| `poll` | `poll[A](d: Deferred[A]) -> Option[A]` | 入っていれば `Some(値)`、まだなら `None`。待たない。中断しない |

- 寿命をスコープに結びつけるため、作れるのは Scope の操作 `deferred` だけである。
- 誰も値を入れない Deferred を待つ子は、スコープの終わりで中断される。
- 使いみちは、どれか1つが終わるのを待つ（race）、走り続ける子から途中の値を受け取る（待ち受けの準備ができた合図）、止める合図を配る（`poll` で区切りごとに見る）の3つである。外から強制的に取り消すのは `Fiber.interrupt`（11.4）である。1つの Deferred を何人で待ってもよく、値が入れば全員が再開する。
- Deferred は可変な入れ物である（14.6）。観測できるのは「まだ入っていない」と「この値が入った」の2つだけである。

### 11.8 持ち出しの禁止

Scope の能力、fiber のハンドル（`Fiber[A]`）、Deferred は、スコープの外へ持ち出せない。

- Scope は能力なので、能力の規則（8.2、8.6）がそのまま掛かる。引数に渡す、データに入れる、返すはエラーになる（E0408〜E0410）。
- `Fiber.scope` の値の型のどこかに `Fiber` か `Deferred` が含まれていればエラーになる（E0425）。`Option[Fiber[User]]` も含む。スコープの外では子はもう終わっているので、正しいプログラムを拒むことはない。
- 型で止まらない持ち出し（State に入れる、クロージャで捕まえて返す）は、実行時に検査する。終わったスコープの Scope の操作、ハンドルの join、await、interrupt、Deferred の complete、await は defect になる（`fiber scope was used after it ended`、`fiber was joined after its scope ended` など）。
- スコープは、本体が値を返したときか、子が失敗したときに閉じる。閉じた後に fork すると defect になる。
- 文面は `fiber scope was used after it ended`、`fiber was joined after its scope ended`（awaited、interrupted も同じ形）、`deferred was completed after its scope ended`（awaited も同じ形）である。poll も同じく検査する。

0.22 で capture set（8.6）が入ると、ハンドルと Deferred を「作ったスコープの能力を抱えた値」として扱い、すべて静的に止める。0.20 でエラーになるプログラムは 0.22 でもエラーになる。版を上げて通らなくなるのは、0.20 で実行時の defect だったものだけである。

| 持ち出し方 | 0.20 | 0.22 |
|---|---|---|
| 能力の値（Scope を含む）を引数に渡す、データに入れる、返す | 静的（E0408〜E0410） | 静的 |
| 能力を捕まえたクロージャを with やスコープの外へ出す | 実行時（状態のあるハンドラと Scope） | 静的 |
| `Fiber` や `Deferred` を型に含む値を Fiber.scope から返す | 静的（E0425） | 静的 |
| `Fiber` や `Deferred` を State に入れる、クロージャで捕まえて外へ出す | 実行時 | 静的 |

## 12. 外部関数

ホスト側の関数は `@external` を付けた本体のない fn として宣言し、副作用のあるものはハンドラの中でしか呼べない。これにより、すべての副作用が名前の付いたエフェクトを通る。

### 12.1 宣言

```emel
@external(js, "console.log")
fn console_log(msg: String) -> ()

@external(js, "Math.sin")
@external(wasm, "env", "sin")
fn sin(x: Float) -> Float use {}

@external(js, "./http_ffi.mjs", "fetchText")
@external(wasm, "wasi:http/client", "fetch")
suspend fn fetch_text(url: String) -> String
```

- 引数と戻り値の型は必ず書く。コンパイラは中身を見られないので、推論しない。
- ターゲットごとに `@external` を1つ書く。1つの fn に複数のターゲットの注釈を並べてよい。同じ fn に同じターゲットの注釈を2つ書くとエラーになる（E0139）。
- fn の `@external` の引数は、`(ターゲット, "名前")` か `(ターゲット, "ファイル", "名前")` の形に限る（E0138）。ターゲットは `js` と `wasm` である（E0140）。文字列に補間は書けない。
- ビルド対象のターゲットに対応する注釈がない fn は、エントリ（`emela build` と `emela run` では main、`emela test` ではテスト関数）からたどれるときだけエラーになる。ハンドラを with に書くと、その操作の本体から呼ぶ fn もたどれる側に入る。たどれない fn は検査しないので、同梱の `SystemConsole` が JS の `@external` しか持っていなくても、WASM のビルドで読んでも、使わなければエラーにならない。
- この検査は build、run、test で行う。`emela check` と LSP はターゲットを決めないので、この検査をしない。
- たどれないのに出力された外部関数（公開の fn から写されたもの）にターゲットの注釈がなければ、呼ばれたときに defect になる。
- ファイルを指す場合（`"./http_ffi.mjs"`）、宣言を含むソースのディレクトリからの相対パス（`./` か `../` で始まる）で指す。出力はそのファイルを絶対パスで読むので、出力をソースと別の場所へ移すと動かない。同梱の core のソースから指すファイルも、core のソースと一緒にコンパイラに同梱し、ビルドの出力先に書き出す。
- 呼び出しは普通の関数と同じ形で書く。

### 12.2 呼べる場所

| 宣言 | 意味 | 呼べる場所 |
|---|---|---|
| `use {}` を明記 | 純粋であると宣言する | どこからでも |
| `use` を省略 | ホストの副作用を持つ | ハンドラの init、release、操作の本体の中だけ |
| `suspend fn` | 完了を待つ必要がある。Async を要求する | ハンドラの中だけ |

- `use {}` の宣言が正しいかどうかを、コンパイラは検証できない。宣言した人が責任を持つ。
- 呼べる場所の制限は、呼び出しだけでなく参照に掛かる。use を省略した外部関数を、関数の値としてハンドラの外へ持ち出すこともできない。ハンドラの操作の本体の中の無名関数の中は、中とみなす。
- 外部関数のホストの副作用は R に載せない。use を省略した外部関数の R は空で、副作用は呼べる場所の制限で扱う。
- suspend fn の外部関数は、JS では Promise を返す関数に、WASI では async な import に対応する。呼び出した fiber は、完了まで中断する。
- JS では、suspend fn の外部関数の最後の引数に、ランタイムが `AbortSignal` を足して渡す。待っている fiber が中断されると abort する。suspend fn の操作の実装の中で外部関数を待っているときも、resume の前に呼び出し元が中断されれば、実装を巻き戻して abort する。通信やタイマーを止めるためで（止めないと結果を捨てても通信が続き、Node ではプロセスが終わらない）、使わない関数は無視してよい。中断で止まるのはこの形で待つものだけで、ハンドラがコールバックで後から resume する形のものは止まらない（14.5 の捨てられた継続）。同梱のハンドラ（SystemClock の sleep を含む）はこの形で書く。
- JS で Promise でない値が返ったときは、解決した値として扱う。Promise の拒否は、呼んだときの例外と同じく defect になる（12.5）。

### 12.3 ホストの型

```emel
@external
type Connection
```

フィールドを持たない `@external type` は、ホスト側のオブジェクトを表す不透明な型である。注釈は引数を取らない。Emela からは持ち回ることしかできない。

### 12.4 境界を越えられる型

外部関数の引数と戻り値に使えるのは、次の型だけである。

- Int、Int64、Float、Bool、String、`()`
- `@external type` で宣言した型
- 上記の型だけからなる関数型（コールバック）

List や利用者が定義した型は、直接は渡せない。ハンドラの中で変換する。

- コールバックとして渡した関数の引数と戻り値も、外部関数の引数と戻り値と同じ扱いを受ける（ホストから受け取る String は 12.5 のとおり正規化する）。
- `()` を返す外部関数は、ホストの戻り値を捨てて `()` を返す。

### 12.5 例外と失敗

- 外部関数が投げた例外は defect になる。メッセージは例外の名前を前に付けたもの（`defect: TypeError: bad`）で、Error でない値は `uncaught exception: ...` とする。
- 外部関数の宣言に `fails` は書けない。失敗として扱いたい結果は、ホスト側で値にして返し、ハンドラの中で fail に変える。
- JS から受け取った文字列に対になっていないサロゲートが含まれる場合、境界で置換文字に正規化する。
- コールバックの中で起きた defect は、外部関数の例外として包まずに、元の defect のまま伝わる。

## 13. テスト

テストは `@test` を付けた関数であり、検証は `assert` で書く。ハンドラを差し替えるだけでテストになるので、モックのための仕組みは持たない。

```emel
@test
fn greet_returns_user() {
  with AppTest {
    user = greet(1)
    assert user.name == "alice"
  }
}

@test
fn greet_fails_for_unknown_id() {
  with AppTest {
    result = Some(greet(999)) escape { NotFound(_) -> None }
    assert result == None
  }
}
```

### 13.1 @test

- `@test` を付けられるのは、引数のない fn である。
- どのファイルにも書ける。実装と同じファイルに書けば、非公開の関数をそのままテストできる。
- テスト関数は、通常のビルドでは取り除かれる。
- テスト関数は、テスト関数の中からしか参照できない（E0227）。通常のビルドで取り除かれるためである。テスト関数どうしは参照してよい。参照には、呼び出しだけでなく値としての参照も含む。

### 13.2 assert

- `assert 式` の式の型は Bool である。False のとき defect になる。assert の式全体の型は `()` である。
- 比較の assert は、両辺を左から1回ずつ評価する。失敗したときの defect のメッセージは `assertion failed: <式の字面>` で、比較のときは続けて両辺の値を dbg と同じ表示で出す。両辺の型が Show を満たさないときは値を出さない。
- assert はキーワードであり、コンパイラが式の形を見る。比較が失敗したときは、両辺の実際の値を表示する。
- assert はテスト関数の外でも使える。通常のビルドでも取り除かない。

### 13.3 テスト関数の制約

- テスト関数の R は、Async を除いて空でなければならない。Async はテストランナーが供給する。
- 処理されなかったエラーは、そのテストの失敗として報告される。テスト関数の E は空でなくてよい。
- defect も、そのテストの失敗として報告される。他のテストの実行は続く。

### 13.4 emela test

- `emela test [パス] [フィルタ]` は、検査を通ったプログラムのテスト関数を1つずつ実行する。
- テストの名前は、エントリのモジュールのものは関数名だけ、ほかのモジュールのものはモジュール名を前に付ける（`Http.Client.gets`）。
- フィルタを渡すと、名前に部分一致する（大文字小文字を区別する）テストだけを実行する。単独ファイルでは、エントリから import でたどれるモジュールのテストだけを実行する。
- 結果は標準出力に、`test 名前 ... ok` か `FAILED` の行と、最後の集計の行（`test result: ok. 3 passed; 0 failed; 0 filtered out`）で出す。
- 1つでも失敗すれば終了コード 1、なければ 0（テストが0個でも 0）とする。テストの途中でプログラムが終了したときは、実行中のテストを失敗にする。
- 中断したまま resume されずに終わったテストは、`interrupted` の失敗として報告し、残りのテストを続ける（14.5）。
- 出力は `target/emela/test` に書き、通常のビルドの出力を上書きしない。

## 14. 動的意味論

評価は正格で左から右に進み、with に入るときの初期化と抜けるときの解放は必ず対になる。この章の細部は、18.2 の仕分けで決定した。正式な意味論は、表層構文を脱糖したコア計算に対して定義する予定である。

### 14.1 評価順序

- 引数は、関数を呼ぶ前にすべて評価する（値呼び）。
- 部分式は、ソースに書かれた順に左から右へ評価する。名前付き引数も、宣言の順ではなく書かれた順に評価する。リストのリテラルと構成子の呼び出しの `..式` は、ほかの要素とフィールドの後に評価する。
- `&&` と `||` は、左辺で結果が決まれば右辺を評価しない。
- match は対象を1回だけ評価し、腕を上から順に試す。ガードは、パターンが合った後に評価する。どの腕にも合わなければ defect になる（型検査で網羅が保証されるので、通常は起きない）。

### 14.2 with の実行

`with H1, ..., Hn { 本体 }` は次の順で実行する。

1. ハンドラを依存関係の順に並べ、順に init を実行する。
2. 本体を評価する。
3. 初期化と逆の順に release を実行する。
4. 本体の結果（値、エラー、defect、中断のいずれか）を、with の結果とする。

- 手順3は、本体がどの形で終わっても実行する。
- ある init が失敗した場合、それまでに初期化が済んだハンドラだけを逆順に release し、本体は評価しない。失敗したハンドラ自身の release は実行しない（init が値を返していないため）。with はその init のエラーで終わる。
- ハンドラの操作の本体で使うエフェクトは、その with の外側のハンドラ、または同じ with で先に初期化されたハンドラが供給する。

### 14.3 エラーの伝播

- `fail e` は、評価中の式を外側へ順に終わらせていく。e のタグに合う腕を持つ最も内側の escape に達すると、その腕を評価し、結果が escape 式の値になる。
- 途中で with を抜けるときは、14.2 の手順3を実行する。
- main が正常に終わったときは、戻り値を表示せずに捨て、終了コード 0 で終わる。値を見たいときは `dbg` を使う。
- main まで達したエラーは、プログラムの異常終了になる。標準エラーに `error: <エラーの値の表示>` を1行出し、終了コード 1 で終わる。表示は dbg と同じ（`error: DbError(message: "down")`）。関数型のフィールドを持つ error は、エラーの名前だけを表示する（`error: Retry`）。defect（終了コード 101、7.5）と終了コードで見分けられる。main の E は空でなくてよい。

### 14.4 defect の伝播

- defect は escape を素通りし、境界まで巻き戻る。途中の with では release を実行する。
- release はエラーで終われない（E が空。8.4）。release の中で defect が起きたときは次のとおりにする。
  - 本体が値かエラーで終わっていたなら、release の defect が with の結果になる。
  - 本体がすでに defect で終わっていたなら、最初の defect を結果にし、release の defect は表示の注記に足す。
  - どちらの場合も、残りのハンドラの release はすべて実行する。
  - 注記は `note: the release of handler <名前> also failed: <メッセージ>` の形で、起きた順に並べる。
  - 中断されたまま巻き戻る途中で release が defect になったときは、`interrupted` でなくその defect が結果になる。release の中の suspend な操作が resume されないまま捨てられたときは、本体が defect ならそれを、そうでなければ `interrupted` を結果にする。

### 14.5 中断と再開

1. suspend な操作を呼ぶと、呼び出し元の残りの計算が継続として取り出され、ハンドラの操作の本体が実行される。
2. ハンドラが `resume(v)` を呼ぶと、継続が再開し、操作の呼び出し式の値が v になる。
3. 操作の本体の中でその場で resume した場合、呼び出し元は中断せずに続きを実行する。resume の後に操作の本体の残りがあれば、それを先に実行し終えてから呼び出し元が続く。
4. 後から resume した場合、その resume の呼び出しの中で呼び出し元が再開し、呼び出し元が次に中断するか終わったところで resume が戻る（値は `()`）。

- 継続を再開できるのは高々1回である。2回目の resume は defect になる。文面には、どのハンドラのどの操作で起きたかを出す。同じ経路で2回呼ぶ、ループや再帰の中で呼ぶ、のような目で見て分かる誤りは linter が警告する。型での保証は持たない（後から足しても、正しいプログラムはそのまま通る）。
- 操作の本体が resume せずに失敗したときは、そのエラーが操作の呼び出しの結果になる（呼び出し側の E に操作の fails として載っている）。resume した後で本体が失敗したり defect になったりしたときは、呼び出し元はすでに進んでいるので、プログラムの最上位（またはテスト）の defect になる（`... failed after resume: <エラー>`）。
- main かテスト関数が終わった後に呼ばれた resume は、何もしない（2回目でも defect にしない）。
- 中断しない文脈（R が Immediate。その場で resume するハンドラの with の中）で suspend な操作がその場で resume されなかったときは、その継続はもう resume されない（後から resume できるハンドラは依存に Async を持ち、R が Immediate でなくなるため）。この場合は、プログラムの最上位が終わるのを待たず、その時点で中断されたまま巻き戻る（main は `interrupted` と終了コード 130、テストは `interrupted` の失敗）。
- resume が一度も呼ばれないまま捨てられた場合、その継続は中断されたものとして巻き戻る。巻き戻るのは、その fiber を待っているスコープ（Fiber.scope か、プログラムの最上位）が終わるときである。継続が捨てられた瞬間を検出することは求めない。
- main の継続が中断されたまま巻き戻ったときは、標準エラーに `interrupted` を1行出し、終了コード 130 で終わる。エラー（1、14.3）とも defect（101、7.5）とも終了コードで見分けられる。テスト関数の継続が中断されたときは、そのテストの失敗として報告する。
- 中断されたまま巻き戻るときも、途中の with の release を内側から実行する。
- main かテスト関数が値、エラー、defect のどれかで終わった後に残った継続（resume の後も走り続ける操作の実装など）の中の with は、release しない。
- 他の fiber への切り替えと、中断の到達が起きるのは中断点だけである（11.1）。
- 別の fiber から呼ばれた resume（resume を値として受け渡したとき）は待ち行列に入れ、呼んだ側の一息の区間に割り込ませない。ホストのコールバックと同じ fiber からの resume は、3と4のとおりその場で続ける。
- resume の後も走り続ける操作の実装（3、4）は、同じ fiber の別の継続として進む。fiber への中断は本筋の継続にだけ届き、操作の実装の継続は止めない。スコープは操作の実装の継続を待たない。起動（main かテスト）が中断されたときは閉じ、その release の defect は起動の結果にする。
- イベントループが空になったときは、すべての fiber を中断し、待っている継続すべてを巻き戻す。release の実行中でも打ち切る。子を待つスコープだけは子の巻き戻りを待つ。

### 14.6 値とメモリ

- すべての値は不変である。可変な状態は、State のエフェクト（8.8）と、ハンドラが持つホスト側のオブジェクトと、Deferred（11.7。一度だけ書ける）に限られる。
- メモリの解放のタイミングは観測できず、規定しない。
- リソースの後始末はハンドラの release で行う。値の解放に連動するデストラクタは持たない。

## 15. 標準ライブラリの範囲

Prelude には純粋なものだけを入れ、ホストに触れる機能は「エフェクトの宣言」と「ターゲット別のハンドラ」に分けて提供する。個々の API はこの文書の範囲外で、ここでは構成だけを定める。

### 15.1 Prelude

Prelude は、import なしですべてのモジュールから見える。純粋なものしか含まないので、Prelude だけで書いた関数は純粋である。

| 分類 | 内容 |
|---|---|
| 型 | Int Int64 Float Bool String Never List Option Ordering |
| 構成子 | True False Some None Less Equal Greater |
| Trait | Eq Ord Show Hash |
| 関数 | panic todo dbg |

それ以外の関数は、`List.map` のようにモジュール名で修飾して呼ぶ。

- `dbg(value)` は value の表示（Show、10.6）を標準エラーに1行出し、value をそのまま返す。出力は副作用だが、デバッグ用の例外として R に載せず、純粋な関数として扱う。
- Bool（`False < True`）、Option、Ordering は Eq、Ord、Show、Hash を満たす。

### 15.2 4つの層

標準ライブラリは、コンパイラと切り離せない core と、切り離せる std の2つに分ける。core はできるだけ小さくし、std を豊かにする。

| 区分 | 置き場所 | 含まれるもの |
|---|---|---|
| core | 短い名前（`List`、`String`）。import なしで使える | Prelude と、コンパイラが構文として知っている型のモジュール（数値、String、List、Option、Bool。リテラル、補間、`..` など）。組み込み関数の表と一対一で対応するので、コンパイラと同じ版でしか動かない |
| std | `Std` の下（`Std.Console`）。import して使う | それ以外のすべて。純粋な Emela で書けるモジュールと platform のハンドラは、コンパイラから切り離して配れる。`@intrinsic` を持つ effect 層（State、Fiber）は、ランタイムと同じ版でしか動かない |

std の中は、性質で4つの層に分ける。

| 層 | 性質 | 含まれるもの |
|---|---|---|
| 値 | 純粋で、ホストに依存しない | Instant、Duration。コレクション（Map、Set、Array）は 0.21 |
| effect | 並行性と状態 | State、Fiber、Cause、Deferred（0.20）。Queue、Semaphore、Schedule、Stream（後の版。同時に走る数の上限は Http より前に入れる） |
| platform | エフェクトの宣言と、ホストのハンドラ | Console、Clock、Random、Env、FileSystem、Http |
| test | テスト用の差し替え | TestClock、TestConsole などのハンドラ。状態を State（8.8）に置くので、`State.run` の中で使う |

- `Std` の下に置くのは、std にモジュールを足すたびに利用者のファイル名が予約名になるのを避けるためである（4.1）。利用者が `http.emel` を書いても、`Std.Http` とぶつからない。
- platform のハンドラは、利用者のコードに Js や Wasm のようなターゲットの名前を出さない。1つのハンドラが、外部関数の `@external` をターゲットごとに並べて持ち（12.1）、ビルドするターゲットでどれを使うかが決まる。エントリからたどれる外部関数に、そのターゲットの注釈がなければ E0412 になる。
- ホストを使う本物のハンドラは `System` を前に付けた名前にする（`SystemConsole`、`SystemClock`、`SystemRandom`、`SystemEnv`）。テスト用のハンドラは `Test` を前に付ける（`TestClock`、`TestConsole`）。どちらも、そのエフェクトと同じモジュールに置く（`import Std.Clock.{Clock, SystemClock, TestClock}`）。
- System のハンドラを全部束ねた layer `Platform` を `Std.Platform` に置く。main はふつう `with Platform { ... }` と書き、一部を差し替えるときは `with Platform, TestClock { ... }` と後ろに並べる（8.3）。テスト用の束は置かない（TestClock と TestConsole は別々の State に依存するので、束ねても `State.run` が重なるだけで楽にならない）。

```emel
import Std.Platform.{Platform}
import Std.Console.{Console}

fn main() {
  with Platform {
    (use Console).print_line("hi")
  }
}
```
- コレクション（Map、Set、Array）は 0.21 で、Trait（Eq、Ord、Hash、Show）の上に `Std.Map`、`Std.Set`、`Std.Array` として置く。0.20 の Trait のない `==` と表示では、中身が同じでも作り方で比較や表示が変わりうるためである。実装の形と並びの順は 18.1 #36。
- コレクションは不変である。
- 時刻は Instant、時間の長さは Duration で表す。どちらも中身が Int64 の opaque な型である。Instant は Unix エポック（1970-01-01T00:00:00Z）からのミリ秒、Duration はミリ秒の長さで、負の値も表す。閏秒は数えない。Instant は `Instant.from_unix_milliseconds(ms: Int64)` で作れる（テストで時刻を固定するときや、利用者が Clock のハンドラを書くとき）。Instant に守る不変条件はなく、opaque にするのは Int64 や Duration との取り違えを防ぎ、単位を隠すためである。
- Console の操作は `print_line(text: String) -> ()`（標準出力）と `print_error_line(text: String) -> ()`（標準エラー）の2つで、どちらも改行を付けて書き、失敗しない。本物のハンドラは `SystemConsole` である。
- Random の操作は `int() -> Int`（Int の全域で一様）と `float() -> Float`（0 以上 1 未満で一様）の2つで、失敗しない。本物のハンドラ SystemRandom は、JS では暗号論的に安全な乱数源（`crypto.getRandomValues`）から引く。範囲つきの値は `int()` の上に書く普通の関数で、種を渡せる擬似乱数は純粋な値と関数で、それぞれ別に用意する。
- Env の操作は `get(name: String) -> Option[String]` だけで、失敗しない。空の値（`NAME=`）は `Some("")`、未設定は `None` である。
- FileSystem（`Std.FileSystem`）はテキスト（UTF-8）だけを扱う。Bytes がないので、バイナリは後の版に回す。操作はすべて suspend fn である（同期の API は読む間すべての fiber を止めるため）。

```emel
pub error FileNotFound(path: String)
pub error FileAccessDenied(path: String)
pub error NotADirectory(path: String)
pub error IsADirectory(path: String)
pub error DirectoryNotEmpty(path: String)
pub error InvalidText(path: String)
pub error FileSystemFailure(path: String, message: String)

pub effect FileSystem {
  suspend fn read_text(path: String) -> String
    fails FileNotFound | FileAccessDenied | IsADirectory | InvalidText | FileSystemFailure
  suspend fn write_text(path: String, text: String) -> ()
    fails FileNotFound | FileAccessDenied | IsADirectory | FileSystemFailure
  suspend fn append_text(path: String, text: String) -> ()
    fails FileNotFound | FileAccessDenied | IsADirectory | FileSystemFailure
  suspend fn exists(path: String) -> Bool
  suspend fn is_directory(path: String) -> Bool
  suspend fn list_directory(path: String) -> List[String]
    fails FileNotFound | FileAccessDenied | NotADirectory | FileSystemFailure
  suspend fn create_directory(path: String) -> ()
    fails FileAccessDenied | NotADirectory | FileSystemFailure
  suspend fn remove(path: String) -> ()
    fails FileNotFound | FileAccessDenied | DirectoryNotEmpty | FileSystemFailure
}
```

  - write_text は作るか上書きし、append_text はなければ作る。親のディレクトリがなければ FileNotFound である。create_directory は親もまとめて作り、既にあれば何もしない。途中にファイルがあれば NotADirectory である。remove はファイルか空のディレクトリを消す。中身ごとの削除は持たない。
  - exists と is_directory は失敗しない。権限で見えないときも False である。list_directory は名前だけを、名前の順に並べて返す。
  - エラーは種類ごとに分け、操作ごとに起こりうるものだけを fails に書く。escape で受けたタグが E から消えるようにするためである（1つの error に種類のフィールドを持たせると、一部の値だけを受ける腕になり E に残る。7.3）。名前は利用者の `NotFound` などとぶつからないようにした。ホストのそれ以外のエラーは FileSystemFailure にまとめる。
  - UTF-8 として読めないファイルは、置換文字に置き換えずに InvalidText で失敗する。読んで書き戻したときに中身が壊れないようにするためである。
  - 相対パスはプロセスの現在のディレクトリから解く。パスは String で表し、正規化（`..` の解決）、絶対パスへの変換、`~` の展開はしない。
  - 本物のハンドラ SystemFileSystem は JS では `node:fs/promises` を使い、Platform に束ねる。
  - テスト用のハンドラ TestFileSystem は、状態を `State[TestFiles]` に置き、その場で resume する。`pub type TestFiles(files: List[(String, String)], directories: List[String])` で、files はパスと中身の組をパスの順に保つ。ファイルの祖先はディレクトリとみなす。パスは文字列のまま比べる。エラーは SystemFileSystem と同じ規則で起こす。FileAccessDenied、InvalidText、FileSystemFailure は起こせないので、試すときは利用者が小さなハンドラを書く。
  - FileSystem の R は Immediate でないので、外部関数のコールバック（9.5）の中では使えない。JS のコールバックの中では待てないためである。コールバックからは Deferred（11.7）で fiber に合図を送り、fiber の側でファイルを扱う。
- Http（`Std.Http`）はクライアントだけを持つ（サーバーは fiber の上に後の段で作る）。操作は `send` の1つで、要求と応答は値である。よく使う形は send の上の関数にする。ハンドラを書く人が実装するのは send だけで済み、要求を組み立てる処理をふつうの関数としてテストできるためである。

```emel
pub enum Method { Get, Head, Post, Put, Patch, Delete, Options }
pub type Request(method: Method, url: String, headers: List[(String, String)], body: String)
pub type Response(status: Int, headers: List[(String, String)], body: String)

pub error InvalidUrl(url: String)
pub error ConnectionFailed(url: String, message: String)
pub error ResponseNotText(url: String)
pub error UnexpectedStatus(status: Int, body: String)

pub effect Http {
  suspend fn send(request: Request) -> Response fails InvalidUrl | ConnectionFailed | ResponseNotText
}

pub fn request(method: Method, url: String) -> Request                  # 本文なし、ヘッダなし
pub fn add_header(req: Request, name: String, value: String) -> Request
pub fn get(url: String) -> Response fails InvalidUrl | ConnectionFailed | ResponseNotText use Http
pub fn post(url: String, body: String) -> Response fails InvalidUrl | ConnectionFailed | ResponseNotText use Http
pub fn header(res: Response, name: String) -> Option[String]           # 最初の値。大文字小文字を区別しない
pub fn headers(res: Response, name: String) -> List[String]            # すべての値
pub fn encode_query(pairs: List[(String, String)]) -> String           # q=%E6%9D%B1&page=2
pub fn require_ok(res: Response) -> Response fails UnexpectedStatus     # 2xx 以外を失敗にする
pub fn response(status: Int, body: String) -> Response                 # ヘッダなしの応答
```

  - 本文はテキストだけを扱う。送るときは UTF-8 にし、受けるときは UTF-8 として読み、読めなければ ResponseNotText で失敗する（FileSystem の InvalidText と同じ考え方）。本文の先頭の BOM は取り除く（FileSystem は読んで書き戻しても変わらないよう BOM を残す）。content-type を書かなければ `text/plain;charset=UTF-8` になる。本文は全部を読み込んでから返す（ストリームは後の版）。
  - ヘッダは `List[(String, String)]` で持つ。Map が 0.21 なのと、同じ名前のヘッダが複数並ぶためである。応答のヘッダの名前は小文字にして名前の順に並べ、同じ名前の値は `, ` でつなぐ（`set-cookie` だけは1つずつ別の組にする）。要求のヘッダは書いた順に送る。
  - メソッドは enum で、一覧にないメソッドは送れない。
  - scheme が `http:` と `https:` 以外の URL は InvalidUrl である（送れないので、届かなかった ConnectionFailed と区別する）。GET と HEAD の空の本文は本文なしで送る。空でない本文や正しくないヘッダは ConnectionFailed である。header と headers は名前を ASCII の範囲で大文字小文字を区別せずに比べる。
  - 4xx と 5xx は失敗にせず、status で返す。404 や 409 を見て分けたい場面が多いためである。失敗にしたいときは require_ok を挟む。失敗にするのは応答を受け取れなかったときだけで、名前解決、接続、TLS、リダイレクトの回数超えはどれも ConnectionFailed にまとめる。詳しい理由は message に入れる。リダイレクトは自動で辿る。
  - タイムアウトの項目は持たない。`Fiber.timeout`（11.3）か race で書く。send を待っている fiber が中断されると、通信を止める（12.2 の AbortSignal）。
  - encode_query は JS の `encodeURIComponent` を純粋な外部関数（12.2）として呼ぶ。URL を部品に分ける型は持たない。
  - 本物のハンドラ SystemHttp は JS の `fetch` を使い、Platform に束ねる。Cookie を覚えず、プロキシの環境変数を使わない。
  - テスト用のハンドラ TestHttp は、状態を `State[TestServer]` に置き、その場で resume する。`pub type TestServer(respond: fn(Request, Int) -> Option[Response], sent: List[Request])` で、respond は要求と何回目か（0 から）を受けて応答を返す純粋な関数、None なら ConnectionFailed である。sent に送られた要求を順に足す。InvalidUrl と ResponseNotText は起こせない。遅い応答は作れず、時間の絡むテストは TestClock（15.2）による。
- `Std.Path` は、パスの文字列を組み立てる純粋な関数 `join(a, b)`、`parent(path)`、`file_name(path)`、`extension(path)` を持つ。区切りは `/` だけを扱う（Node は Windows でも `/` を受け付ける）。`parent`、`file_name`、`extension` は Option を返す（`Path.parent("a.txt")` は None）。
- JSON の変換（Encode、Decode）は、導出規則を持つ Trait として標準ライブラリが提供する。
- Prelude と core のモジュールは、コンパイラに同梱する `.emel` のソースである。std も、配る仕組み（18.1 #14）が決まるまでは同じく同梱する。Emela で書けない関数は、そのソースの中で `@intrinsic` を付けた本体のない fn として、シグネチャを Emela の文法で宣言する。`@external` を使わないのは、12.4 の境界の型の制約（List などを渡せない）を受けないためである。

### 15.3 API の約束

標準ライブラリ（core と std）の関数は、次の約束に従って名前を付ける。18.1 #34 で決めたものから足していく。

- 対象を最初の引数に置く。`xs |> List.map(f)` のように、パイプで書ける。
- 関数を受ける引数の名前は `f` とし、ラベルでなく位置で渡す（`List.map(xs, fn(x) { ... })`）。`with` と `where` をラベルにする案は、どちらも予約語（3.1、3.3）で仮引数の名前に使えず、外向きのラベルと中の名前を分ける構文を足すほどではないので採らなかった。
- 2つをつなぐ関数は `append`（`List.append(xs, ys)`、`String.append(a, b)`）、並びを平らにする関数は `List.flatten(xss)` と `String.concat(parts)`、区切りを挟んでつなぐ関数は `join`（`String.join(parts, sep)`）とする。
- 畳み込みの初期値の引数の名前は `from` とする（`List.fold(xs, from: 0, f: add)`）。
- うまくいかないときの返し方は、場面で分ける。
  - 探して無い、範囲の外: Option を返す（`List.get`、`List.find`、`Env.get`）。
  - 入力の形が正しくない: error を宣言して fail する（`Int.parse(s) -> Int fails ParseError`）。Option の版は持たず、欲しければ escape で変える。
  - 外の世界の失敗: エフェクトの操作の `fails` に書いて fail する（8.1）。
  - 呼んだ側の前提が崩れた: defect にする。
- 名前の型は次のとおりとする。`to_*` は失敗しない変換、`from_*` は失敗しない作成、`parse` は失敗しうる文字列からの変換、`is_*` は Bool を返す判定。Option の既定値は `Option.or(opt, default)`、つなぐのは `Option.and_then` とする。
- 2つの型の間の変換は、後から足した型（依存する側）のモジュールに、行きと帰りをまとめて置く（`Int64.from_int` と `Int64.to_int`、`Instant.from_unix_milliseconds` と `Instant.to_unix_milliseconds`）。基本の型は後から足した型を知らないためである。ただし String への変換は、どの型も自分のモジュールの `to_string` に置く。同じ変換を両方の型に置かない。
- 入力の形の誤りを表す error は、Prelude の `error ParseError(input: String)` である（`Int.parse`、`Float.parse`）。Int と Float の間の変換は `Float.from_int`、Int と Int64 の間は `Int64.from_int` と `Int64.to_int` に置く。

## 16. ターゲットに関する規定

同じプログラムは、JS と WASM で同じ観測可能な結果を返さなければならない。そのために、数値と文字列の意味をターゲットから独立に定める。

JS のターゲットは、サーバーで動くホスト（Node 18 以降と、`node:` のモジュールと `fetch` を持つ Deno、Bun）を前提にする。ブラウザは 0.20 の対象にしない。platform のハンドラ（15.2）は、ブラウザでの動きを規定しない。

### 16.1 数値

| 項目 | 規定 |
|---|---|
| Int の範囲 | -2,147,483,648 から 2,147,483,647 |
| Int64 の範囲 | -2^63 から 2^63 - 1 |
| 整数のあふれ | 2の補数で巻き戻る。defect にはならない |
| 整数の除算 | 0の方向へ切り捨てる。剰余の符号は被除数に従う |
| 整数のゼロ除算 | defect |
| Float | IEEE 754 binary64。ゼロ除算は IEEE のとおり無限大か NaN になる。`%` は fmod（被除数の符号） |
| 型の変換 | 暗黙には行わない。`Int64.from_int` のような関数で明示する |
| Float から Int への変換 | `Float.floor`、`ceil`、`round`、`truncate` で明示する。結果が Int の範囲外か、`NaN`、±`Infinity` なら defect（巻き戻しも飽和もしない）。`Float.round` は 0.5 を 0 から遠い方へ丸める（`2.5` は 3、`-2.5` は -3） |
| Int64 から Int への変換 | `Int64.to_int` は下位32ビットに巻き戻す |

あふれを検出したい場合は、`Int.checked_add` のような関数を使う。最小値を -1 で割ったとき（`-2147483648 / -1`）も、あふれとして巻き戻る。

### 16.2 文字列

- String は Unicode 文字の列であり、内部の符号化は観測できない。
- 位置を数値で指定する API は持たない。走査は `String.chars` や `String.split` などの関数で行う。
- `String.length` は見た目の文字数（書記素クラスタの数）を返す。`String.length("👍")` は 1 である。
- 文字の型は持たない。1文字は長さ1の String である。コードポイントを扱うときは `String.code_points(s) -> List[Int]` と `String.from_code_point(n) -> Option[String]` を使う。
- 書記素クラスタの境界は Unicode の版によって変わる。JS と WASM で結果をそろえるために、使う Unicode の版を固定する。どの版にするかは未決（18.1 #18）。
- バイト数が必要な場合は `String.byte_size` を使う。UTF-8 で符号化したときのバイト数を返す。
- 文字列の大小比較はコードポイントの辞書順である（10.6）。
- `String.split(s, "")` は書記素クラスタごとに分ける（`String.chars` と同じ。`String.split("", "")` は `[]`、`String.split("", ",")` は `[""]`）。
- `String.contains`、`starts_with`、`ends_with`、`split` の照合はコードポイントの列で行い、書記素の境界は見ない。
- `String.from_code_point(n)` は、`n` が Unicode のスカラー値（0〜10FFFF でサロゲートを除く）でなければ `None` を返す。
- `String.trim` が取り除く空白は Unicode の White_Space 特性の25文字で、表は固定する（U+FEFF と U+200B は含めない）。

### 16.3 末尾呼び出し

自分自身への末尾呼び出しがスタックを消費しないことを、両方のターゲットで保証する。末尾位置は 6.8 に定める。それ以外の再帰の深さの上限は、実装依存である。

### 16.4 規定しない点

次の点は実装依存であり、プログラムが依存してはならない。

- 値のメモリ上の表現と、解放のタイミング
- Trait の実装方式（辞書渡しか、型ごとの複製か）
- 継続の実装方式
- 実行可能な fiber が複数あるときの実行順序

### 16.5 参考: 想定する実装方式

この節は規定ではない。

## 17. 文法

この章は、ここまでの決定を EBNF に落とした初版である。formatter の実装で曖昧さを洗い出し、適合テストとともに確定させる。

### 17.1 記法

- `{ x }` は0回以上の繰り返し、`[ x ]` は省略可能、`|` は選択を表す。引用符で囲んだものは終端記号である。
- NL は、文の区切りとして働く改行である（2.5）。継続と判定された改行と、`(` `[` の内側の改行、効果の集合（`use { ... }`）の波括弧の内側の改行は、字句解析の段階で取り除かれる。
- 並びの末尾のカンマは、どこでも許される。規則では省略している。

### 17.2 字句

字句は最長一致で切る。`""""` は `"""` と `"` であり、空の文字列 `""` を2つ並べたものとは読まない。

```ebnf
lower_name = ( "a".."z" | "_" ) { letter | digit | "_" }      (* 予約語を除く *)
type_name  = "A".."Z" { letter | digit }                      (* 小文字を1つ以上含む *)
upper_name = "A".."Z" { "A".."Z" | digit | "_" }

dec_lit    = digit { digit | "_" }
int_lit    = dec_lit
           | "0x" hex_digit { hex_digit | "_" }
           | "0b" ( "0" | "1" ) { "0" | "1" | "_" }
float_lit  = dec_lit "." dec_lit [ ( "e" | "E" ) [ "+" | "-" ] dec_lit ]
string_lit = '"' { char | escape | "#{" expr "}" } '"'
           | '"""' NEWLINE { line } '"""'                (* 複数行。インデントの規則は 2.4 *)
escape     = '\\' ( '"' | '\\' | "n" | "t" | "r" | "#" | "u{" hex_digit { hex_digit } "}" )
literal    = int_lit | float_lit | string_lit
```

- `letter` と `digit` は ASCII に限る。
- `char` は `"`、`\`、改行を除く文字。`hex_digit` は `0`〜`9`、`a`〜`f`、`A`〜`F`。
- `1..2` は `dec_lit ".." dec_lit`、`1.x` は `dec_lit "." lower_name` と読む。小数点の後に数字がなければ浮動小数点にしない。

### 17.3 モジュールと宣言

```ebnf
module       = { import NL } { decl NL }

import       = "import" module_path [ "." "{" import_item { "," import_item } "}" ]
module_path  = type_name { "." type_name }
import_item  = lower_name | type_name | upper_name

decl         = { annotation NL } [ "pub" [ "opaque" ] ] item
             | impl_decl
item         = fn_decl | type_decl | enum_decl | error_decl | const_decl
             | effect_decl | handler_decl | layer_decl | trait_decl

annotation   = "@" lower_name [ "(" annot_arg { "," annot_arg } ")" ]
annot_arg    = lower_name | literal | lower_name ":" literal

fn_decl      = [ "suspend" ] "fn" lower_name [ type_params ]
               "(" [ params ] ")" [ signature ] [ block ]
signature    = [ "->" type [ "fails" error_set ] ] [ "use" effect_set ]
params       = param { "," param }
param        = "self" | lower_name [ ":" type ]

type_params  = "[" type_param { "," type_param } "]"
type_param   = ( upper_name | type_name ) [ ":" bound { "+" bound } ]
bound        = type_ref

type_decl    = "type" type_name [ type_params ] [ "(" [ fields ] ")" ] [ derive ]
enum_decl    = "enum" type_name [ type_params ] "{" variant { sep variant } "}" [ derive ]
variant      = type_name [ "(" ( fields | type { "," type } ) ")" ]
error_decl   = "error" type_name [ "(" [ fields ] ")" ]
fields       = field { "," field }
field        = { annotation } lower_name ":" type
derive       = "derive" type_ref { "," type_ref }
sep          = "," | NL

const_decl   = "const" upper_name [ ":" type ] "=" expr

effect_decl  = "effect" type_name [ type_params ] "{" { op_sig NL } "}"
op_sig       = [ "suspend" ] "fn" lower_name [ type_params ] "(" [ params ] ")"
               "->" type [ "fails" error_set ]     (* type_params は組み込みのエフェクトだけ。8.1 *)

handler_decl = "handler" type_name [ "(" [ fields ] ")" ]
               "implements" type_ref [ "[" type { "," type } "]" ] "{" { handler_item NL } "}"
handler_item = "init" block
             | "release" block
             | [ "suspend" ] "fn" lower_name "(" [ lower_name { "," lower_name } ] ")" block

layer_decl   = "layer" type_name "{" type_ref { sep type_ref } "}"

trait_decl   = "trait" type_name [ ":" bound { "+" bound } ] "{" { trait_item NL } "}"
trait_item   = "fn" lower_name "(" [ params ] ")" [ signature ] [ block ]
             | derive_rule                                    (* 構文は未確定 *)

impl_decl    = "impl" type_ref "for" type "{" { impl_item NL } "}"
impl_item    = "fn" lower_name "(" [ params ] ")" block
```

文法の外で課す制約は次のとおりである。

- 本体のない fn_decl と、トップレベルの suspend fn は、`@external` が付いている場合にだけ許される。trait_item の fn は既定の実装を持たなくてよく、この制約は掛からない。
- `opaque` は type と enum にだけ付けられる。
- フィールドのない type_decl は、`@external` が付いている場合にだけ許される。
- enum_decl は1つ以上のバリアントを持つ。値を持たない型は Never だけである。
- type_decl と enum_decl の直後の改行に `derive` が続くとき、その改行は区切りにならず、derive は宣言の続きになる（10.5 の例の書き方）。間の空行とコメントだけの行は飛ばす（2.5 の継続の判定と同じ）。`derive` は文脈依存の語なので、2.5 の字句の継続規則には入れず、宣言の位置でだけ扱う。

### 17.4 型

```ebnf
type       = type_ref [ "[" type_arg { "," type_arg } "]" ]
           | upper_name                                       (* 型引数 *)
                                                              (* 型名の型引数は type_ref の形で書き、名前解決で区別する *)
           | "Self"
           | "(" ")"                                          (* Unit *)
           | "(" type ")"                                     (* 括弧 *)
           | "(" type "," type { "," type } ")"               (* タプル *)
           | "fn" "(" [ type { "," type } ] ")" "->" type
             [ "fails" error_set ] [ "use" effect_set ]
type_ref   = [ module_path "." ] type_name

type_arg   = type
           | "{" [ effect_item { "," effect_item } ] "}"          (* 効果の集合。{} は空の集合 *)
           | error_item "|" error_item { "|" error_item }          (* エラーの集合 *)

error_set  = "{" "}" | error_item { "|" error_item }
error_item = type_ref | upper_name                            (* エラーのタグか、集合の型引数。混ぜてよい *)
effect_set = "{" [ effect_item { "," effect_item } ] "}" | type_ref | upper_name
effect_item = type_ref [ "[" type { "," type } "]" ] | upper_name   (* エフェクト（型引数つきでよい）か、集合の型引数。混ぜてよい *)
```

### 17.5 式

```ebnf
block      = "{" { stmt NL } "}"
stmt       = binding | expr
binding    = pattern [ ":" type ] "=" expr

expr       = "fail" expr
           | "assert" expr
           | pipe_expr { ( "escape" | "match" ) "{" { arm NL } "}" }

pipe_expr  = or_expr  { "|>" or_expr }
or_expr    = and_expr { "||" and_expr }
and_expr   = cmp_expr { "&&" cmp_expr }
cmp_expr   = add_expr [ ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) add_expr ]
add_expr   = mul_expr { ( "+" | "-" ) mul_expr }
mul_expr   = unary    { ( "*" | "/" | "%" ) unary }
unary      = ( "!" | "-" ) unary
           | "use" type_ref [ "[" type { "," type } "]" ]
           | postfix
postfix    = primary { "(" [ args ] ")" | "." lower_name }

primary    = literal | lower_name | upper_name | type_ref | "self"
           | "(" ")"
           | "(" expr ")"
           | "(" expr "," expr { "," expr } ")"
           | "[" [ expr { "," expr } [ "," ".." expr ] ] "]"
           | block | if_expr | with_expr | lambda

args       = arg { "," arg } [ "," ".." expr ]
           | ".." expr
arg        = expr | lower_name ":" [ expr ]

if_expr    = "if" expr block [ "else" ( block | if_expr ) ]
arm        = pattern [ "if" expr ] "->" expr
with_expr  = "with" type_ref { "," type_ref } block
lambda     = "fn" "(" [ params ] ")" block
```

- ブロックの最後の文が式のとき、その値がブロックの値になる。最後が束縛のとき、ブロックの値は `()` である。
- 文が束縛か式かは、パターンとして読める並びの直後に `=` または `:` があるかで区別する。
- `use X` の操作をその場で呼ぶときは、`(use X).op(...)` と括弧で囲む。
- 引数の並びでは、名前付き引数の後に位置引数を書けない。
- 引数の並びの末尾の `..式` は、構成子の部分更新である（5.3）。関数の呼び出しに書くとエラーになる。
- リストのリテラルの `..式` は末尾に1回だけ書ける。`[x, y, ..rest]` は `rest` の前に `x`、`y` を付けたリストである。`..` の後は名前に限らず任意の式でよい（`[x, ..List.tail(xs)]`）。要素なしの `[..rest]` と、途中や複数の `..`（`[..a, ..b]`）は書けない。

### 17.6 パターン

```ebnf
pattern  = "_"
         | lower_name
         | literal
         | "-" ( int_lit | float_lit )      (* 負の数。パターンだけ（6.5） *)
         | upper_name
         | type_ref [ "(" pat_args ")" ]
         | "(" ")"
         | "(" pattern "," pattern { "," pattern } ")"
         | "[" "]"
         | "[" pattern { "," pattern } [ "," ".." [ lower_name ] ] "]"

pat_args = ".."
         | pat_arg { "," pat_arg } [ "," ".." ]
pat_arg  = pattern | lower_name ":" [ pattern ]
```

## 付録 A. 診断のコード

コンパイラとツールの診断には、コードを振る。

- 形は、エラーが `E` + 4桁、警告が `W` + 4桁である。一度振った番号は、診断を廃止しても使い回さない。
- 番号は、段ごとの帯に分ける。警告も同じ帯を使う（`W03xx` は型の警告）。
- 文面は英語で書く。文面は仕様の一部ではなく、改善のために変えてよい。コードは変えない。
- 表示は次の形にする。コードのない診断は `error: ...` と出す。

```
error[E0211]: cannot find value `usr` in this scope
   ╭─[ src/main.emel:2:7 ]
   │
 2 │   x = usr
   │       ─┬─
   │        ╰───
───╯

error[E0204]: duplicate module `Http.Client`
   ─[ src/http/Client.emel ]
   = note: `src/http/client.emel` already defines this module

2 errors
```

- 診断は標準エラーに出し、診断の間は空行で区切る。位置は `╭─[ パス:行:桁 ]` の枠で示し、位置がファイル全体のときは `─[ パス ]` の1行にする。
- 注記は `= note: ...`、助言は `= help: ...` と出す。
- 最後の行は `N errors`、警告もあれば `N errors, M warnings` とする（1件なら単数形）。
- 色は、標準エラーが端末で、環境変数 `NO_COLOR` が空か未設定のときだけ付ける。

## 付録 B. コマンド

この付録は `emela` コマンドの外から見える振る舞いを定める。`emela test` は 13.4 にある。

### emela check、build、run

- パスを1つ取り、省けば `.` とする。ディレクトリを渡すと、祖先の `Pome.toml` のプロジェクト全体を対象にする（4.1）。渡せるのはプロジェクトのディレクトリかソースのルートの中のディレクトリで、ソースのルートの外のディレクトリ（`scripts/`）はエラーになる（E0208。fmt と同じ）。ソースのルートの中のディレクトリを渡しても、型の検査はモジュールをまたぐので、プロジェクト全体を検査する。`emela test` も同じ。
- 出力先には、エントリを写した `main.mjs` とランタイムを書き出す。`emela run` も既定の出力先（4.1）に書き出してから実行し、前の出力は消さずに上書きする。`--out-dir` で出力先を変えられる。
- プログラムへの引数は `--` の後に書く。診断はプログラムを起動する前に出す。
- node は、環境変数 `EMELA_NODE` があればそれを、なければ PATH の `node` を使う。
- 終了コードは次のとおりとする。
  - 診断にエラーがあれば 1。警告だけなら 0。
  - `run` でプログラムまで進めば、プログラムの終了コード（0、エラーの 1（14.3）、defect の 101（7.5）、中断の 130（14.5））。
  - シグナルで止まれば 128 + シグナル番号。

### emela fmt

- `emela fmt [パス...]` は、渡したファイルとディレクトリの `.emel` を整形して書き換える。パスを省けば `.` とする。
- ディレクトリには `Pome.toml` が要る（E0207）。プロジェクトのディレクトリならソースのルートの下全部、ソースのルートの中ならその下全部を対象にし、ソースのルートの外ならエラーになる（E0208）。
- `.` で始まるものは飛ばす。名前がモジュール名にならないファイルも整形する。
- 構文エラーのファイルは書き換えず、診断を出してほかのファイルを続ける。
- `--check` は書き換えず、整形が要るファイルを標準出力に1行ずつ出す。`-` は標準入力を整形して標準出力に書く。
- 終了コードは、診断にエラーがあるか `--check` で整形が要るファイルがあれば 1、引数の誤りは 2 とする。

### emela lsp

- 引数を取らず、標準入出力で言語サーバーとして動く。

### 2026-10-12（E0417 を呼び出し単位に）

- 8.1、9.5、付録 A: E0417 の判定を、fn の操作の実装の本体の R が Immediate かどうかから、本体の中の呼び出しが中断しうるかどうかに改めた。操作の呼び出しは操作の宣言、関数と関数の値の呼び出しは型の R で決め、`@external suspend fn` の呼び出しはいつも中断しうるとする。Immediate がエフェクト単位なので、suspend fn を持つエフェクト（Clock）の fn の操作の実装から、同じエフェクトの fn の操作（`now`）さえ呼べなかったため。型の R、ハンドラの依存、with で消える集合、`R: Immediate`（E0416）、関数の型は変えない。R に操作の粒度を持たせる案（`use { Clock.now }`）は、集合の要素、with で消すもの、ハンドラの依存がすべて操作単位になり、型と効果の体系（9章）が大きく変わるので採らなかった。関数の本体から中断しないことを推論する案は、関数の本体を変えると呼ぶ側の検査が変わり、8.1 の「中断の印は操作の宣言だけに付き、関数のシグネチャには付かない」を崩すので採らなかった（#173）。
- 8.1、9.5、付録 A: 呼び出し単位の判定だけにすると、その場で resume するハンドラの with の中で suspend fn の操作を呼ぶ本体（前は本体の R が空なので通っていた）が E0417 になるため、本体の R が Immediate であることと、中断しうる呼び出しを含まないことの、どちらかを満たせば通すとした。どちらもそれだけで本体が中断しないことを保証するので、健全さは崩れない。外側のエフェクトの fn の操作と、内側の with の中の suspend fn の操作を同じ本体に混ぜる形は、呼び出しごとに供給する with まで見る必要があり規則が重くなるので、拾わずに残した（#173）。
